# D-09-02 구현 계획

정식 요구: `docs/tasks/D_ml_ads.md` D-09-02, `ml_lifecycle.md` 2절, README P-16.
사용자가 구현·검증·증빙까지 재개하도록 승인한 범위에서 기존 포트와 Python/Mongo 패턴을 재사용한다.

- [x] 평가 관문: benchmark/human 씐 자 지표와 test_human 의도 지표, 첫 규칙 기준선, 소표본 CI, 거부 이유/기존 버전 유지. 경계 테스트를 먼저 실행했다.
- [x] 밴딧: 이벤트 조인, 먼저 종료한 가명별 5판, 신규 응답 20판, P-16 보상/Thompson 비율, Mongo 불변 비율 버전+CAS, 재시도·경합 테스트.
- [x] BERT: D-09-01의 어댑터/분류기 검증과 테스트만 재사용. 11/9 재검증에서 기존 D-07-03 체크포인트 실제 연결과 실물 통합 4개를 포함한 22개 테스트가 통과했다. B 주입 자료를 남겼고 재학습은 하지 않았다.
- [x] 전체 precheck 943개 통과, 격리 Mongo 5개 통과, 증빙/트러블/모듈/인계 문서 작성. RunPod 사용자 증거와 사람 평가는 미입력으로 명시했다. 태스크 전체 완료는 대기다.

변경 범위: ml/gate.py, ml/bandit.py, ml 밴딧 Mongo 어댑터/배치, tests/, intent/bert.py 및 finetune.py, 관련 문서. 엔진/웹 포트와 운영 DB는 바꾸지 않는다.
가명은 배치의 5판 제한 계산에만 일시 사용하고 영속 상태에는 팔 집계와 판 ID만 저장한다. 개인정보 삭제는 C가 판 ID로 버전 기록을 추적해야 한다.

판정: 소표본 개선 여부는 씐 자의 log loss, 의도의 명령 전체 일치율의 95% 구간으로 판단한다. 승률은 개선 목표가 아니라 안정성 제한이다.
진행 기록과 실제 검증 결과는 `docs/evidence/D-09-02.md`에 남긴다.

최종 리뷰 중요 지적 3개는 회귀 실패→수정→단위/실물 Mongo 통과로 처리했다. 소표본 주 지표 구간 선택은 위 판정대로이며 잘못 선택하면 채택 판단이 과도하게 보수적일 수 있다. 대규모 운영용 상태 분리는 파일럿 요구 밖으로 보류했다. B 웹 통합·실물 BERT·RunPod 증거 대기는 구현 완료와 별도로 관리한다.
