## 2. 측정 방법

- 입력: `fixtures/llm/interrogation_requests.json` 3건(회피·자백·역공)을 차례로 돌려 쓴다.
- 구조(서비스 E-08-09와 같게): 모델 인스턴스 1개, FIFO 큐, 작업자 스레드 1개. 한 라운드에 요청 N건을 같은 시각에 큐에 넣고 모두 끝날 때까지 기다린다.
- 요청마다 잰 것: 큐 대기(넣은 시각 → 처리 시작), 프롬프트 처리·생성(`llama_perf_context`의 `t_p_eval_ms`·`t_eval_ms`), 검증. **전체 = 큐 대기 + 처리 + 검증**.
- 백분위: 최근접 순위(nearest-rank). 표본이 9건이면 p95 = 최댓값이다.
- 요청마다 앞 요청의 KV를 재사용하지 않는다(`reset`). 같은 시스템 프롬프트 접두어를 재사용하면 서비스에서는 더 빨라질 수 있다.
- 생성 설정: `max_tokens` 128, temperature 0.7, top_p 0.8, top_k 20, seed 1, n_ctx 1024. 채팅 템플릿은 GGUF의 것을 직접 그려 `enable_thinking=False`(Qwen 사고 모드 끔).
- 메모리: llama.cpp 로드 로그의 버퍼 크기. 가중치는 파일 매핑(`CPU_Mapped`)과 AVX2용 재배열 사본(`CPU_REPACK`)이 따로 나온다. 실제 상주량은 그 사이이고, 보조 지표로 프로세스 최대 작업 집합을 함께 적는다.
- **임시 프롬프트·검증**(`bench-tmp-1`): 검증은 `fact_sentence`를 그대로 포함하는지와 200자 이하인지만 본다. E-07-07(`llm/prompt.py`, `llm/validator.py`)이 실제 함수로 바꾼다. 검증 실패 수는 참고 지표이고, 이 벤치의 탈락 기준은 지연이다.
- 환경: 충전기 연결, 절전 모드 꺼짐, 전원 계획·전원 모드 '균형'(결과 JSON `source`에 기록). ①·②·③ 켬·라는 VMware VM 4대(약 13.8 GB)와 개발 도구(Edge, VS Code, Docker Desktop, ChatGPT, Discord, Notion, Claude Code)가 켜진 상태다. 측정 직후 확인한 값이다.

## 4. 결정 근거

- p95 15 s 이하를 만족하는 조합: Kanana-2-3B, 스레드 8, 동시 4건(켬 14.4 s, 끔 12.4 s). 동시 4건이 서비스가 받을 최대 동시 추궁 수라는 전제에서다.
- 여유가 작다(켬 0.6 s). 그래서 서비스(E-08-09)에서 다음을 권한다: 큐 길이 상한, 우선순위 0 우선 처리(ports.md 4절), 마감 15 s를 넘기면 폴백, 출력 상한 `max_tokens` 64(평균 생성 10 토큰이라 영향 작음). 시스템 프롬프트를 짧게 하거나 고정 접두어 KV 재사용을 하면 프롬프트 처리 시간이 준다(E-07-07).
- 배정 RAM 6 GB: 최대 작업 집합 3,493 MiB에 서비스 프로세스와 OS 여유를 더한 값이다. VM으로 가면 VM에 6 GB를 주고, VM 안에서 같은 측정을 다시 해 확정한다.
- 차선: Kanana 표기 의무를 받아들일 수 없으면 Qwen3.5-4B를 쓴다. 이 모델은 단일 요청 p95가 9.3 s라 동시 2건부터 15 s를 넘을 가능성이 크다. 그때는 동시 생성 수를 1~2로 제한하고 나머지는 폴백한다(측정하지 않은 추정).

## 6. 한계와 남은 일

- **② VM 비교 미실시**: llm-01 실행, 스레드 비교, llm-01 Python 3.14 `llama_cpp` import·버전 기록이 남았다. C-05-02 뒤에 같은 커밋으로 잰다. 순서는 다음과 같다.
  1. `git bundle`로 코드를 옮기고, VM에서 `--mode vm --out <json>`으로 잰다.
  2. 그 JSON을 받아 `--import-json`으로 기록한다.
  - 그 결과로 실행 방식을 확정한다.
- 표본이 작다(단계별 9~20건). p95는 최댓값에 가깝다. 스레드 차이 1 s 안팎은 오차 범위일 수 있다.
- **실제 프롬프트로 다시 재기**: E-07-07의 프롬프트·검증기가 나오면 최종 조합의 동시 4건(켬)을 같은 스크립트로 다시 잰다. 이때 `--max-tokens`도 실제 값으로 둔다. 답 길이가 늘면 p95가 15 s를 넘을 수 있다.
- 프롬프트·검증은 임시다(`bench-tmp-1`). 검증 실패가 절반 안팎인 것은 프롬프트 탓일 수 있고, 모델 품질의 결론으로 쓰지 않는다. 말투 품질(사람 평가)은 이 벤치에서 보지 않는다.
