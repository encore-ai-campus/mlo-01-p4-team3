# D-08-02 implementation plan

**Goal:** 확정 집계 기반 CTR·페이싱을 기존 광고 경매에 연결하고 시나리오 1~5의 로컬 검증을 남긴다. 기존 reports 폴더를 사용해 새 코드/문서 폴더를 늘리지 않는다.
**Spec:** docs/tasks/D_ml_ads.md D-08-02, docs/contracts/ads.md 4~8절.
**Architecture:** 기존 Beta/경매/원장을 재사용한다. 전체 확정 집계는 불변 MySQL 버전으로 저장하고 요청 시 프로세스 캐시를 60초마다 갱신한다. 페이싱은 Primary 예약+확정 순액으로 5분마다 조정한다.
**Scope:** ads/app 갱신 2개, serve, 구성 지점, infra 저장/캐시, ORM·migration, 관리 명령, 계약/서비스/평가 테스트와 D 증빙·라우팅. D-08-01 및 운영 배포·병합은 제외한다.

- [x] 확정 집계 재계산·중복 누적 방지·입력 거절 테스트 후 CTR/pacing 순수 함수를 구현한다.
- [x] 버전 저장·재시작·60초 reload·후속 이벤트 버전 고정, CPC/CPM·탐색·페이싱을 검증하고 연결한다.
- [x] 학습 생성기와 독립된 시간 변화/사용자/피로/지연/비콘 손실 평가와 동일 자원 기준선을 구현한다. 3개 시드로 1~5를 채점한다.
- [x] 실제 테스트 전용 MySQL/HTTP 검증, precheck, 증빙·인계 명령과 미충족 조건을 기록한다. 개발 DB migration/서버 시작은 자동 승인 검토로 차단되어 승인 대기다.

## Decisions and limits

- 사용자 요청대로 계획 승인 대기 없이 구현까지 진행한다. 저장소 규칙의 task/D-08-02를 최신 origin/dev 63468ce에서 생성했다. 작업 폴더는 시작 시 clean이었다.
- C-08-02 광고 gold/silver/대사 산출물이 저장소에 없다. 명시적인 최종 집계 어댑터 입력을 만들고 실제 Delta 연결 성공으로 표현하지 않는다.
- 평가 입력의 truth는 생성기만 읽는다. 갱신 작업은 관측 확정 노출/클릭만 읽는다. 실제 결과를 보정하거나 합격선에 맞추어 정답을 모델에 전달하지 않는다.
- 검증 수치는 실행 결과 그대로 보고한다. 실제 인계/웹 로그 대응·11시 기한은 로컬 기동만으로 통과시키지 않는다.
