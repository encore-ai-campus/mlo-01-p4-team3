# 개인정보 계약 (B 수집, C 저장·삭제, D·E 사용)

기획서 6.5(v1.1의 8.5)는 아직 가정 단계다. 아래 내용은 사용자 테스트 전에 PM이 확정한다.

## 1. 식별자
- 실명, 연락처, 로그인 ID는 게임 데이터에 저장하지 않는다. 참가자 명단(연락처)은 PM이 저장소 밖에서 따로 관리한다.
- **개인 계정(11/4 PM 결정)**: 모든 게임 화면·API는 로그인해야 쓸 수 있다. 사용자가 로그인 ID와 비밀번호를 직접 만든다. 로그인 ID와 비밀번호 해시는 **계정 저장소**(MySQL 계정 전용 스키마·전용 DB 계정, 광고 스키마와 분리)에만 둔다. 이름·연락처·이메일은 받지 않는다. 계정 규칙은 5절.
- 플레이어는 **가명 ID**(`player_pseudonym`)로 식별한다. 가입 때 무작위 UUID를 발급해 계정에 저장하고 바꾸지 않는다. 게임 데이터, 이벤트, 로그, 지표에는 가명 ID만 쓰고 로그인 ID는 쓰지 않는다. 광고에는 아래 규칙대로 세션 가명 ID만 보낸다(로그인 ID도 보내지 않는다). 가명 ID와 실제 인물의 대응표는 만들지 않는다(계정 저장소 안의 로그인 ID ↔ 가명 ID 연결은 로그인과 삭제 요청 처리에만 쓴다).
- 세션 ID(`session_id`)는 테스트 회차를 묶는 용도로만 쓴다.

- 광고는 세션 가명 ID만 받는다. 플레이어 가명 ID와 판 내용은 광고 서버에 보내지 않는다(ads.md 9절). 광고 이벤트도 같은 보존·삭제 규칙을 따른다.

## 2. 원문 텍스트(자유 입력, 설문 의견)
- 저장 전에 마스킹한다. 전화번호, 이메일, 주민번호 형식, 13자리 이상 숫자열을 `<MASK>`로 바꾼다. 마스킹 규칙의 버전도 기록한다.
- **보존 기간**: 프로젝트 종료일(11/12) + 30일(2026-12-12)까지 보관한다. 그날 원문만이 아니라 가명 ID가 붙은 모든 사용자 테스트 데이터(라벨·특징·추출 데이터셋·계정 포함)를 삭제한다(11/4 PM 결정, C-09-02).
- **삭제 요청**: 참가자가 가명 ID로 요청하면 그 ID의 이벤트, 원문, 진척 상태와 **계정 행(로그인 ID·비밀번호 해시)**을 삭제한다. 가명 ID는 비밀이 아니므로 요청은 본인이 로그인한 화면을 운영자에게 보여 주는 방식(사용자 테스트 현장)으로만 받는다. 처리 순서는 계정 비활성화·세션 삭제 → 다른 저장 위치 삭제(가명 ID 기준, 재시도 가능) → 마지막에 계정 행 삭제. 이미 학습된 모델은 다음 재학습부터 제외한다. 처리 담당은 C다.

## 3. 수집 고지 문구(가입 화면, 동의해야 가입)
> 플레이 기록(선택, 입력한 문장, 수첩 값, 설문)을 이름 없이 저장하고, 게임 속 인물의 행동과 입력 해석 모델을 개선하는 데 씁니다. 단, 설문 점수는 개인별이 아니라 여러 판을 모은 값으로만 분석과 게임 속 인물의 전략 조정에 씁니다. 로그인 ID와 비밀번호(복원할 수 없는 형태로 변환)는 로그인에만 쓰고 플레이 기록과 따로 보관합니다. 로그인 ID에도 이름이나 연락처를 쓰지 마세요. 개인정보(이름, 연락처 등)는 입력하지 마세요. 입력하더라도 자동으로 가립니다. 기록은 2026년 12월 12일까지 보관하며, 화면 아래의 ID로 삭제를 요청할 수 있습니다.

## 4. 학습 사용 범위

| 데이터 | 학습 사용 | 제외 조건 |
|---|---|---|
| 행동 로그(명령, 투표, 수첩) | 씐 자 모델 평가, 대역 봇 보정 | 동의하지 않은 세션, `load_test`, 중단된 판(라벨 없음) |
| 자유 입력 문장 | 의도 해석기 학습·평가 | 마스킹 후에도 개인정보가 남은 문장(검수 때 제외), `auto_executed` 단독 라벨 |
| 설문 | 집계 분석·보고(재미 대리 지표)와, 개인 단위가 아닌 전략별 집계값으로 밴딧 보상(씐 자 전략 비율 보정, 기획서 9.4 ③, D-09-02의 P-16 보상식)에만 사용. 개인별 모델·프로필을 만들지 않고, 다른 모델 학습에는 쓰지 않음(11/4 PM 결정) | 동의하지 않은 세션 |
| 운영 지표 | 학습 제외 | - |

- 학습에 쓰는 행에는 가명 ID를 분할 키로만 남긴다. 특징값에는 넣지 않는다.

## 5. 계정 규칙 (11/4 PM 결정, B-06-04)

| 항목 | 규칙 |
|---|---|
| 가입 | 로그인 ID, 비밀번호, 비밀번호 확인, 3절 동의만 받는다. 이름·연락처·이메일 입력란 없음. 가입 때 가명 ID 발급 |
| 가입 방식 | **공개 가입**(11/4 PM 결정, BRD `BR-OQ-022` 닫힘). 환경 변수 `PALDO_SIGNUP_INVITE_CODE`가 있으면 가입 때 그 초대 코드를 요구하는 기능은 남기되 파일럿에서는 설정하지 않는다. 코드 값은 로그에 남기지 않는다 |
| 가입 남용 | 가입 요청 수 제한 없음(11/6 사용자 결정으로 삭제: 강의실 공유기 뒤에서 참가자가 한 접속 주소로 묶여 정상 가입이 막히므로). 내부망 한정 운영, 판 수·설문 이상치 점검, 운영자 잠금 해제로 대신하고, 외부 공개(AWS) 전에 다시 검토한다([design_notes.md](../design_notes.md) 2절). 남는 위험(대량 가입)은 BRD `BR-RISK-015` |
| 로그인 ID | 대소문자를 구분하지 않고 유일(소문자로 정규화해 저장·비교). 잠금 횟수도 정규화한 ID로 센다 |
| 비밀번호 | 8자 이상 128자 이하. 소문자, 숫자, 특수문자(영문자·숫자·공백이 아닌 문자)를 각각 1개 이상 포함. 흔한 비밀번호 거부(Django `CommonPasswordValidator`), 로그인 ID와 비슷한 비밀번호 거부(`UserAttributeSimilarityValidator`). 모든 규칙을 `AUTH_PASSWORD_VALIDATORS`에 등록하고, 가입은 로그인 ID를 채운 사용자 객체로 `validate_password`를 부른다(관리자 초기화 `changepassword`도 같은 설정으로 검사) |
| 저장 | Django 기본 비밀번호 해셔(PBKDF2)로 해시만 저장(`set_password`). 평문 비밀번호는 DB·로그·이벤트 어디에도 남기지 않는다. Django 기본 사용자 모델 + `accounts` 프로필(가명 ID, 동의 시각, 잠금 상태)을 쓰고 사용자 모델은 바꾸지 않는다. Django `default` DB가 계정 저장소이며 인증·세션·admin 테이블도 여기에 둔다 |
| 잠금 | 같은 로그인 ID로 5회 연속 실패하면 15분 동안 로그인 거부(잠금 중에는 맞는 비밀번호도 거부, 잠금 중 시도는 만료를 늘리지 않음, 성공하면 실패 횟수 초기화). 상태는 계정 저장소에 두고 원자적으로 갱신한다(다중 워커·재시작에도 유지). 없는 ID도 같은 방식으로 세어 잠그므로, 없는 ID·틀린 비밀번호·잠김의 응답(상태 코드, 문구, 이동 위치)이 같다. 운영자는 관리 명령으로 잠금을 풀 수 있다 |
| 세션 | Django 세션 인증과 CSRF 검사 유지. 세션 유효 기간은 Django 기본값 `SESSION_COOKIE_AGE` = 1,209,600초(2주)를 설정 파일에 명시한다. 로그인 성공 시 세션 ID를 새로 발급한다(Django `login()`·`logout()`만 사용). 비밀번호 초기화·계정 삭제 뒤 기존 세션은 무효. 세션 쿠키 `HttpOnly`·`SameSite=Lax`(Django 기본). HTTPS로 서비스하는 환경에서는 `SESSION_COOKIE_SECURE`·`CSRF_COOKIE_SECURE`를 켠다(`PALDO_PUBLIC_ORIGIN`이 `https://`일 때, B-07-05). 내부망 사용자 테스트도 HTTPS로 한다(11/4 PM 결정, BRD `BR-OQ-023` 닫힘): app-01 게임 웹 앞 자체 서명 HTTPS 프록시(C-07-04), AWS 데모는 C-10-02 |
| 복구 | 관리자 초기화만(`python manage.py changepassword <로그인 ID>`). 이메일 등 자동 복구 없음. 운영자는 본인을 현장에서 확인한 경우에만 초기화하고, 확인할 수 없으면 초기화하지 않는다(새 계정 가입 안내) |
| 접근 | 비로그인 요청은 JSON이면 401, 화면 요청이면 로그인 화면으로 이동. 판과 그 하위 객체(`attempt_id`, `job_id`, 수첩, 설문, 복기)는 판을 시작한 가명 ID의 계정만 접근(다른 계정은 404, 멱등 재요청 응답·버전 충돌 판정보다 먼저 검사). 운영자 화면은 운영자 계정(`is_staff`)만 |
| 기록 | 로그인 성공·실패·잠금은 로그와 지표로 남기되 로그인 ID 대신 결과와 가명 ID(없는 ID면 가명도 남기지 않음)만 쓴다. 운영 설정은 `DEBUG=False`, 오류 보고에 인증 폼 값(로그인 ID, 비밀번호, 초대 코드)을 넣지 않는다(`sensitive_post_parameters`). admin의 계정 표시 문자열은 가명 ID |
