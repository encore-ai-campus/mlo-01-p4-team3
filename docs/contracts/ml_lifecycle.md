# 모델 수명주기 계약 (D 로직, C 실행 기반, B 적용)

대상은 씐 자 확률 모델과 의도 해석기다. 레지스트리는 MLflow, 데이터는 Delta에 둔다(버전 번호 기록).

## 1. 학습 최소 조건

| 모델&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; | 최소 조건(시작값, 11/7 재검토) |
|---|---|
| 씐 자 확률 | 종료된 판 300개 이상(봇 포함). 라벨이 붙은 마을 주민 관찰자 행만 쓴다. 프리셋마다 50판 이상 |
| 의도 해석기 | 라벨마다 사람 확인 문장(player_edited 또는 human_annotation) 30개 이상. 부족한 라벨은 시드와 생성 문장으로 채우되 비율을 기록한다 |

## 2. 평가 통과 기준
- **씐 자 확률**: 고정 시드 벤치마크 판과 사람 판 평가 세트에서 다음을 모두 만족해야 한다.
  - log loss가 현재 운영 모델보다 나쁘지 않다(허용 오차 0.01).
  - 보정 오차(ECE)가 0.05 이하다.
  - 엔진에 연결한 시뮬레이션에서 마을 승률이 현재 모델 대비 ±5%p 안에 든다. 난이도가 급변하지 않아야 한다.
- **의도 해석기**: `test_human` 세트에서 다음을 모두 만족해야 한다.
  - **명령 전체 일치율**(행동, 수신자, 대상, 근거, 밤, 시간대가 모두 맞음)이 현재 모델 이상이다. 슬롯별 오류율 중 어느 하나도 2%p 넘게 나빠지지 않는다.
  - 매크로 F1이 현재 모델 이상이다.
  - `unsupported`를 다른 라벨로 오해하는 비율이 현재 모델 이하다.
  - 대조쌍 정확도가 현재 모델 이상이다.
- 첫 모델(운영 모델이 없을 때)의 비교 기준은 다음과 같다. 의도 해석기는 규칙 기준선, 씐 자 확률은 규칙 v0다. 평가 세트가 200문장(또는 50판) 미만이면 부트스트랩 95% 구간을 함께 보고한다. 구간이 겹치면 "개선 아님"으로 본다.
- **평가에 실패해 기존 모델을 유지하는 것도 성공 경로다.** 거부 사유를 레지스트리 태그로 남긴다.

## 3. 등록과 승격 순서
1. 학습한다. 실행 기록에 데이터 버전(Delta), 특징 버전, 코드 커밋을 남긴다.
2. 평가 관문을 실행한다.
3. 통과하면 레지스트리에 `candidate`로 등록한다. 실패하면 등록하지 않고 거부 기록을 남긴다.
4. 카나리아로 적용한다(`canary`).
5. 관찰 기간이 지나면 `production`으로 승격한다. 이전 운영 버전은 `previous`로 보관한다.

초기에는 3~5단계를 사람이 실행한다(기획서 9.4).

## 4. 카나리아와 버전 고정
- `ModelSelector.select`는 판 시작 시에만 호출한다. 신규 판 중 일정 비율(시작값 20%)을 카나리아 버전에 배정하고, `GameMeta.canary=true`로 표시한다.
- 고른 버전은 `GameMeta.model_versions`에 고정한다. **판이 끝날 때까지 바꾸지 않는다.** 롤백하더라도 진행 중인 판은 원래 버전을 유지한다.
- 사용자 테스트 세션에서는 카나리아를 끈다. 비교 실험은 시뮬레이션으로 한다.

## 5. 성능 저하 감지와 롤백

| 신호 | 조건(시작값) | 조치 |
|---|---|---|
| 모델 폴백률 | 카나리아 판 결정의 5% 초과 | 즉시 롤백 |
| 추론 지연 p95 | 100ms 초과 | 즉시 롤백 |
| 마을 승률 | 카나리아와 운영의 차이 10%p 초과(30판 이상) | 롤백 검토 |
| 의도 해석 수정·취소율 | 운영 대비 1.5배 | 롤백 검토 |

- **감지는 C가 맡는다**(Prometheus 경보, Grafana). **롤백 결정과 실행은 D가 맡는다.** 레지스트리에서 `previous`를 다시 `production`으로 돌리고, Selector는 다음 판부터 적용한다. **사용자 테스트 중의 판단은 E(PM)가 승인한다.**
- 롤백 사유는 레지스트리 태그와 `ops/` 운영 기록에 남긴다.
