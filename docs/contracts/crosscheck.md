# 계약 크로스체크

## 요청
다섯 흐름(A 엔진, B 웹·API, C 인프라/파이프라인, D ML, E 콘텐츠·LLM)이 11/5부터 서로 기다리지 않고 병렬 개발할 수 있도록 계약 문서, 계약 코드, 가짜 구현, 픽스처를 만든다.

## 배경
- 기획서: `../paldo_design_v1.md` 4~9장. 팀 일정: `../team_plan.md`.
- 조율자가 13개 항목을 추가로 요청했다(이벤트 처리 통일, 명령 책임 경계, 상태 전이 표, 자유 입력 수명주기, 모델 출력, LLM 작업, 학습-진실 경계, 모델 수명주기, 판 밖 상태, 개인정보, 시나리오, 11인 축약, 배정 검증기).
- 프론트엔드는 Django 템플릿 + htmx + Alpine.js로 정했다.

## 초안
- 문서: `docs/contracts/` 10개
- 코드: `engine/domain/{model,content,events,serde}.py`, `engine/ports.py`, `engine/testing/fakes.py`, `contracts/datasets.py`, `server/app/dto.py`, `server/api/viewmodels.py`
- 픽스처: `tools/build_fixtures.py`가 생성한다.

## 전제
- 엔진은 표준 라이브러리만 쓴다.
- 진실은 판 문서 안의 별도 필드에 둔다.
- 계약 테스트는 unittest로 작성한다.

## Codex 검토
1차 검토(gpt-6.1-sol, 읽기 전용, 2026-11-04)는 15건을 지적했다(P0 3건, P1 12건). 요지는 다음과 같다.
1. 상태를 바꾸지 않는 이벤트(해석, 수첩, 설문, 렌더)를 저장할 경로가 없고, seq 배정 주체가 정해지지 않았다.
2. 가짜 엔진이 새 판 ID를 반영하지 않고, render_requests도 만들지 않는다.
3. 알리바이 명제를 만들려면 피해 장소를 알아야 하는데, 공개 규칙이 없다.
4. 목격은 확률적인데, `witness_at_crime`은 동선만으로 거부한다. 공범 예외도 없다.
5. 매 밤의 행적, 목격, 실종 순서가 모호하다.
6. 고백자가 후보에 남아 확률을 받는다.
7. `resolve_vote`가 표의 완전성(누락 표, 추가 표)을 검사하지 않는다.
8. 비밀이 적용되는 밤이 정해지지 않았다.
9. 공개 기색 기록이 없다.
10. 판에 고정된 의도 해석기 버전을 조회하는 포트가 없다.
11. 가짜 해석기가 문서의 인물 우선순위와 다르고, 인용 질문형을 처리하지 못한다.
12. 단서 진척을 읽고-고치고-쓰기로 저장해 동시 판에서 유실된다.
13. 결말 선택 API가 없고, 가설 묶음과 퇴마 기본값이 빠져 있다.
14. 의도 모델 승격 기준에 명령 전체 일치율이 없다.
15. 일정 위험: 11/6 인수 조건이 모호하고, 기획서 6.3과 7.3의 LLM 배치 대상이 다르다.

## 최종 결정
- **반영(코드와 문서)**:

  | 지적 | 반영 내용 |
  |---|---|
  | 1 | `append_events`(dedup_key)를 추가하고, 저장소가 seq를 매기도록 했다 |
  | 2 | 가짜 엔진이 판 ID를 치환하고 render_requests를 재생한다 |
  | 4 | 공범을 예외로 하고, 근거를 "기획서 대비 결정"으로 고쳐 적었다 |
  | 5 | 밤 처리 6단계를 정하고, 행적 제약을 매 밤 적용하도록 했다 |
  | 6 | 고백자를 후보에서 제외했다 |
  | 7 | `resolve_vote(voters=)`로 표의 완전성을 검사한다 |
  | 8 | 비밀 사건은 0일째 밤에만 일어나는 것으로 정했다 |
  | 9 | `TellRecord`를 추가했다 |
  | 10 | `ModelSelector.intent_parser(version)`을 추가했다 |
  | 11 | 명시한 인물이 우선하도록 하고, 인용 질문형을 처리하게 했다 |
  | 12 | 원자·멱등 `ProgressRepository` 연산과 아웃박스 재처리로 바꿨다 |
  | 13 | `ending_choice`, `hypothesis_id`를 추가하고 퇴마를 기본값으로 했다 |
  | 14 | 명령 전체 일치율, 슬롯 오류, 첫 모델의 기준과 표본 처리를 넣었다 |

  회귀 테스트는 `tests/contract/test_fakes.py::CodexReviewRegressions`에 있다.
- **일부 반영**:
  - 3: 관찰자가 피해 장소를 자기 증거로 알 때만 명제를 만들도록 했다. 피해 장소의 공개 규칙 자체는 기획서의 공백이므로 메인에 보고한다.
  - 15: parallel_dev.md에 인수 조건을 넣었다. LLM 배치 충돌은 다시 확인해 보니 현재 기획서 6.3과 7.3이 모두 llm-01로 일치한다. 검토 이후 메인이 갱신한 것으로 보여 조치하지 않았다.
- **반영하지 않음**: 없음.

## 광고 계약 Codex 검토 (gpt-6.1-sol, 읽기 전용, 2026-11-04)
기준은 기획서 14.3~14.7(크로스체크 6을 반영한 판)이다. 12건을 지적받았다. 처리 결과는 다음과 같다.

| # | 지적 | 처리 |
|---|---|---|
| 1 | 예약의 잔액 검사와 반영이 원자적이지 않다 | 반영. 메모리 구현에 잠금을 걸고, MySQL 계약에 행 잠금 또는 조건부 갱신을 명시했다 |
| 2 | 판정 직후 해제와 경합해 유효 클릭이 영구 미과금될 수 있다 | 반영. 해제 시각을 기한 + 유예로 늦추고, 판정·확정·아웃박스를 한 트랜잭션으로 정했다 |
| 3 | 유예가 클라이언트 발생 시각에 의존한다 | 반영. 서버 최초 수신 시각 기준으로 바꾸고, 만료도 최초 수신 시각으로 검사한다 |
| 4 | 공급자가 None을 반환하면 예외가 난다 | 반영. 응답 검증을 추가하고 빈 광고를 돌려준다 |
| 5 | serve 기록이 없으면 해제가 KeyError로 멈춘다 | 반영. 원장에 `release_after_ms`를 둔다 |
| 6 | CPM을 건마다 내려 비용이 사라진다 | 반영. 나머지를 이월한다("기획서 대비 결정") |
| 7 | 같은 캠페인 후보가 둘이면 점수를 덮어쓴다 | 반영. 캠페인당 후보 1개를 강제한다 |
| 8 | 합성 소재 ID가 실제와 같다 | 반영. 소재 ID에도 `syn:` 접두어를 붙인다 |
| 9 | 반복 클릭 공격이 첫 유효 클릭을 만든다 | 반영. 이미 클릭한 serve에만 적용한다 |
| 10 | 탐색 노출 하한이 구현되지 않았다 | 반영하지 않음. 계약 문서에는 있으며 D의 구현 범위다. ads.md에 미구현이라고 적었다 |
| 11 | Delta에만 있는 중복을 놓치고, 빈 목록에서 예외가 난다 | 반영. 픽스처에 경계 사례를 추가했다 |
| 12 | 예약 금액과 캠페인 소속의 불변조건 검사가 없다 | 반영 |

회귀 테스트는 `tests/contract/test_ads.py::AdsReviewRegressions`에 있다.

## 코드 변경 Codex 검토 (gpt-6.1-terra, `codex review --uncommitted`)
1차 검토는 3건을 지적했고, 모두 반영했다.
- P1: 시간 초과로 버린 호출이 끝나기 전에 슬롯을 반환한다. 호출이 실제로 끝날 때 반환하도록 고쳤다.
- P2: 반열림 상태에서 시험 호출을 하나만 허용하지 않는다. 시험 호출을 1개로 제한하고, 실패하면 곧바로 다시 열도록 고쳤다.
- P2: `ListEventSink`가 같은 배치 안의 중복을 걸러내지 않는다. 고쳤다.

회귀 테스트는 `GatewayReviewRegressions`와 `SinkBatchDedup`에 있다.
- 재검토 1(2건, 모두 반영):
  - P1: 회로가 열린 뒤에 도착한 이전 호출의 성공이 회로를 닫는다. 세대 번호를 붙여 늦은 결과를 무시하도록 고쳤다.
  - P2: CPM 환입 때 나머지 이월이 보정되지 않는다. 정확한 기여만큼 이월값과 환입액을 되돌리도록 고쳤다.
- 재검토 2(1건, 반영): 진술 카드가 목격·비목격 주장을 자기 행적처럼 표시한다. 목격 대상을 표시하도록 고쳤다. 재검토 횟수 상한(2회)에 도달해 추가 검토는 하지 않았다.
