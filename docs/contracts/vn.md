# VN 연출 규칙과 UI 적용 범위

회의·밤 화면의 표시 방식과 B-10-07 구현·검증 기준을 정한다. 상태는 **확정(11/9, B-09-06)**이다. B가 쓴 초안을 담당 이동(11/9 PM 결정, B → E) 뒤 E가 7절 판정으로 확정했고, 검토자는 B다. B의 11/7 화면 설계 시안(공유 폴더 `창귀_화면설계_디자인시안.html`)이 화면 디자인의 기준이다(11/9 사용자 결정). 시안의 배치·색·창 틀·이미지·글꼴을 그대로 옮길 수 있고, 구현이 시안과 다르면 시안을 따른다. 다르게 할 때만 그 사유를 증빙에 적는다. 예외: 900px 미만 배치는 시안의 세로 무대 대신 5절 확정안(16:9 무대 바로 아래 대사·선택지)을 따르고, 색·버튼·여백만 시안을 따른다(11/9 사용자 결정). 시안을 따를 때도 지키는 조건은 세 가지다: ① 화면 정보는 이 문서 3·7절과 [화면 정보](domain.md)를 따른다(정답·밤 실행자·숨은 상태를 드러내지 않음). ② 로그인·동의·명령 재전송·설문 같은 기존 기능을 유지한다. ③ 시안 원화는 생성 기록 예외([기획서](../paldo_design_v1.md) 이미지 에셋 원칙, 프롬프트 "확인 불가")로 `content/images/SOURCES.md`에 적고, 시안 글꼴은 라이선스 전문을 함께 넣는다.

## 1. 기준과 적용 범위

- 원본: [B-09-06·B-10-07](../tasks/B_web.md), [API](api.md) 3~6절, [화면 정보](domain.md), [에셋 규격](../assets/spec.md) 7절, 배치 수치는 `tools/assets/vn.py`다.
- **API·DTO·이벤트·게임 규칙은 바꾸지 않는다.** VN 조작은 읽기 연출만 제어하며 명령을 자동 제출하거나 행동·시간을 소비하지 않는다. 변경이 필요하면 별도 계약 변경 절차를 거친다.
- 아래에서 `기존 기준`은 이미 정해진 요구, `B 제안`은 B가 초안에서 정한 표시 선택이다. B 제안은 7절 판정으로 모두 확정 기준이 됐다.

| 영역 | 적용 내용 | 담당 태스크·경계 |
|---|---|---|
| 회의·밤 | 배경·대화창·읽기 상태·공개 사건 표정·허용 마스코트 | B-10-07, 이 문서 |
| 지도·주민 초상 | manifest 참조, 이름·출처, 용량·첫 화면 측정 | B-10-02 |
| 복기 | 종료 후 이유·근거·템플릿 해설·광고 | B-10-01. 11/9 사용자 결정으로 게임 화면 안 화면 전환(별도 페이지 아님). VN 대사창 연출은 쓰지 않음 |
| 로그인·홈(판 시작 전) | 시안의 로그인 화면(제목 `창귀`, 호랑이 로고, 밤 마을 그림, 로그인 양식)을 그대로 적용. 기존 로그인·가입·동의 기능 유지 | [B-10-08](../tasks/B_web.md#b-10-08-로그인홈-화면-시안-반영) |
| 로비·진술표·수첩·투표·결과·진척 | 현재 기능과 정보 표시 유지. 시안에 해당 화면이 있으면 시안을 따른다 | 해당 태스크 |
| 공통 색·글꼴·버튼·메뉴 | 시안의 먹·한지·놋쇠 배색과 창 틀, 시안 글꼴(본문 제목 Gowun Batang, 본문 Pretendard, 둘 다 SIL OFL 1.1) | `web/static/css/theme.css` 토큰(B-10-07, 글꼴은 B-10-08). 다른 화면은 같은 토큰을 쓴다 |
| 소리·장면 전환 효과 | 이번 VN 범위에서 제외 | B-10-07 명시 범위 |

## 2. 장면·인물·에셋

기존 기준: 회의는 공통 회의 무대 `meeting` 한 장, 밤은 공통 `night` 한 장을 쓴다. 회의 배경은 고정 회의 장면이며 주민의 실제 이동 장소를 뜻하지 않는다. 구체적인 회의 장소의 명칭·미술은 E 검토 사항이다. 숨은 행적·역할·거짓 여부·의심도·개인 지식으로 배경이나 인물·표정을 바꾸지 않는다. 화면 입력은 API가 허용한 플레이어 공개 정보다.

| 항목 | 기존 배치 기준 |
|---|---|
| 무대 | 1280×720, 좁은 화면에서는 비율 유지 축소 |
| 평소 인물 | 회의의 현재 화자 1명, sprite 0~640행을 0.8배로 410×512, 위 y=28·아래 y=540 |
| 대사창 | 무대 하단 180px, 이름표·대사. 선택지 패널은 무대 안(대사창 옆 또는 위, 11/9 사용자 원칙: 조작은 플레이 화면 안에서, B-10-07 7번). 가로/세로 1.95 이상 화면은 무대 오른쪽 바깥(5절 예외) |
| 전신 컷 | 전체 sprite 0.5배 256×640, 위 y=40, 대사창 숨김. 클릭 또는 명시적 다음 버튼으로 복귀 |
| 전신 컷 조건 | 첫 등장 자기소개·추방/처형 결과·엔딩·밤 습격 결과의 아침 발표, 그 밖에는 표시하지 않음. 밤 습격 결과는 까치 발표 줄 바로 다음에 피해자 전신 컷을 한 박자 둔다(11/10 사용자 승인, 실종 없는 아침은 없음). 이 한 박자 컷(`data-beat`)은 대사로 다시 그리지 않아 닫으면 다음 줄로 가고(마지막 줄이면 앞 줄), 밤 화면에서는 읽기 목록에서 뺀다 |
| 밤 | sprite·초상·마스코트 없음. 무당 독백은 대사창만 표시 |
| 엔딩 컷 | 평소와 같은 그림, 정체는 공개된 글로만 설명. 결과 화면의 별도 VN 개편은 포함하지 않음 |
| 마스코트 | 256×256, x=64·y=260. 족제비는 튜토리얼·도움말만, 예외로 판 도중 원한 단서 알림(11/10 사용자 승인). 까치는 아침 실종 발표 줄이 나올 때만(밤 화면이 아니면 단계와 상관없이), 그 밖의 아침 줄에는 세우지 않는다(11/10 사용자 승인) |

에셋은 manifest ID로만 참조한다. 임시 에셋도 같은 ID·규격을 쓰고, 최종 이미지 교체로 코드의 파일명을 바꾸지 않는다. 투명 sprite 실패 시 초상 액자 대체 여부는 A-08-04·에셋 검수 결과를 따른다. 호랑이는 회의·밤 등 게임 장면에 등장하지 않고, 판 시작 전 로그인·홈 화면의 로고로만 쓴다(11/9 사용자 결정, manifest `branding:tiger_emblem`, [에셋 규격](../assets/spec.md) 2절).

표정은 [에셋 규격 7절](../assets/spec.md)의 사건·대상·우선순위를 그대로 따른다. 현재 읽는 사건에만 묶고 뒤 사건의 표정을 앞당기지 않는다. 한 대사 뒤에는 기본으로 돌아가며 겹치면 슬픔 > 당황 > 기쁨 > 기본이다. 같은 공개 사건이면 역할과 무관하게 같은 표정이고 파일이 없으면 기본 그림을 쓴다.

## 3. 대사 순서와 정보 보존

기존 기준: 서버가 제공한 공개 발언 순서와 `speech_id`를 유지한다. 발언 하나를 하나 이상의 표시 줄로 나눌 수 있으나 발언을 합치거나 요약·누락하지 않는다. 새 사건·대사 ID를 도메인에 추가하지 않는다. 화자 이름을 표시하고 플레이어 독백과 NPC 발언을 구분한다.

| 공개 정보 | 항상 확인할 위치 |
|---|---|
| 대사·화자 | 대화창, 모두 보기의 발언별 기록 |
| 주장 ID·진술 원문 | 기존 진술표, 대화창 아래의 관련 주장 참조. LLM 문장으로 진술 원문을 덮어쓰지 않음. 주장 ID는 동작용 속성(`data-record-id`·근거 값)에만 두고 화면 글자로는 보이지 않는다(11/10 사용자 승인) |
| 정정·철회·기색 | 해당 공개 발언의 표시와 기존 진술표에 텍스트로 유지. 표정·색만으로 대체하지 않음. 진술표의 정정 진술 카드에는 "정정한 진술" 배지를 붙이고 마우스 올림 설명에 고치기 전 진술 문장을 둔다(대상 진술이 화면 기록에 없으면 배지만, 11/10 사용자 승인) |
| 근거 선택 | 기존 발언 카드·진술표의 선택 컨트롤, 무대 안 선택지 패널(진술표는 무대 위 창). VN 넘김으로 선택·제출하지 않음 |
| 11인 축약 | 확장 E-08-08이 실제 제공한 축약만 표시. 숨겨진 원문을 다시 구성하지 않음 |

행동 결과·아침 진술 줄(11/10 사용자 지적 "행동 결과가 대사 로그에만 있다"): 공개 기록 패널에만 있던 결과도 대사 줄로 한 번 이상 나온다. 줄은 viewmodel `server/api/vn_script.py`가 공개 기록만으로 만들고, 문장 틀은 그 파일 맨 위 상수 한 곳에 둔다(11/10 사용자 승인). 진술표 카드 문장도 같은 문장 틀을 쓰고(`claim_card_text`, 11/10 사용자 승인), 카드 위 요약 줄(`N일째 밤 · 시간대 · 장소`)은 그대로다.

| 줄 | 나오는 단계 | 화자·그림 | 문장 |
|---|---|---|---|
| 아침 진술(발언이 만들지 않은 주장) | 진술한 날 아침, 실종 발표 다음 | 진술한 인물, sprite | 행적 `{N}일째 밤 {시간대}에는 {장소}에 있었소/없었소.` · 목격 `…에서 {이름}을(를) 보았소.` · 못 봄 `…에서 {이름}은(는) 보지 못했소.` · 아무도 `…에서는 아무도 보지 못했소.` |
| 내 점괘(밤 N) | N+1일째 아침, 실종 발표 다음 | 무당 혼잣말, 그림 없음 | `내 점괘` 패널 문구 |
| 본투표 결과 발표 | 결선이 있으면 결선, 없으면 그날 밤 | 투표 결과, 그림 없음 | 득표 요약 `투표 결과 — {이름} {n}표, …`(많은 순) → `공개된 투표` 패널 문구 한 줄 → 동점이면 `{이름들}의 표가 같아 결선 투표로 넘어갑니다.`(득표 요약·결선 안내 11/10 사용자 승인) |
| 결선 결과 발표 | 그날 밤 | 투표 결과, 그림 없음 | `결선 결과 — …` → 패널 문구 한 줄 |
| 감금·금줄 반응 | 그날 밤 | 감금 결과. 감금된 인물 전신 컷(추방 결과 허용 조건, 밤 화면의 유일한 인물) | `{N}일째 · {이름} 감금`(무감금은 `{N}일째 · 무감금`, 그림 없음) → 금줄 반응 한 줄 |
| 첫 판 안내 | 계정의 첫 판, 각 단계 첫머리(시작 안내는 실종 발표 앞, 아침 안내는 진술 앞) | 족제비, 무대 왼쪽 마스코트 자리. 밤 안내와, 밤 화면에서 늦게 읽는 아침 안내는 그림 없이 글만 | `server/api/tutorial_script.py`(11/10 사용자 승인 문장) |
| 아침 실종 발표 | 그날 아침 첫머리(시작 안내 다음, 진술 앞) | 까치, 무대 왼쪽 마스코트 자리(밤 화면은 글만). 바로 다음 줄에 피해자 전신 컷(새 문장 없이 발표 문장을 그대로 달고, 컷 동안 대사창은 숨음) | `깍깍! 간밤 {시간대}에 {이름}이(가) 사라졌어요. {이름}의 짚신이 {장소}에서 발견됐대요!`(집이면 `{이름}의 집`), 실종 기록이 없는 아침은 `깍깍! 간밤엔 아무도 사라지지 않았어요.`(11/10 사용자 승인). 기록 창의 실종 기록 문구는 그대로 |
| 의심·모순 지적 즉시 반응 | 플레이어의 의심 제기·모순 지적 발언 바로 뒤 | 지목된 주민, sprite(모순 지적은 근거 두 진술의 같은 화자, 또는 남의 목격과 어긋난 당사자. 고를 수 없으면 없음). 주민끼리의 발언에는 없음 | 성향별 2개 중 발언 ID로 고름(`server/api/vn_script.py` `REACTION_*`, 11/10 사용자 승인). 엔진과 무관한 연출 줄(믿음·투표·진술에 안 들어감) |
| 판 도중 원한 단서 알림 | 캐묻기 고백 발언 바로 뒤 | 단서 문장은 해설(이름표 없음), 이어서 족제비(마스코트 자리). 안내 스위치와 상관없이 늘 나온다(족제비 등장 예외) | 새 단서·이미 가진 단서·한풀이 열림 세 경우(`server/api/tutorial_script.py` `CLUE_*`, 11/10 사용자 승인). 판정은 응용 `server/app/clue_notice.py`(공개 고백·콘텐츠·진척) |

투표 결과 발표 줄(`data-result`)을 다 읽기 전에는 그 단계 행동(결선 투표·밤 점치기)을 잠그고(잠긴 버튼은 흐리게, 커서 금지 모양) "투표 결과를 먼저 확인하세요" 안내를 띄운다. 대사를 끝까지 넘기거나 모두 보기·연출 건너뛰기를 누르면 풀린다. 서버 명령 규칙은 바꾸지 않는다(화면 잠금). 족제비 안내는 도움말의 `이번 판에서 안내 보기` 스위치로 켜고 끈다(11/10 사용자 결정). 첫 판은 서버가 안내 줄(`data-guide`)을 넣어 기본 켬이고, 다른 판은 같은 문장을 숨은 목록(`data-guide-pool`)으로 내려 보내 켰을 때만 클라이언트가 대사 줄로 만든다. 켠 순간 판 시작 안내부터(다른 판은 첫 줄만 "무당님, 또 만났네요! 처음부터 다시 알려 드릴게요!"로 바꾼다, 11/10 사용자 승인), 이후 단계 안내는 그 단계에 처음 들어갈 때 나온다(켠 단계보다 앞 단계 안내는 다음 날 그 단계에서). 다시 켜면 읽은 안내도 처음부터 다시 나오고, 첫 판도 1일째가 지난 뒤 다시 켜면 숨은 목록(`data-guide-first`)으로 판 시작 안내부터 만든다. 밤 안내는 글만, 판 종료 한풀이 말풍선(`data-guide-end`)도 스위치를 따른다. `안내 건너뛰기`는 스위치를 끈 것과 같다. 상태는 판별 sessionStorage(`changgui:guide-skip:<판>`·`changgui:guide-on:<판>`), 저장이 막히면 탭 메모리에 둔다. 주민 창의 수첩 버튼은 활동 중인 주민에게만 보인다. 실종·감금된 주민의 저장 값은 지우지 않고 수첩 저장 때 그대로 함께 보낸다(11/10 사용자 결정).

조사(을/를·와/과·은/는·이라/라)는 앞 글자 받침으로 골라 괄호 없이 낸다. 거짓 진술도 같은 틀이라 문장 모양으로 진위를 알 수 없다. 점괘 공개는 이미 무당 발언(콘텐츠 문장)으로 대사창에 나오므로 그 문장을 그대로 쓴다(11/10 사용자 결정).

`다음`은 출력 중인 한 문장을 즉시 완성하고, 이미 완성됐으면 다음 표시 줄로 간다. 마지막 줄에서는 끝임을 알리고 기존 행동 패널을 이용한다. `건너뛰기`는 현재 연출을 끝내고 같은 공개 대사 전체를 기록으로 보여준다. `모두 보기`는 순서대로 전체 대사를 표시한다. 둘 다 서버 명령을 보내거나 단계를 넘기지 않으며 근거·정정·철회 표시를 보존한다(7절 확정).

## 4. 읽기 상태·응답 갱신

변경(11/10 사용자 지적): 읽기 키는 `(game_id, day)`이고 그날 줄을 단계 순서(아침→1라운드→캐묻기→2라운드→투표→결선→밤)로 잇는다. 본 줄 ID 목록(`seen`)을 함께 저장하고, 화면을 다시 그리면 처음 안 본 줄에서 시작한다(모두 봤으면 마지막 위치). 행동 뒤 단계가 바뀌어도 앞 단계에서 새로 생긴 반응·결과 줄에서 멈추고, 새로고침·재연결은 본 줄을 다시 보게 하지 않는다. 밤 화면은 앞 단계 줄도 글로만 보인다(sprite 금지 유지). 아래 기존 기준의 "단계가 바뀌면 초기화"는 이 규칙으로 바뀐다.

기존 기준: 읽기 키는 `(game_id, day, phase, speech_id)`이며 `state_version`을 넣지 않는다. htmx 조각 교체·409 최신 화면·버전 변경 후에도 같은 키면 읽던 위치를 유지하고, 판·날짜·단계가 달라지면 초기화한다. 현재 공개 목록에서 사라진 ID는 복원하지 않는다.

확정(7절): 읽기 위치와 즉시 표시 옵션은 탭의 `sessionStorage`에만 보관한다. 새로고침·뒤로가기는 최신 화면의 같은 키를 검증한 뒤 복원하고, 저장소가 차단되면 메모리로 동작하며 새로고침 시 초기화한다. 대사 원문·입력·토큰·역할은 저장하지 않는다. 문장 길이가 바뀌면 문자 위치를 유효 범위로 제한한다. 읽기 중 새 발언이 추가돼도 자동으로 현재 줄을 옮기지 않는다.

추궁 답변은 API 5절대로 폴백을 먼저 표시하고 기존 1초 폴링을 유지한다. `game_id`·`speech_id`·`job_id`가 현재 기록과 일치할 때만 갱신한다. **final이 도착하면 해당 문장을 즉시 완성된 문장으로 교체**한다(7절 확정). 같은 문장의 글자 출력 타이머를 중지하고 완성 문장을 한 번 알린다. `done` 외 종료 상태는 폴백을 유지한다. 다른 대사로 이동한 뒤 도착하면 해당 기록만 고치며 현재 대사로 강제 이동하지 않는다. 단계 전환으로 제거된 작업·늦은 응답은 현재 화면을 덮어쓰지 않는다. `final=true`이면 폴링 속성을 제거한다.

이는 기존 폴링 호환 규칙이며 런타임 LLM을 새로 도입하는 요구가 아니다. `Powered by Kanana`는 대사창의 `data-vn-attribution`·`.vn-mobile-attribution` 자리에 고정 표시하지 않고, 게임 화면 밖 좌측 하단 출처 표시 영역에 한 번만 둔다(11/11 사용자 결정으로 11/10 "답변 대사 자리에 표시"를 바꿈).

## 5. 조작·접근성·가독성

- 기존 기준: 명시적 `다음` 버튼, 글자 출력 없는 즉시 표시 옵션, 문장 단위 `aria-live`, 화면 교체 후 포커스 복원. 폭 360px·확대 200%·최대 길이 대사에서 무대·선택지가 가려지지 않아야 한다.
- 확정(7절): Space·Enter는 VN 읽기 영역이 활성화됐을 때만 다음으로 동작한다. input·textarea·select·contenteditable·버튼·링크·근거 카드 내부, 한글 조합 중에는 넘김 처리를 하지 않는다. 키를 누르고 있는 반복 입력도 무시한다. 버튼의 기본 키보드 동작은 유지한다.
- 넘김(11/10): 한 번에 한 줄만 넘긴다. `다음 대사` 버튼 또는 무대·대사창 한 번 클릭이 다음 줄이다(글자 출력 중이면 첫 클릭은 문장 완성). 무대의 인물 그림 클릭도 넘김이다(11/10 사용자 결정, 인물 행동 메뉴는 주민 창·행동하기). 버튼·입력·창(dialog)·선택지 패널 위 클릭은 넘기지 않는다. 여러 줄을 저절로 흘리지 않는다.
- 버튼 설명(11/10): 게임 화면 버튼은 마우스를 올리면 한 줄 설명이 뜬다. 문구는 `server/api/template_tags.py`의 `UI_TIPS` 한 곳에 두고 `{% tip %}`로 `title`에 넣는다. aria-label이 있는 버튼은 같은 문구다. 화면 안 설명 상자는 `ui-vn.js`가 그리고, 창(dialog) 안 버튼은 브라우저 기본 설명을 쓴다.
- 글자별 낭독을 하지 않는다. 시각 출력과 별도로 완성된 문장·화자를 한 번 전달하며 final 교체는 완성 문장 갱신 한 번으로 알린다. 모두 보기는 각 문장을 탐색 가능한 순서로 제공하고 전체 기록을 반복 방송하지 않는다.
- 포커스는 살아 있는 동일 컨트롤에 복원하고 사라졌으면 갱신 영역 제목으로 옮긴다. 배경 폴링·대사 추가가 입력 포커스를 빼앗지 않는다.
- 무대 축소 후에도 본문·버튼 글자는 읽을 크기로 유지한다. 폭 900px 이상은 에셋 규격대로 무대 하단 180px 대사창과 무대 안 선택지 패널(대사창 오른쪽 옆, sprite 오른쪽 x 860 이후, 무대 아래 끝까지)을 쓴다. 대사창은 패널 왼쪽까지만 덮는다. 사유(11/9 사용자 요청): 패널을 대사창 위에만 두면 1366×768에서 패널 높이가 약 320px라 명령 대부분이 대사창 뒤로 잘려 보였다. 무대 최대 폭은 `(화면 높이 − 190px) × 16/9`로 넓혀 대사 넘김 줄까지 첫 화면에 들어오게 한다. 폭 1200px 이상은 머리글과 진행 단계 줄을 한 줄로 합치고 무대 최대 폭을 `(화면 높이 − 152px) × 16/9`로 하고, 이미지 출처 안내는 무대 아래 작은 글씨 두 줄로 줄여 세로 스크롤 없이 한 화면에 들어오게 한다(내용은 그대로). **조작은 무대 안 원칙의 예외(11/9 사용자 결정):** 화면 가로/세로 비율이 1.95 이상인 화면(16:9보다 옆으로 긴 화면, 예: 1528×730·1528×683·1600×800)에서는 선택지 패널(380px)과 대사 넘김·읽기 옵션을 무대 오른쪽 바깥에 붙이고, 무대 폭은 `min((화면 높이 − 104px) × 16/9, 화면 폭 − 패널 − 여백)`으로 줄여 패널이 무대를 가리지 않게 한다. 대사창은 무대 전체 폭을 쓴다. 사유: 이런 화면은 무대 크기가 화면 높이로 정해져 옆 공간이 비므로, 패널을 밖에 두어도 무대가 거의 줄지 않고 패널이 그림을 가리지 않는다. 16:9 근처 화면(1366×768, 1920×1080, 1280×720)은 옆 공간이 모자라 패널을 무대 안에 둔다. 패널은 같은 게임 화면 영역(`#meeting`) 안에 있고 페이지 이동·새 창은 없다. **폭 900px 미만(7절 확정)**에서는 무대를 비율대로 줄이고 대사 글과 선택지 패널을 무대 바로 아래, 같은 게임 화면 영역(`#meeting`) 안에 붙인다. 사유: 360px 폭의 무대는 높이가 약 200px이라 대사와 명령 양식을 무대 안에 넣으면 글자를 읽을 수 없다. 페이지 이동·새 창은 없고 게임 화면을 벗어나지 않는다(B-10-07 8번 원칙). 선택지 위에 sprite를 겹치지 않고 전신 컷에도 키보드로 복귀할 버튼을 제공한다.
- 공포 분위기는 배경·색·테두리로 표현하고 본문 대비·한글/영문 가독성을 유지한다. 의미를 색·표정·아이콘만으로 전달하지 않는다. 수치·색상 등 새 디자인 선택은 시안과 실제 화면을 E와 검토한다.

## 6. 후속 구현·검증 인계

이 문서 작성으로 UI 구현·브라우저 검증을 완료 처리하지 않는다. 기존 `B-ui-design`·`B-ui-development` 작업은 보존하고 최신 dev에서 필요한 디자인만 태스크별로 옮긴다. 예전 API·광고·폴링 코드를 함께 되돌리지 않는다.

| 후속 확인 | 기대 결과·증빙 |
|---|---|
| 정보 동등성 | 같은 판의 기존 화면·VN 화면 주장 ID·원문·근거·정정·철회 비교, 금지 키 없음 |
| 숨은 정보 | 같은 공개 사건/다른 역할에서 배경·표정 동일, 밤 인물·마스코트 없음 |
| 전신·표정 | 허용 4조건만 전신 컷, 사건별 대상·우선순위·기본 복귀 |
| 읽기·폴링 | 넘김·건너뛰기·모두 보기, htmx·409·새로고침·뒤로가기·저장소 차단, final·늦은 응답 |
| 조작·화면 | 한글 입력/카드 조작 중 넘김 없음, 포커스·문장 낭독, 360px·200%·긴 문장 캡처 |
| 완주·성능 | 6인·8인 녹화 VN 완주, 즉시 표시 켬/끔 읽기 시간, B-10-02 용량·첫 화면 시간 |
| 배포 | 11/10 리허설부터 18시까지 테스트 서버 SHA 유지. VN 병합과 배포를 구분하고 blocker 예외는 E 승인 절차 |

화면 전환 설정은 서버 환경 변수 `PALDO_GAME_UI`(`vn` 기본, `classic`)다. VN 화면에 막는 문제가 생기면 `classic`으로 바꾸고 웹 서버를 재시작해 기존 회의 화면(`meeting_classic.html`)으로 되돌린다. 두 화면은 같은 정보 조각(`meeting_parts/`)과 같은 명령 경로를 쓴다.
