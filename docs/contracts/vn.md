# VN 연출 규칙과 UI 적용 범위

회의·밤 화면의 표시 방식과 B-10-07 구현·검증 기준을 정한다. 상태는 **확정(11/9, B-09-06)**이다. B가 쓴 초안을 담당 이동(11/9 PM 결정, B → E) 뒤 E가 7절 판정으로 확정했고, 검토자는 B다. B의 11/7 화면 설계 시안(공유 폴더)은 색·창 틀·무대 배치의 참고로 쓰고, 시안의 이미지·글꼴 파일은 가져오지 않는다.

## 1. 기준과 적용 범위

- 원본: [B-09-06·B-10-07](../tasks/B_web.md), [API](api.md) 3~6절, [화면 정보](domain.md), [에셋 규격](../assets/spec.md) 7절, 배치 수치는 `tools/assets/vn.py`다.
- **API·DTO·이벤트·게임 규칙은 바꾸지 않는다.** VN 조작은 읽기 연출만 제어하며 명령을 자동 제출하거나 행동·시간을 소비하지 않는다. 변경이 필요하면 별도 계약 변경 절차를 거친다.
- 아래에서 `기존 기준`은 이미 정해진 요구, `B 제안`은 B가 초안에서 정한 표시 선택이다. B 제안은 7절 판정으로 모두 확정 기준이 됐다.

| 영역 | 적용 내용 | 담당 태스크·경계 |
|---|---|---|
| 회의·밤 | 배경·대화창·읽기 상태·공개 사건 표정·허용 마스코트 | B-10-07, 이 문서 |
| 지도·주민 초상 | manifest 참조, 이름·출처, 용량·첫 화면 측정 | B-10-02 |
| 복기 | 종료 후 이유·근거·템플릿 해설·광고 | B-10-01. 11/9 사용자 결정으로 게임 화면 안 화면 전환(별도 페이지 아님). VN 대사창 연출은 쓰지 않음 |
| 로그인·로비·진술표·수첩·투표·결과·진척 | 현재 기능과 정보 표시 유지 | 전체 재디자인은 해당 태스크 또는 별도 UI 범위로 검토 |
| 공통 색·글꼴·버튼·메뉴 | 시안의 먹·한지·놋쇠 배색과 창 틀 | `web/static/css/theme.css` 토큰(B-10-07). 다른 화면은 같은 토큰을 쓴다 |
| 소리·장면 전환 효과 | 이번 VN 범위에서 제외 | B-10-07 명시 범위 |

## 2. 장면·인물·에셋

기존 기준: 회의는 공통 회의 무대 `meeting` 한 장, 밤은 공통 `night` 한 장을 쓴다. 회의 배경은 고정 회의 장면이며 주민의 실제 이동 장소를 뜻하지 않는다. 구체적인 회의 장소의 명칭·미술은 E 검토 사항이다. 숨은 행적·역할·거짓 여부·의심도·개인 지식으로 배경이나 인물·표정을 바꾸지 않는다. 화면 입력은 API가 허용한 플레이어 공개 정보다.

| 항목 | 기존 배치 기준 |
|---|---|
| 무대 | 1280×720, 좁은 화면에서는 비율 유지 축소 |
| 평소 인물 | 회의의 현재 화자 1명, sprite 0~640행을 0.8배로 410×512, 위 y=28·아래 y=540 |
| 대사창 | 무대 하단 180px, 이름표·대사. 선택지 패널은 무대 안(대사창 옆 또는 위, 11/9 사용자 원칙: 조작은 플레이 화면 안에서, B-10-07 7번) |
| 전신 컷 | 전체 sprite 0.5배 256×640, 위 y=40, 대사창 숨김. 클릭 또는 명시적 다음 버튼으로 복귀 |
| 전신 컷 조건 | 첫 등장 자기소개·추방/처형 결과·엔딩·밤 습격 결과의 아침 발표, 그 밖에는 표시하지 않음 |
| 밤 | sprite·초상·마스코트 없음. 무당 독백은 대사창만 표시 |
| 엔딩 컷 | 평소와 같은 그림, 정체는 공개된 글로만 설명. 결과 화면의 별도 VN 개편은 포함하지 않음 |
| 마스코트 | 256×256, x=64·y=260. 족제비는 튜토리얼·도움말만. 까치 조건은 7절 확인 필요 |

에셋은 manifest ID로만 참조한다. 임시 에셋도 같은 ID·규격을 쓰고, 최종 이미지 교체로 코드의 파일명을 바꾸지 않는다. 투명 sprite 실패 시 초상 액자 대체 여부는 A-08-04·에셋 검수 결과를 따른다. 호랑이 브랜딩 제안은 기존 시안에 보존하되 현재 기획서의 비등장 기준을 변경 승인받기 전 정식 게임 화면에 적용하지 않는다.

표정은 [에셋 규격 7절](../assets/spec.md)의 사건·대상·우선순위를 그대로 따른다. 현재 읽는 사건에만 묶고 뒤 사건의 표정을 앞당기지 않는다. 한 대사 뒤에는 기본으로 돌아가며 겹치면 슬픔 > 당황 > 기쁨 > 기본이다. 같은 공개 사건이면 역할과 무관하게 같은 표정이고 파일이 없으면 기본 그림을 쓴다.

## 3. 대사 순서와 정보 보존

기존 기준: 서버가 제공한 공개 발언 순서와 `speech_id`를 유지한다. 발언 하나를 하나 이상의 표시 줄로 나눌 수 있으나 발언을 합치거나 요약·누락하지 않는다. 새 사건·대사 ID를 도메인에 추가하지 않는다. 화자 이름을 표시하고 플레이어 독백과 NPC 발언을 구분한다.

| 공개 정보 | 항상 확인할 위치 |
|---|---|
| 대사·화자 | 대화창, 모두 보기의 발언별 기록 |
| 주장 ID·진술 원문 | 기존 진술표, 대화창 아래의 관련 주장 참조. LLM 문장으로 진술 원문을 덮어쓰지 않음 |
| 정정·철회·기색 | 해당 공개 발언의 표시와 기존 진술표에 텍스트로 유지. 표정·색만으로 대체하지 않음 |
| 근거 선택 | 기존 발언 카드·진술표의 선택 컨트롤, 무대 안 선택지 패널(진술표는 무대 위 창). VN 넘김으로 선택·제출하지 않음 |
| 11인 축약 | 확장 E-08-08이 실제 제공한 축약만 표시. 숨겨진 원문을 다시 구성하지 않음 |

`다음`은 출력 중인 한 문장을 즉시 완성하고, 이미 완성됐으면 다음 표시 줄로 간다. 마지막 줄에서는 끝임을 알리고 기존 행동 패널을 이용한다. `건너뛰기`는 현재 연출을 끝내고 같은 공개 대사 전체를 기록으로 보여준다. `모두 보기`는 순서대로 전체 대사를 표시한다. 둘 다 서버 명령을 보내거나 단계를 넘기지 않으며 근거·정정·철회 표시를 보존한다(7절 확정).

## 4. 읽기 상태·응답 갱신

기존 기준: 읽기 키는 `(game_id, day, phase, speech_id)`이며 `state_version`을 넣지 않는다. htmx 조각 교체·409 최신 화면·버전 변경 후에도 같은 키면 읽던 위치를 유지하고, 판·날짜·단계가 달라지면 초기화한다. 현재 공개 목록에서 사라진 ID는 복원하지 않는다.

확정(7절): 읽기 위치와 즉시 표시 옵션은 탭의 `sessionStorage`에만 보관한다. 새로고침·뒤로가기는 최신 화면의 같은 키를 검증한 뒤 복원하고, 저장소가 차단되면 메모리로 동작하며 새로고침 시 초기화한다. 대사 원문·입력·토큰·역할은 저장하지 않는다. 문장 길이가 바뀌면 문자 위치를 유효 범위로 제한한다. 읽기 중 새 발언이 추가돼도 자동으로 현재 줄을 옮기지 않는다.

추궁 답변은 API 5절대로 폴백을 먼저 표시하고 기존 1초 폴링을 유지한다. `game_id`·`speech_id`·`job_id`가 현재 기록과 일치할 때만 갱신한다. **final이 도착하면 해당 문장을 즉시 완성된 문장으로 교체**한다(7절 확정). 같은 문장의 글자 출력 타이머를 중지하고 완성 문장을 한 번 알린다. `done` 외 종료 상태는 폴백을 유지한다. 다른 대사로 이동한 뒤 도착하면 해당 기록만 고치며 현재 대사로 강제 이동하지 않는다. 단계 전환으로 제거된 작업·늦은 응답은 현재 화면을 덮어쓰지 않는다. `final=true`이면 폴링 속성을 제거한다.

이는 기존 폴링 호환 규칙이며 런타임 LLM을 새로 도입하는 요구가 아니다. 게임 대사에 `Powered by Kanana`를 다시 붙이지 않는다.

## 5. 조작·접근성·가독성

- 기존 기준: 명시적 `다음` 버튼, 글자 출력 없는 즉시 표시 옵션, 문장 단위 `aria-live`, 화면 교체 후 포커스 복원. 폭 360px·확대 200%·최대 길이 대사에서 무대·선택지가 가려지지 않아야 한다.
- 확정(7절): Space·Enter는 VN 읽기 영역이 활성화됐을 때만 다음으로 동작한다. input·textarea·select·contenteditable·버튼·링크·근거 카드 내부, 한글 조합 중에는 넘김 처리를 하지 않는다. 키를 누르고 있는 반복 입력도 무시한다. 버튼의 기본 키보드 동작은 유지한다.
- 글자별 낭독을 하지 않는다. 시각 출력과 별도로 완성된 문장·화자를 한 번 전달하며 final 교체는 완성 문장 갱신 한 번으로 알린다. 모두 보기는 각 문장을 탐색 가능한 순서로 제공하고 전체 기록을 반복 방송하지 않는다.
- 포커스는 살아 있는 동일 컨트롤에 복원하고 사라졌으면 갱신 영역 제목으로 옮긴다. 배경 폴링·대사 추가가 입력 포커스를 빼앗지 않는다.
- 무대 축소 후에도 본문·버튼 글자는 읽을 크기로 유지한다. 폭 900px 이상은 에셋 규격대로 무대 하단 180px 대사창과 무대 안 선택지 패널(대사창 위 오른쪽, sprite 오른쪽 x 860 이후)을 쓴다. **폭 900px 미만(7절 확정)**에서는 무대를 비율대로 줄이고 대사 글과 선택지 패널을 무대 바로 아래, 같은 게임 화면 영역(`#meeting`) 안에 붙인다. 사유: 360px 폭의 무대는 높이가 약 200px이라 대사와 명령 양식을 무대 안에 넣으면 글자를 읽을 수 없다. 페이지 이동·새 창은 없고 게임 화면을 벗어나지 않는다(B-10-07 8번 원칙). 선택지 위에 sprite를 겹치지 않고 전신 컷에도 키보드로 복귀할 버튼을 제공한다.
- 공포 분위기는 배경·색·테두리로 표현하고 본문 대비·한글/영문 가독성을 유지한다. 의미를 색·표정·아이콘만으로 전달하지 않는다. 수치·색상 등 새 디자인 선택은 시안과 실제 화면을 E와 검토한다.

## 6. 후속 구현·검증 인계

이 문서 작성으로 UI 구현·브라우저 검증을 완료 처리하지 않는다. 기존 `B-ui-design`·`B-ui-development` 작업은 보존하고 최신 dev에서 필요한 디자인만 태스크별로 옮긴다. 예전 API·광고·폴링 코드를 함께 되돌리지 않는다.

| 후속 확인 | 기대 결과·증빙 |
|---|---|
| 정보 동등성 | 같은 판의 기존 화면·VN 화면 주장 ID·원문·근거·정정·철회 비교, 금지 키 없음 |
| 숨은 정보 | 같은 공개 사건/다른 역할에서 배경·표정 동일, 밤 인물·마스코트 없음 |
| 전신·표정 | 허용 4조건만 전신 컷, 사건별 대상·우선순위·기본 복귀 |
| 읽기·폴링 | 넘김·건너뛰기·모두 보기, htmx·409·새로고침·뒤로가기·저장소 차단, final·늦은 응답 |
| 조작·화면 | 한글 입력/카드 조작 중 넘김 없음, 포커스·문장 낭독, 360px·200%·긴 문장 캡처 |
| 완주·성능 | 6인·8인 녹화 VN 완주, 즉시 표시 켬/끔 읽기 시간, B-10-02 용량·첫 화면 시간 |
| 배포 | 11/10 리허설부터 18시까지 테스트 서버 SHA 유지. VN 병합과 배포를 구분하고 blocker 예외는 E 승인 절차 |

화면 전환 설정은 서버 환경 변수 `PALDO_GAME_UI`(`vn` 기본, `classic`)다. VN 화면에 막는 문제가 생기면 `classic`으로 바꾸고 웹 서버를 재시작해 기존 회의 화면(`meeting_classic.html`)으로 되돌린다. 두 화면은 같은 정보 조각(`meeting_parts/`)과 같은 명령 경로를 쓴다.
