  2. **실제 API 경유**: 가상 사용자(세션 가명 ID)가 **실제 광고 서버 HTTP API**로 광고를 요청하고, 서버가 경매로 고른 광고만 본다(생성기가 광고를 직접 고르지 않음).
  3. **주사위**: 받은 광고의 숨긴 CTR로 클릭 여부를 무작위 결정. 같은 사용자가 같은 소재를 반복해서 보면 CTR이 떨어지는 **피로 효과**(감소율을 설정값으로, 정답 파일에 기록). 노출 비콘은 가시 기준을 만족한 경우만 보냄.
  4. **무효 클릭 주입**: 기본 5%(검증 시나리오 설정값이며 기획서 수치가 아님. 0%·20%로도 실행해 무효 과금 0건 확인). 전체 클릭의 해당 비율을 계약의 무효 사유(ads.md 6절, `rules.py`)에 맞는 유형으로 섞는다: 같은 serve 중복 클릭(`duplicate`), 만료 토큰(`expired`), 위조 토큰(`bad_signature`), serve 기록 없는 토큰(`no_serve`). 유형별 수를 정답 파일에 기록. 노출 비콘 없이 온 클릭은 무효가 아니다(클릭이 노출 증거, `implied_by_click`으로 노출 인정, 과금은 과금 방식대로: CPC는 클릭, CPM은 노출)라 유효 사례로 센다. 빠른 연속 클릭은 서로 다른 serve의 유효 클릭일 때만 `suspect` 표시 후 과금하는 사례이고, 같은 serve 재사용이면 `duplicate` 무효다(11/5 PM 결정, 계약 기준). `no_serve`는 정상 서명·미만료 토큰에 serve 기록을 남기지 않는 합성 전용 시험 경로로 주입한다(임의 토큰은 `bad_signature`가 된다).
  5. `source=synthetic`, 합성 캠페인만 가리킴(`tests/contract/test_ads.py::SyntheticAds` 통과). 시드 고정 재현. serve·이벤트 ID와 합성 세션 ID에 실행 ID를 넣어 같은 시드의 새 실행이 이전 데이터와 섞이지 않게 한다(재처리는 같은 실행 ID를 다시 쓴다).
