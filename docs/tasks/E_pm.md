## 에셋 작업 기준

**원칙**
  - 생성형 AI로 미리 만든다. 설화 원전 그림·문장을 쓰지 않는다.
  - 이미지 안에 **실존 인물, 상표·로고, 글자(한글·한자·영문·숫자)** 를 넣지 않는다. 글자가 필요한 곳은 화면(HTML)이 쓴다.

- 문서화(+0.25h, 공통 ⑦): 모듈 문서 [`docs/modules/ci.md`](../modules/ci.md)의 필수 절 6개 갱신과 `변경 이력`에 `E-05-02` 행 · [트러블 E](../troubles/E.md)에 `### E-05-02` 항목(문제 → 원인 → 대응 → 결과 수치, 없으면 "없음") · 새로 만들거나 바꾼 공개 함수·클래스 docstring · 새 폴더를 만들면 `paldo/README.md` 폴더 안내·작업별 위치 표 갱신
- 완료 조건:
  1. PR마다 필수 체크 4개(README 3절 ②): `core`(Python 3.12, `python -m unittest discover -s tests -t .`, `python -m tools.check_secrets`), `django`(Mongo·MySQL 서비스 컨테이너 + `python manage.py test`; `server/manage.py`가 생기기 전에는 "건너뜀" 대신 실패하지 않는 빈 단계로 두고, B-05-01 병합과 함께 실제 실행으로 바꿈), `evidence`(아래 3번), `docs`(아래 4번). 네 체크를 `main` 보호 규칙의 필수 체크로 등록.
  2. `check_evidence`: `--format`은 README 4절 양식 제목이 모두 있는지만 본다(`상태: 실패` 문서도 통과). `--complete <ID>`는 README 4절 "검사 규칙" 1~6을 모두 검사한다(조건 번호 누락, 통과 아님, `상태: 실패`, 결과 JSON과 다른 측정값, 없는 커밋 SHA, 검수 기록 누락, **문서화 검사(`check_docs --task <ID>`) 실패**면 실패). `--all --until <날짜>`는 그 날짜까지의 태스크 전부를 `--complete`로 검사. 규칙마다 실패 사례 자체 테스트 포함.
  3. `evidence` 체크(PR 본문 연결, README 11절): PR 본문의 `Task:` 줄에서 태스크 ID를 읽는다. 본문에 `Closes #` 또는 `Fixes #`가 있으면 그 태스크 ID로 `check_evidence --complete`를 돌리고, 없으면(`Refs #`) 변경된 증빙에 `--format`만 돌린다. `Task:` 줄이 없거나 ID가 태스크 문서에 없으면 실패. `Task: P-xx`(결정 대기)는 README 7절 "확정된 결정"에 그 ID가 기록됐는지만 본다. 이 체크가 실패하면 병합이 막히므로, 이슈는 `--complete`를 통과한 PR의 병합으로만 닫힌다.
  4. `check_docs`(README 10절 검사 규칙 1~5): `--task <ID>`는 그 태스크의 문서화 조건(모듈 문서 필수 절·변경 이력 행, 트러블 항목, 문서 산출 태스크의 제목 규칙)을 검사. `--diff <base>`는 PR 변경분에 대해 공개 함수·클래스 docstring, 계약 파일 ↔ 계약 문서 동시 변경, 새 폴더 ↔ `paldo/README.md` 동시 변경을 검사. 규칙마다 실패 사례 자체 테스트 포함.
  5. `check_secrets`: 사설 IP 대역, `password=`/`passwd`/`secret`/`token` 값, 개인 키 헤더를 찾으면 실패. 자체 테스트 포함.
  6. 일부러 규칙을 어긴 PR 3개(증빙 누락 + `Closes`, docstring 누락, 계약 파일만 변경)가 각각 해당 체크에서 실패하는 것을 확인한 화면을 증빙에.
- 워크플로 예시(그대로 써도 됨):

```yaml
name: ci
on: [pull_request, push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
  core:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: python -m unittest discover -s tests -t .
      - run: python -m tools.check_secrets
  django:
    runs-on: ubuntu-latest
    services:
      mongo: { image: "mongo:7", ports: ["27017:27017"] }
      mysql: { image: "mysql:8.4", env: { MYSQL_ALLOW_EMPTY_PASSWORD: "yes" }, ports: ["3306:3306"] }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: pip install -r server/requirements.txt
      - run: cd server && python manage.py test
  evidence:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - name: PR 본문의 태스크 ID로 증빙 검사
        env: { PR_BODY: "${{ github.event.pull_request.body }}" }
        run: python -m tools.check_evidence --pr-body-env PR_BODY --changed
  docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: actions/setup-python@v5
        with: { python-version: "3.12" }
      - run: python -m tools.check_docs --diff origin/${{ github.base_ref || 'main' }}
```

(위 예시의 첫 `test` 작업은 `core`로 대체한다. 서비스 이미지 버전은 `tech_stack.md`에 맞춘다. PR 본문은 셸 명령에 직접 넣지 말고 환경 변수로 넘긴다.)
