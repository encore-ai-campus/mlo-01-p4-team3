### A-05-01 판 생성·배정·아침 진술
- 문제: 첫 구현(b0875d8)에서 문서에 근거가 없는 값과 범위를 임시로 정했다. 조건 6 기준(1000 ms), 목격 확률 0.7, 실행자 거짓 행적(집 고정), 고백 문턱값 채움이 그것이고, 9·11인 프리셋 유지 여부도 범위 축소 결정(11/5)과 겹쳐 확인이 필요했다.
- 원인: 태스크 문서에 조건 6의 합격선, 목격 확률 초기값, 씐 자 거짓 행적 규칙, 고백 범위가 정해져 있지 않았다.
- 대응: PM에게 확인하고 아래 결정대로 고쳤다(b5b38d3).
  PM 결정(11/5): 조건 6은 합격선 없는 기록 조건이고 참고 기준은 엔진 몫 p95 100 ms(A-05-02 조건 5와 같음). 넘으면 실패로 두지 않고 원인을 적는다.
  PM 결정(11/5): 목격 확률 `WITNESS_PROB=0.7` 승인(A의 규칙 상수). 주석 "초기값, A-08-03에서 조정"을 달고 `RULE_PARAMS_VERSION`을 rule-0.2로 올렸다.
  PM 결정(11/5): 실행자 거짓 행적은 기획서 5.2의 단순형으로 바꿨다. 범행 장소와 자기 한밤 목격 장소를 뺀 공공장소 중에서 시드로 고른다(정교화는 A-07-01). `EXECUTOR_ALIBI_PLACE`는 삭제했다.
  PM 결정(11/5): 고백은 A-06-01·A-07-01 범위라 고백 문턱값 코드를 뺐다. 이 태스크는 0일째 비밀 사건과 그 시간대 거짓말만 만든다.
  PM 결정(11/5): 프리셋 6개(9·11인 포함)를 그대로 둔다.
- 결과: 6개 프리셋 × 시드 200개에서 배정 검증기 위반 0건. 실행자 거짓 행적은 4개 공공장소 모두에서 나왔고, 자기 목격으로 반박되는 경우는 0건이다. 판 생성 p95는 0.222 ms(참고 기준 100 ms). 증빙 `docs/evidence/A-05-01.md`

### A-06-02 관측 투영·스냅샷·진실 이벤트·이유 코드

### A-06-03 D·C 인수 패키지 (실제 엔진 소량 판)
- 문제: 엔진 판 메타(`GameMeta.npc_policy_versions`) 기본값이 빈 dict라, 그대로 봉투를 만들면 모든 이벤트의 정책 버전이 비어 D가 정책 버전별로 데이터를 나눌 수 없었다(parallel_dev.md 3절). 첫 검사 도구는 진실·결정 본문의 형식이 깨진 줄에서 위반 보고 대신 예외로 멈추고, 관측·결정이 통째로 빠진 판이나 manifest 판 수가 없는 패키지를 통과시켰다(Codex 리뷰 3회에서 지적).
- 원인: `npc_policy_versions`를 채우는 판 시작 유스케이스가 아직 없고, 엔진은 메타를 받은 그대로 쓴다. 검사는 `decision`을 만났을 때만 짝·이유 코드를 보고, 봉투 본문(`payload: dict[str, Any]`)의 값 타입은 `serde`가 검사하지 않는다.
- 대응: PM 결정(11/6)대로 실행 도구가 `new_game` 직후 주민 전원(실종자 포함)을 정책 버전(`min-legal` → `baseline-0`)으로 채운 메타로 이후 전이를 진행하고 봉투에 싣는다(엔진 계약 변경 없음). 검사는 본문 값 타입을 먼저 확인하고, 판마다 결정 1개 이상·관측 수 = 결정 수를 요구하며, manifest 판 수가 양의 정수가 아니면 실패한다. 재실행 실패 때 옛 manifest가 남지 않게 실행 시작 때 지운다. 각 지적은 위반 주입 테스트로 고정했다.
- 결과: base6 200판 이벤트 17823개, 인수 조건 위반 0건(관측 5704·결정 5704·진실 200), 처리량 14.653 판/초, 같은 명령 재실행 시 `events.jsonl` sha256 동일. `tests/tools/test_run_engine_games.py` 19개 통과. 증빙 `docs/evidence/A-06-03.md`

### A-07-04 이미지 도구 시험 생성

- 원인: 도구 입력에 시드 설정이 없고, 생성 요청만으로 픽셀 크기·비율·세부 외형을 보장할 수 없다. 첫 생성은 계측하지 않았다. 이전 얼굴 영역은 공통 고정 값이었으나 최신 dev는 인물 키 등급에서 계산한다.

### A-08-04 단색 바탕 처리 시험

- 대응: ① `tools/assets/normalize.py`를 만들어 인물별 머리카락 윗선과 보이는 발끝으로 단일 배율을 정하고 `cutout.fit_sprite`로 배치했다(10장이 모두 규격을 통과해야 파일을 씀). ② 갓 없는 5명의 (눈 − 머리카락 윗선)/(턱 − 눈) 평균 1.23을 갓 쓴 3명의 눈·턱에 적용해 추정하고, 갓 아래로 보이는 머리카락과 어긋나지 않는지 확대 그림으로 확인했다. 값과 근거는 `HAIR_TOP` 표 주석. ③ 원본 PNG의 콘텐츠 자격 증명(C2PA)에서 도구·모델·생성 시각을 읽어 `SOURCES.md`에 적고, 프롬프트 전문·금지 지시는 "B 확인 대기"로 두었다. ④ 11/9 사용자 결정(에셋2 예외)으로 프롬프트는 받지 않기로 하고 그 칸을 "확인 불가"로 바꿔 닫았다.
- 결과: 8명 모두 머리카락 윗선이 등급 값, 발끝 y=1248, 가로 가운데 255.5~256. 마스코트 2장 아랫변 480·가운데 256. `check_assets --placeholder` 에셋2~4 위반 0(실제 18개). 시연 기준 모드의 위반 60건은 범위 밖(장면 배경·표정 변형·추가 주민)이다. `SOURCES.md`의 프롬프트 칸은 "확인 불가"이고 도구·모델·생성 시각은 C2PA 값이다. 증빙 `docs/evidence/A-09-05.md`

### A-10-05 장면 배경 2장 (회의·밤)
- 문제: 회의·밤 배경이 그라데이션에 "회의 배경(임시)"·"밤 배경(임시)" 글자가 박힌 임시 그림이라 사용자 테스트(11/10) 화면에 그대로 보일 상황이었다. 실제 배경 원본은 B의 11/7 화면 설계 시안 HTML 안에만 base64로 들어 있었고 크기도 1672×941로 규격(1280×720)과 달랐다.
- 원인: 배경 생성 담당(D, 11/10 예정) 전에 B가 시안용으로 먼저 만든 그림이 저장소 규격으로 옮겨지지 않았다. 1672×941은 16:9에서 0.06% 벗어난다.
- 대응: `tools/assets/normalize.py`에 배경 정규화(`background_crop`·`fit_background`·`normalize_backgrounds`, CLI `--background id=경로`)를 더했다. 가운데 기준으로 정확한 16:9(1664×936)로 잘라 가로·세로 같은 배율(0.76923)로 줄이고, 두 장이 모두 규격을 통과한 뒤에만 파일·manifest를 쓴다. 도구·모델·생성 시각은 원본 C2PA 기록에서 읽어 `SOURCES.md`에 적었다. 프롬프트·금지 지시는 시안용 생성이라 기록이 없어 "확인 불가"로 적었다(11/9 사용자 결정, B에게 받지 않음).
- 결과: 두 장 모두 1280×720 불투명 RGB(meeting 1,936,669바이트, night 1,513,399바이트, 상한 10MB), `check_assets` 에셋2~4 위반 0, 시연 기준 모드의 임시 허용 범위 위반이 60 → 58건(남은 58은 표정 변형·추가 주민, 범위 밖). 인물·글자·사람 그림자 없음(눈 확인). 증빙 `docs/evidence/A-10-05.md`
