### B-10-04

- 문제: 로컬·실제 DB·가짜 광고·VM 대기 결과가 여러 태스크 증빙에 나뉘어 있어 발표에서 측정 범위를 혼동할 수 있었다. 초안 증빙에는 다른 태스크의 후속 검증을 B-10-04 실패 조건으로 추가한 오류도 있었다.
- 원인: 각 증빙의 측정 SHA와 전송 방식이 다르고 시험 대상이 겹치므로 테스트 수를 단순 합산하거나 현재 dev 성능으로 옮길 수 없다. 산출물의 후속 갱신 목록을 태스크 자체의 필수 선행으로 잘못 해석했다.
- 대응: [발표 초안](../presentation/B.md)을 네 구간으로 구성하고 트러블·성능·테스트 수마다 증빙을 연결했다. 원래 태스크에 없는 실패 조건을 제거하고 후속 갱신 목록·실제 인계 상태를 별도로 명시했다.
- 결과: 네 구간·트러블 세 건·원본 수치 대조 결과와 보완 검사는 [B-10-04 증빙](../evidence/B-10-04.md)에 기록한다. 11/11 dev 92ddbad 기준으로 S-11-03 인계 목록을 추가하고 가짜 광고 시험과 실제 광고 장애 시험의 범위를 구분했다. 기능 시험·새 성능 측정은 수행하지 않았으며 실제 인계는 대기다.

### B-09-03 리허설 준비

- 문제: 로컬 회귀에서 기능 결함은 미발견했으나, 준비 문서가 SHA 유지 규칙을 13:00~18:00 절에만 적어 리허설 중 재배포 조건이 모호했다. 실제 리허설·테스트 중 신고는 아직 미수행이다.

- 대응: [리허설 절차](../../server/tests/REHEARSAL.md)에 로컬/실제 환경 구분, 결함 재현 양식, E 승인·C 배포와 SHA 유지 절차 및 확인 대기를 기록했다. SHA 유지를 10:30 리허설부터 18:00까지로 명시하고, 리허설 재배포도 E가 승인한 blocker 수정으로 한정했다. 디자인·운영 코드와 공통 계약은 수정하지 않았다.

### B-09-02 BERT 연결 사전 준비

- 문제: 같은 호스트에서는 가능했던 실제 엔진·해석 혼합 부하를 서버와 부하 생성기가 분리된 모드에서 실행할 수 없었다.
- 원인: 서버 CLI가 혼합 간격을 거절했고, 교환 파일과 부하 생성기 호출에 간격이 없었다.
- 대응: 서버가 정한 간격을 교환 파일로 전달하고 반환 간격을 대조한다. 간격0·기존 접근 제한·운영 해석기 설정은 유지한다.
- 결과: 분리 도구 관련 검사 37건 중 33건 통과·Redis 관련 4건 건너뜀. 최신 dev HTTP 회귀 54건 중 44건 통과·실물 BERT 필요 10건 건너뜀. 로컬 실제 엔진은 해석10·취소10·게임/비콘 오류0. 실제 모델·분리 호스트/VM 성능은 대기다. [증빙](../evidence/B-09-02.md#1111-실제-엔진-분리-부하-연결-보완)

#### D 어댑터 수신 후 연결(11/9)

사용자 요청으로 현재 범위는 **연결 준비 완료**로 마무리한다. 최신 dev fc75e6e의 D-08-02 광고 변경은 반영했으며 실제 체크포인트·실제 엔진 부하·VM 측정은 후속 대기다. 태스크 전체 완료나 운영 BERT 전환을 뜻하지 않는다.

**어댑터 연결.** 경로가 필요한 `BertIntentParser(run_dir)`를 무인자 `INTENT_PARSER_FACTORY`로 직접 만들 수 없어 `make_bert_parser`로 보호 환경의 로컬 경로를 전달했다. 기본값은 유지하고 로드 실패는 기준선으로 대체하지 않았다. Django 115건 중 104건 통과·실제 체크포인트 10건과 Mongo 1건 건너뜀, D 경계 8건 중 4건 통과·실물 torch 4건 건너뜀이다. 실제 모델 수신·실측 p95는 대기로 남겼다. [당시 증빙](../evidence/B-09-02.md#119-마무리-범위-연결-준비-완료)

**녹화 엔진 혼합 부하.** 기존 시험은 `fixture_service`가 interactions를 비우고 시작·명령만 측정했다. 시험에만 해석기·Mongo 보조 기록을 주입해 해석·취소를 더하고 전체 API·해석 HTTP·순수 해석 지연·프로세스별 호출 수를 분리했다. 로컬 Caddy·Daphne 2프로세스·격리 Mongo에서 해석 24건·취소 24건·완주 2건, 게임·웹소켓 오류 0건을 확인했다. 실제 BERT·동급 VM은 판정하지 않았다. [당시 증빙](../evidence/B-09-02.md)

- 결과: 서버 관련 60건과 Chrome PC·모바일 확인 44항목 통과. 가로 넘침·깨진 이미지·JS 예외·HTTP 오류 0건. [증빙](../evidence/B-11-01.md). 결과·설문 재배치와 툴팁 줄바꿈 등 기존 확대 수정본은 사용자 요청으로 제출에서 제외했다.

### B-11-01 판 종료 화면 탭·안내 개선

- 문제: 결과 탭에 설문과 공개 기록이 섞여 있었고, 조회에 실패하면 같은 탭을 다시 눌러야 했다.
- 원인: 종료 템플릿이 세 탭만 제공했고, 스크립트에 의존하던 설문 양식과 조회 안내에 별도 복구 경로가 없었다.
- 대응: 승인된 다섯 탭을 적용했다. 탭은 표시만 바꾸며, 조회 재시도는 기존 GET을 사용한다. 설문은 기존 POST로 제출하고 HTML 기본 폼도 저장 확인 뒤 같은 판으로 돌아온다. 기존 체크박스와 두 진술 비교를 유지했다.
- 결과: 최신 dev `fd02936`에서 서버 시험 543건 중 529건 통과·14건 건너뜀, PC·모바일 브라우저 95항목 통과. 새 버튼에 한 줄 설명을 붙여 기존 툴팁 시험을 통과했다. 마지막 투표 뒤 탭 초기화와 기존 광고 지면·저장 규칙, #383 복기 해설의 시험용 응답을 확인했다. [증빙](../evidence/B-11-01.md#판-종료-화면-탭안내-개선-1111-승인).

### B-11-01 금색·한지 UI 표시 오류 후속

- 11/12 추가: 건수 배지의 음수 여백을 없애고 선택 수 안내와 간격·서체를 정리했다. 긴 첫 판 안내는 PC 대사창을 넓혀 끝까지 표시한다. CSS 200% 확대에서 대사 조작부의 최소 열 폭이 가용 폭을 넘고, 진술표 필터의 3열 고정으로 글자가 사라졌다. 내용 폭을 기준으로 읽기 조작과 필터 배치를 전환했다. 진술표 회귀 테스트는 접근성 속성이 추가된 목록 태그를 인식하도록 보완했다. 일반 180개·확대 40개 배치에서 가로 넘침·조작 요소 잘림·깨진 이미지·JS 예외 0건, 관련 서버 회귀 173건 통과. [후속 증빙](../evidence/B-11-01.md#좁은-가용-폭확대-표시-후속-보완).

- 문제와 원인: 오류 안내 높이를 무대 계산에 반영하지 않아 메뉴·대사·출처가 겹쳤다. 진술 목록 두 줄 제한과 아래 비교 버튼이 접근을 방해했다. htmx 실패 응답에서도 읽기 이벤트를 해제하고 포인터 이탈 때 설명 상자를 닫지 않았다. 도움말의 화면 높이 단위는 CSS 확대 후 실제 보이는 높이보다 컸다.
- 대응: 머리글·안내·무대·출처를 격자로 분리하고, 진술표는 비교 버튼을 목록 위에 고정해 창 하나에서 스크롤한다. 화면의 실제 제거 시점에 읽기 이벤트를 정리하며 포인터 이탈·스크롤 때 말풍선을 닫는다. 도움말은 본문 스크롤과 고정 제목·닫기, 퍼센트와 동적 화면 높이 중 작은 최대 높이를 사용한다.
- 결과: dev `4780db2` 기반의 PC·모바일 160개 배치 확인과 별도 683px·730px 재현 조건 통과. CSS200%의 제목·닫기 잘림도 보완 후 통과했다. 서버 회귀 87건 중84건 통과·MySQL 조건3건 제외. [증빙](../evidence/B-11-01.md#pr-422-병합-후-표시-오류-보완).
