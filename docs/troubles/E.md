### E-05-01 저장소·결정 기록·담당 배정·이슈 생성
- 문제: 브랜치 보호 규칙(PR 필수, 필수 체크 4개, 작성자 외 1명 승인)을 설정하려 하자 GitHub가 HTTP 403("Upgrade to GitHub Pro or make this repository public")을 돌려줬다. 11/5 담당 변경 뒤에는 이슈 담당자가 옛 흐름 담당으로 남았고, ID가 바뀐 옛 이슈 3개가 열린 채 남았다.
- 원인: 교육기관이 저장소를 비공개로 만들었고(P-11 전제는 공개), 조직이 무료 플랜이라 비공개 저장소에는 보호 규칙·규칙 집합을 쓸 수 없다. 이슈 동기화 도구는 담당자를 더하기만 하고 빼지 않았으며, 원본에서 사라진 ID는 보고만 했다.
- 대응: 보호 규칙은 운영 규칙으로 대체했다(병합 전 작성자 외 1명 승인과 CI 4개 통과를 사람이 확인하고 병합은 PM이 한다. 병합 방식은 저장소 설정으로 merge commit만 허용). `tasks_to_issues --assign`이 흐름 담당으로 덮어쓰게 고쳤고(로그인 비교는 대소문자 무시), 옛 이슈 3개는 새 ID를 적은 댓글과 함께 not planned로 닫았다.
- 결과: 열린 이슈 130개 = `--dry-run` 130개, 담당 1명씩 130개, 원본에 없는 열린 이슈 0개. 보호 규칙은 설정 0개(불가). 증빙 [`docs/evidence/E-05-01.md`](../evidence/E-05-01.md)

### E-05-02 GitHub Actions와 증빙·문서·비밀정보 검사
- 문제: 원래 조건 5 문구("`password=`/`passwd`/`secret`/`token` 값")를 그대로 구현하면 저장소 전체 검사에서 비밀이 아닌 39줄이 걸렸고(광고 픽스처의 serve 토큰 자리 가짜 이름 19줄, 그 생성 코드 19줄, CI 예시의 MySQL 빈 암호 허용 설정 1줄), 규칙을 고친 뒤에도 조건 5 문구 자체의 대역 표기(`docs/tasks/E_pm.md` 84행, 점 네 개 IPv4 3개)가 사설 IP로 걸렸다.
- 원인: 키 이름 부분 문자열 일치는 게임 용어(`secret_id`, `secrets`)·광고 serve 토큰 자리의 가짜 이름과 실제 비밀을 구분하지 못한다. 대역을 점 네 개 주소로 적은 문구는 검사 규칙이 정의상 잡는 형식이다.
- 대응: PM 결정(11/4)으로 규칙 확정 — 키 이름의 마지막 조각 일치 + 문자열 값, 파일·키 단위 예외 목록 `tools/secrets_allowlist.txt`(4항목, 죽은 예외는 실패). 대역 표기는 원본 문구를 `10/8` 형식으로 고치기로 함(PM 세션 반영). 구현은 바꾸지 않음.
- 결과: 예외 적용 전 39줄 → 예외 4항목으로 0줄. 원본 문구 수정 전에는 3줄이 남는다(`python -m tools.check_secrets`). 증빙 [`docs/evidence/E-05-02.md`](../evidence/E-05-02.md)

### E-05-05 스타일 가이드·파일 규격·임시 에셋
- 문제: 사전 작업(11/4) 시작 때 태스크 원본의 임시 파일 위치가 서로 달랐다. 산출물·교체표는 `content/images/placeholder/`, 원칙은 "실제와 같은 경로에 덮어쓰기"였다. 픽셀 크기·manifest 형식·아이콘 ID도 정해져 있지 않았다. 작업 중에는 주인공이 1종에서 여·남 2종으로 바뀌어 기대 수가 36에서 37로 늘었다.
- 원인: 태스크 문서가 11/4 PM 결정(유형별 크기, manifest 형식, 주인공 2종)보다 먼저 쓰였다.
- 대응: 구현 전에 PM에게 확인했고, 원본이 보완됐다(master bfd824e, f4c08b5). 실제 경로 `content/images/<kind>/`에 임시 파일을 만들고 `placeholder` 표시로 구분했다. 기대 항목은 규격표(`docs/assets/spec.md`)와 픽스처에서 계산하고, 수를 코드에 적지 않아 37로 바뀐 것을 코드 수정 없이 반영했다. 아이콘 ID는 엔진 enum 이름에 맞춰 PM 확인을 받았다. 화풍은 만화풍 평면 채색 SVG 샘플을 본 PM이 도트로 바꿨다. SVG를 작은 격자로 자동 변환하면 얼굴이 뭉개져서, 샘플은 픽셀을 직접 지정해 다시 만들었다. 파일 크기는 그대로 두고 원본 격자 × 정수 배율 규칙을 원본에 추가했다(master bc15d01, dfb556d). 초상 격자는 샘플을 보고 64에서 128로 바꿨다. Claude가 코드로 그린 그림은 실제 에셋 품질에 못 미쳐(PM 판단) 임시 초상에만 쓰고, 실제 제작 방식은 미정(P-10)으로 남겼다. 임시 초상은 표준 라이브러리로 128 격자에 직접 래스터화했다. 첫 샘플에서 눈썹이 앞머리 위로 비친 원인은 그리는 순서였다. 그래서 머리카락을 얼굴 요소보다 나중에 그리고, 스타일 가이드 4절에 탈락 기준으로 넣었다. 커밋돼 있던 단색 임시 초상 13장은 새 생성기와 바이트가 달라 `protected_files`로 잡혀서 `--force`로 한 번 다시 만들었다.
- 결과: 유형별 기대 수 = manifest 항목 수 = 파일 수 = 37(누락 0, 남는 파일 0, 규격 위반 0), 최대 파일 5,788바이트(상한 512,000). 증빙 `docs/evidence/E-05-05.md`

### E-06-07 LLM 벤치마크
- 문제: 시험 실행에서 세 가지가 어긋났다. Kanana-2-3B는 모델 로드 뒤 채팅 템플릿에서 `TemplateSyntaxError: Encountered unknown tag 'generation'`으로 멈췄다. Qwen3-4B 가중치 메모리는 파일 크기(2.50 GB)보다 큰 4,046 MiB로 나왔다. 지연은 생성보다 프롬프트 처리(약 180 토큰에 5~10 s)에서 대부분 나왔다.
- 원인: Kanana 템플릿은 HF 학습용 태그 `{% generation %}`를 쓰는데, 일반 jinja2에는 이 태그가 없다. 가중치는 llama.cpp가 파일 매핑(`CPU_Mapped` 2,363 MiB)과 AVX2용 재배열 사본(`CPU_REPACK` 1,683 MiB)을 따로 로그에 남기는데, 이 둘을 한 값으로 더했다. 출력이 짧아(평균 10~22 토큰) 프롬프트 처리 비중이 크다.
- 대응: `generation` 태그를 본문 그대로 통과시키는 jinja 확장을 넣고 테스트를 추가했다. 가중치는 `weights_mib`(매핑)·`weights_repack_mib`·`weights_total_mib`로 나눠 기록했다. Codex 리뷰 지적에 따라 생성 실패가 있으면 결과를 쓰지 않게 했고, 다른 기기 결과는 측정 커밋이 같을 때만 받게 했다. 프롬프트 처리 비중은 보고서에 적어 E-07-07(프롬프트 길이)과 E-08-09(접두어 재사용)로 넘겼다.
- 결과: 4개 모델 모두 측정했다(오류 0건). 최종 조합 Kanana-2-3B 스레드 8, 동시 4건 p95는 14,419 ms(켬)·12,419 ms(끔)로 15 s 이하다. 증빙 [`docs/evidence/E-06-07.md`](../evidence/E-06-07.md)

### E-07-07 추궁 표현: 프롬프트·검증기·평가 세트
- 문제: 첫 프롬프트(규칙만 나열)로 100건을 시험하니 성공이 85건이었다. 모델이 "사실 문장:" 머리말까지 따라 쓰거나 예시 문장을 그대로 베꼈고, 말투는 거의 입히지 않았다. 최종 측정 전 시험(21f00b5)에서는 "그날"을 "그 날"로 띄어 쓴 답 4건이 `fact_changed`로 거부됐다.
- 원인: 3B 모델이 지시보다 예시·형식을 강하게 따른다. 행적 예시 하나만 주면 고백 사례(사실이 행적 문장이 아님)에서 예시를 베꼈다. 검증기의 사실 어절 비교가 띄어쓰기까지 같아야 통과하게 되어 있었다.
- 대응: 반응 의도별 예시 한 쌍(user "사실 문장: …" → assistant 대사)을 넣고, 고백은 고백형 예시를 줬다. 예시에는 게임에 없는 장소 '방앗간'과 숫자 '4일째'를 써서 베끼면 검증기가 거부하게 했다. Codex 리뷰 지적으로 사실 문장 어절 보존·사건 단정 동사·덧붙임 길이 상한(한글 25자)을 검증에 더했고, 어절 비교는 띄어쓰기를 무시하게 고쳤다.
- 결과: 100건 성공 98 %, 폴백 2건(모두 `fact_changed`, 폴백의 사실 문장 포함 100 %), 전체 p95 5,468 ms, 일관성 판정 일치 95 %. 남은 문제: 말투가 인물별로 거의 같고, 같은 프롬프트로 동시 4건을 재면 p95 18,167 ms(참고 측정)라 E-08-09에서 줄여야 한다. 증빙 [`docs/evidence/E-07-07.md`](../evidence/E-07-07.md)
