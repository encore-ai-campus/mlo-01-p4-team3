### E-05-02 GitHub Actions와 증빙·문서·비밀정보 검사
- 문제: 원래 조건 5 문구("`password=`/`passwd`/`secret`/`token` 값")를 그대로 구현하면 저장소 전체 검사에서 비밀이 아닌 39줄이 걸렸고(광고 픽스처의 serve 토큰 자리 가짜 이름 19줄, 그 생성 코드 19줄, CI 예시의 MySQL 빈 암호 허용 설정 1줄), 규칙을 고친 뒤에도 조건 5 문구 자체의 대역 표기(`docs/tasks/E_pm.md` 84행, 점 네 개 IPv4 3개)가 사설 IP로 걸렸다.
- 원인: 키 이름 부분 문자열 일치는 게임 용어(`secret_id`, `secrets`)·광고 serve 토큰 자리의 가짜 이름과 실제 비밀을 구분하지 못한다. 대역을 점 네 개 주소로 적은 문구는 검사 규칙이 정의상 잡는 형식이다.
- 대응: PM 결정(11/4)으로 규칙 확정 — 키 이름의 마지막 조각 일치 + 문자열 값, 파일·키 단위 예외 목록 `tools/secrets_allowlist.txt`(4항목, 죽은 예외는 실패). 대역 표기는 원본 문구를 `10/8` 형식으로 고치기로 함(PM 세션 반영). 구현은 바꾸지 않음.
- 결과: 예외 적용 전 39줄 → 예외 4항목으로 0줄. 원본 문구 수정 전에는 3줄이 남는다(`python -m tools.check_secrets`). 증빙 [`docs/evidence/E-05-02.md`](../evidence/E-05-02.md)

### E-05-05 스타일 가이드·파일 규격·임시 에셋
- 문제: 사전 작업(11/4) 시작 때 태스크 원본의 임시 파일 위치가 서로 달랐다. 산출물·교체표는 `content/images/placeholder/`, 원칙은 "실제와 같은 경로에 덮어쓰기"였다. 픽셀 크기·manifest 형식·아이콘 ID도 정해져 있지 않았다. 작업 중에는 주인공이 1종에서 여·남 2종으로 바뀌어 기대 수가 36에서 37로 늘었다.
- 원인: 태스크 문서가 11/4 PM 결정(유형별 크기, manifest 형식, 주인공 2종)보다 먼저 쓰였다.
- 대응: 구현 전에 PM에게 확인했고, 원본이 보완됐다(master bfd824e, f4c08b5). 실제 경로 `content/images/<kind>/`에 임시 파일을 만들고 `placeholder` 표시로 구분했다. 기대 항목은 규격표(`docs/assets/spec.md`)와 픽스처에서 계산하고, 수를 코드에 적지 않아 37로 바뀐 것을 코드 수정 없이 반영했다. 아이콘 ID는 엔진 enum 이름에 맞춰 PM 확인을 받았다. 화풍은 만화풍 평면 채색 SVG 샘플을 본 PM이 도트로 바꿨다. SVG를 작은 격자로 자동 변환하면 얼굴이 뭉개져서, 샘플은 픽셀을 직접 지정해 다시 만들었다. 파일 크기는 그대로 두고 원본 격자 × 정수 배율 규칙을 원본에 추가했다(master bc15d01, dfb556d). 초상 격자는 샘플을 보고 64에서 128로 바꿨다. Claude가 코드로 그린 그림은 실제 에셋 품질에 못 미쳐(PM 판단) 임시 초상에만 쓰고, 실제 제작 방식은 미정(P-10)으로 남겼다. 임시 초상은 표준 라이브러리로 128 격자에 직접 래스터화했다. 첫 샘플에서 눈썹이 앞머리 위로 비친 원인은 그리는 순서였다. 그래서 머리카락을 얼굴 요소보다 나중에 그리고, 스타일 가이드 4절에 탈락 기준으로 넣었다. 커밋돼 있던 단색 임시 초상 13장은 새 생성기와 바이트가 달라 `protected_files`로 잡혀서 `--force`로 한 번 다시 만들었다.
- 결과: 유형별 기대 수 = manifest 항목 수 = 파일 수 = 37(누락 0, 남는 파일 0, 규격 위반 0), 최대 파일 5,788바이트(상한 512,000). 증빙 `docs/evidence/E-05-05.md`

### E-05-03 인물 6·비밀 6 초안 (첫 플레이 버전)
