# C-08-04 콘텐츠 대조·사용자 테스트 준비
- 커밋: 43d21ad4ad7081f4856832313e654556dc72545a
- 작성자(흐름): C
- 환경: 2026-11-08 실제 PJ4 VM, Python 3.14.4.
- 상태: 부분 완료. 아래 미완료 조건을 유지하고 Refs PR로 제출한다.

11/8에는 운영 paldo_web의 content-1.0과 후보 5315516의 bundle을 같은 DTO로 읽고 정규 직렬화 SHA를 대조해 일치했다. 11/9에는 dev 4e5c703의 content-1.0.1이 운영 Mongo에 아직 없음을 실제 조회로 확인했다. 11/10 09:00–10:00에 E가 그 시점의 후보를 고르면 후보에서 적재·재대조한다.

**미완료 조건 2:** 11/10에 E가 고른 후보 SHA를 고정해 배포하고 10:30 리허설에 들어간다. 통과하면 E가 12:00에 같은 SHA에 태그를 단다. 11/9에는 `release --candidate`로 dev 4e5c703의 고정 묶음을 실제 생성했다. E 확정 후보 배포, 일반 판 시작 확인, 30명 부하 측정과 태그 대조는 미실행이다.

**미완료 조건 3:** 4th_private 실제 전달 위치를 로컬·접근 가능한 GitHub 저장소·연결 Drive에서 찾지 못했다. 경로를 확인하기 전에는 계정을 만들지 않았고 자격정보를 다른 곳에 기록하지 않았다. reader 도구의 경로 우회/덮어쓰기 guard와 dev/main 거절은 단위 시험했다. 운영 read·쓰기 거절 code13은 **아직 실행하지 않았다**.

**미완료 조건 4:** PM #267의 D 접속 전달을 추가 반영했다. 광고 DB·TLS·Garage 공용 설정의 보호 경로와 pj4/ 쓰기 금지, D 읽기 prefix를 정리한 인계 초안은 저장소 밖에 있다. 실제 D가 접근 가능한 전달 위치와 수신 확인은 미완료다. 증빙에 계정 원문이나 보호 경로를 복사하지 않는다.

11/9 사전 검증에서 운영 설치본 Caddy 2.6.2가 `health_fails`를 인식하지 못했다. 별도 바이너리 v2.11.8로 후보 Caddyfile의 운영 환경값 검증과 Daphne 템플릿 unit의 `systemd-analyze verify`를 통과했다. 격리 비교의 앞단이 자동 HTTPS를 끈 뒤에도 HTTPS로 구성되는 문제를 찾아 HTTP 스킴과 loopback bind를 명시했다. 이 검증은 운영 바이너리 교체나 E 후보 배포와 구분한다.

조건 7은 후보에 `backfill_surveys` 명령이 있는지 테스트 서버에서 도움말로 확인했다. 격리 설문 테스트 6건과 마감 뒤 보충 이벤트 집계 테스트를 통과했다. 실제 보충은 11/10 18:00 KST 직후 실행하고 성공 후 스냅숏을 확보한다. 조건 8은 B-10-07에서 확정한 화면 설정과 E 요청이 필요하다.

## 명령

```sh
git ls-remote --tags origin "v-usertest-*"
python ops/user_test_ops.py release --repo "$REPO" --candidate "$E_SHA" --out "$PRIVATE_ARCHIVE"
python ops/user_test_ops.py release --repo "$REPO" --tag "$E_TAG" --out "$PRIVATE_ARCHIVE"
# 아래 reader 명령은 보호 위치 확인 후에만 실행, 현재 미실행
python ops/user_test_ops.py reader --admin-profile "$PRIVATE_ADMIN" --ca "$PRIVATE_CA" --seed "$PRIVATE_SEED" --out "$CONFIRMED_4TH_PRIVATE/reader.json"
python -m unittest tests.ops.test_user_test_ops -v
```
