두 분류기의 라벨은 7건 모두 정답과 일치했다. 공통 슬롯 처리 `intent.matcher.resolve_time`은 붙여 쓴 시간대만 읽고, 밤 번호가 생략되면 지정된 상대 시간 표현이 있을 때만 공개 기록에서 밤 번호를 구한다. 오류 입력에 이 함수를 직접 적용하면 `(None, None)`이며, 시간대 띄어쓰기만 정규화하면 `(None, midnight)`, 상대 시점 표현도 명시하면 검수 정답과 같은 `(0, midnight)`다. 이 진단은 평가 원본과 점수를 바꾸지 않았다. 슬롯 개선은 띄어쓰기 변형과 공개 문맥에 밤이 하나뿐인 경우를 각각 검증하고, 여러 밤 중 대상을 정할 수 없으면 기존 확인 절차를 유지한다. 공통 슬롯을 개선하면 두 모델이 모두 이득을 볼 수 있다. BERT의 분류 개선 여부는 별도의 미사용 사람 입력에서 같은 슬롯 처리로 비교한다.

BERT parse p95는 192.547 ms, 기준선은 2.137 ms다. 로그는 `out/d09_01/development_42f7a0f.txt`, 상세 결과는 `mlruns/intent_human_eval/20261109T124007753397Z/run.json`이다. 이 개발 CPU 실측은 수명주기 100ms 지연 신호를 넘으므로 실제 웹 환경의 성능 검증이 필요하다. 사람 평가 인계 전이라 채택은 대기이며 평가 출력의 `accepted`는 0이다.

아래 11/8 및 11/9 초기 검사 출력은 당시 이력으로 보존했다.

```text

OK (skipped=4)
```

개발 측정 이후 `origin/dev`의 `af951da`를 D-09-01에 반영했다. 변경은 태스크 문서 5개였고 D-09-01 완료 조건은 동일했다. 갱신한 기준에서 실행한 전체 검사 출력은 `out/d09_01/precheck_dev.txt`에 있다.

```text
precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 861개, base af951da, 203초)
```

11/8에는 실물 PyTorch 통합 테스트가 `import torch`에서 `OSError: [WinError 4551]`로 실패했고 개발 평가 CLI는 종료 코드 2를 반환했다. 11/9 첫 재시도도 `torch._C` 로드가 앱 제어 정책에 차단됐으나, 이후 동일 환경에서 import와 실제 D-07-03 모델 추론이 성공했다. 정책 설정을 변경하지 않았으며 성공으로 바뀐 원인은 미확인이다. C-05-03은 기준 개발 PC의 설치·검증 태스크다. 실제 웹 환경의 BERT 연결 검증은 B-09-02 1번이며 C 신성민에게 VM 환경 지원을 요청할 수 있다. Windows 정책 변경 권한자는 태스크 문서에 명시돼 있지 않다.

최신 실행은 `out/d09_01/development_1109.txt`(종료 0), `out/d09_01/bert_integration_1109.txt`(4개 통과), `out/d09_01/precheck_1109.txt`에 있다. 미리 준비한 공개 문맥·주석을 공식 `ut_freeze` manifest의 원문·ID·사용자·판에 조인하는 검사도 통과했다. 64개 의도 테스트 중 기본 실행에서는 실물 ML 통합 4개를 생략했고, 별도 실행에서 그 4개를 실제로 통과했다.

```text

OK
precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 1080개, base a6675f8, 206초)
```

KoELECTRA `koelectra-intent-v0-7ec09f448fe3`은 D-07-03 5 epoch 실행 `20261107T162208Z`의 산출물이다. `model.safetensors` SHA-256 `7ec09f448fe3f768575227be0baebdb23408bf829968eb2694c29e39d18239d3`이 실행 기록과 일치했다. `config.json`의 분류 라벨 10개, 토크나이저 파일 2개, 원본 데이터 SHA-256과 학습/개발 ID도 확인했다. 개발 입력은 동일 원본 532행 중 기존 학습 390행과 분리된 개발 142행이다. 390행으로 다시 맞춘 TF-IDF의 비교값을 이번에 측정했다. [D-07-03 증빙](D-07-03.md)의 5 epoch 명령 일치율 83.80%는 기존 개발 실험 결과다. 그 실행의 보관된 예측에서 명령 불일치 23건 중 `defend`와 `unsupported`가 각각 5건, `interrogate_suspicion_reason`과 `interrogate_whereabouts`가 각각 4건이었다. 같은 실행에서 미지원 15건 중 후보를 낸 경우는 5건이었다. 이 라벨들은 D-10-01 개발 보강 시 우선 확인할 지점이다.

개발 TF-IDF 명령 일치율 64.79%의 95% 구간은 55.17~73.94%, BERT 83.80%의 구간은 75.16~91.54%다. 실제 사람 평가에서는 웹 기본 TF-IDF를 기준선으로 사용하고, 발언 당시 공개 문맥과 독립 주석 명령을 비교한다. 이번 지연은 전체 precheck 등과 병렬로 실행한 개발 CPU 측정이며 B-09-02의 테스트 서버 동시 30명 API 측정은 별도로 필요하다.
