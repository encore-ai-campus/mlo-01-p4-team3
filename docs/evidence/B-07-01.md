### 추가 불일치 3건 개선 재검증 (`a30dbb3` 작업본)

- 수정 전 실제 기준선 해석기의 회귀 시험 3개가 모두 실패하는 것을 확인했다. 다중 의도의 정상 카드까지 비활성화됐고, 직전 캐묻기 상대와 재입력 선택 문맥이 전달되지 않았다.
- 카드별 누락 슬롯·근거 모호성으로 확인 가능 여부를 판정한다. 실제 입력 “주모가 수상하다; 0일째 밤의 말이 모순이다”에서 모호한 카드만 비활성화되고 정상 의심 카드는 확인 가능하다. 녹화 엔진으로 해당 카드 하나의 수락·버전 증가를 확인했다.
- 직전 상대는 공개 캐묻기 질문·답변에서 찾는다. 주모 캐묻기 뒤 “수상하다”는 주모로 해석되며, 선택 인물·명시 인물이 있으면 각각 우선한다. 재입력은 선택 인물·공개 근거·직전 상대를 보존하고 새 시도를 연결한다. 원문은 추가 보존하지 않는다.
- 최종 카드·화면 시험 22개(4.038초), 실제 기준선 계약 3개(0.102초)가 통과했다. Django 회귀 112개 중 109개 통과·MySQL 전용 3개 건너뜀(27.715초). 로그는 `out/handoff/B-07-01-context-ui.log`, `out/handoff/B-07-01-context-django.log`다. 이번 추가 검증은 HTTP·메모리 저장·녹화 엔진 기준이며 브라우저 재실행·실제 DB·LLM·VM 성능 검증은 포함하지 않는다.
- 이 단계의 시험은 구현 커밋 전에 실행했다. 이후 구현 SHA를 문서 상단에 반영했고 격리 MySQL 시험을 추가했다.
- 저장소 사전 검사도 통과했다. `precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 701개, base a30dbb3, 62초)`. 로그는 `out/handoff/B-07-01-context-precheck.log`다. PR 본문을 포함한 완료 검사는 아직 수행하지 않았다.

### 최신 dev 재검수 (`36a30cb`, 11/7)

PR #212(A-07-02)의 엔진 변경을 반영했다. 이전 `2d4a350` 이후 API·이벤트·태스크 계약의 변경은 없다. 반영 전 작업 파일을 저장소 밖에 백업했고, 반영 후 기존 변경의 SHA-256 일치를 확인했다. 위 커밋은 구현 SHA가 아닌 검수 기준 dev다. 최종 PR에서는 구현 커밋의 SHA로 갱신하고 PR 본문을 포함해 다시 검사한다.

재검수에서 미지원 입력의 단순 이동 링크가 실제 버튼 전환과 같은 이름으로 표시되는 문제를 발견했다. 이 링크는 시도 닫기 반응을 보내지 않아 제거했다. switch_to_buttons 전송 버튼 한 개만 제공하고, 가짜·실제 기준선 해석기의 화면 시험에서 중복 링크가 없는지 검증한다. 수정 후 Django 회귀 97개 중 94개 통과, MySQL 전용 3개 건너뜀(31.695초). 결과는 out/handoff/review-36a30cb-fixed.log에 있다. D-07-01 수신 및 가짜 렌더러 시험은 완료 범위에 포함된다. 구현 커밋과 증빙 SHA 갱신 후 --pr-body의 --complete 검사를 통과해야 Closes로 제출할 수 있다.
