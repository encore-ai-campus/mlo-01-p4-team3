## PM 결정 요청 초안

아래는 미확정 제안이다. 계약·태스크의 완료 조건을 이 기록만으로 변경하지 않는다.

### CPM 금액 정밀도와 환입 귀속일

청구 CPM 500밀리원의 노출 한 건은 정확히 0.5밀리원이다. 계약 4절은 캠페인별 나머지 이월을 요구하고, 5절은 serve 날짜를 원장 귀속일로 삼는다. 현재 구현은 다른 날짜의 나머지까지 합쳐 정수 금액을 확정하고, 환입 시점의 캠페인 나머지로 계산한 조정액을 원래 귀속일에 기록한다. 이 때문에 최초 확정 금액이 0이었던 날짜의 합계가 -1밀리원이 되는 사례가 나온다. 캠페인 전체 누적액과 나머지의 관계가 유지돼도 일별 비용·예산 소진율·대사 해석은 정해야 한다.

| 선택지 | PM·D·C가 합의해야 할 내용 |
|---|---|
| 캠페인 × 귀속일별 나머지 | 날짜 간 이월을 막을지와 하루 종료 시 소수 잔여액의 보존·절사·반올림 기준. 기존 캠페인 단위 계약 변경이 필요하다. |
| 캠페인 전체 나머지 유지 | 날짜 간 반올림 차액을 조정할 귀속일과 일별 음수 비용 허용 여부. |
| 원장 내부 정밀도 확대 | 1/1000밀리원까지 보존하고 정산·표시에 반올림할지. 정수 밀리원 DTO·이벤트·집계의 변경 범위. |

D가 C와 처리안을 마련하고 PM이 일별 비용의 의미·환입 귀속일을 확정한 뒤 기준 구현·MySQL 원장·silver/gold 대사에 같은 규칙을 반영하는 안이다. 나머지 키만 임의로 바꾸거나 현재 문제를 MySQL로 그대로 복제하지 않는다. 결정 후 날짜 경계·지연 확정·환입 순서·중복 환입 회귀 검증을 추가한다.

### 자체 검증 인계와 최종 공동 검증

D-06-02 조건 7은 C-08-02 실제 재판정 이벤트의 환입 동작을 요구한다. 반면 C-08-02는 D-06-02를 선행으로 적고 실제 Kafka·MySQL·Delta 환입 후 대사를 요구한다. 선행을 "이슈 전체 종료"로 해석하면 순환 대기가 생긴다.

제안 순서는 다음과 같다.

1. D가 실제 로컬 MySQL·Kafka와 계약에 맞는 시험용 `ad.rejudge`로 원장·발행·만료·환입 멱등성을 자체 검증한다.
2. D는 미완료 상태로 코드·스키마·실행 방법·검증 결과를 C에 인계한다. C의 착수 요건을 이 인계로 충족할 수 있는지 PM이 정한다.
3. C의 실제 silver 재판정 → Kafka → D 환입 → 재대사를 공동 실행한다. 중복 환입·대사 불일치를 확인한다.
4. 공동 검증 결과를 양쪽 증빙에 연결하고 공통 완료 정의까지 충족한 뒤 각 이슈를 종료한다.

PM이 승인하기 전까지 이 순서는 제안이며, 기존의 실제 공동 검증 요구를 삭제하거나 시험용 이벤트로 대체하지 않는다.
