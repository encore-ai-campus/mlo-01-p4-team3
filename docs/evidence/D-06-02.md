## 2026-11-08 ad-01 운영 실행 확인

- 인프라 인계 문서의 SSH 접속 정보로 ad-01에 접속했다. systemd 상태와 프로세스 인자, 시작 로그, 작업자 지표를 읽기 전용으로 확인했다.
- 광고 웹과 publish·expire·refund는 서로 다른 PID의 네 프로세스다. 세 작업자 모두 `active/running`, `enabled`였고 역할별 시작 로그와 지표 HTTP 200을 확인했다.
- 배포본의 작업자·환입·만료·아웃박스·MySQL 원장 및 저장소 소스 6개가 로컬 검증 기준과 SHA-256으로 일치했다. 배포본 커밋 SHA는 확인할 수 없었다. 환입 작업자는 `ad.rejudge`를 구독한 뒤 시작 로그를 남기는 코드로 실행 중이다.
- 프로세스의 누적 처리 지표는 발행 4건, 만료 해제 1건, 환입 0건이었다. 15:01 KST에 발행기와 환입 소비자에서 각각 Kafka SSL 연결 종료가 1회 기록됐다. 이후 발행 처리 로그가 확인됐다. 실제 재판정 이벤트 수신과 환입·대사는 조건 7에서 검증한다.

## 2026-11-09 C-08-02 환입 연동 확인

- PR #274가 포함된 dev `93360e1`을 반영했다. C는 격리 합성 실행에서 silver 무효 재판정 1건을 실제 `ad.rejudge`로 발행했고, D 소비자가 MySQL 원장에 -137284밀리원 환입 1행을 기록했다. 재대사에서 원장과 Delta의 순액은 각각 1208456밀리원이고 불일치 다섯 범주는 모두 0건이었다. [C 검증 기록](C-08-02.md)
- D는 ad-01의 환입 서비스 저널을 읽기 전용 조회했다. C 시험 시간대(11/8 22:30~23:00 KST)에 `ad_refunded`가 1건이고, 22:41:53 KST에 기록된 금액 -137284밀리원이 C 측정과 일치했다. 앞 절의 환입 0건은 이 시험 전에 조회한 값이다. 원과금 귀속일 보존과 중복 환입 차단은 앞선 MySQL 회귀 및 경합 시험으로 확인했다.
- PM #267에서 D-06-02 7번은 C-08-02 5번의 실제 재판정·환입·재대사를 함께 확인하는 조건이다. C-08-02 3번은 D-08-02 7번에서 제공할 실행 ID에 대해 별도 대사가 필요하다. C의 이번 실행은 D-06-02 7번 검증에 사용했고 C-08-02 3번은 대기 상태다.
