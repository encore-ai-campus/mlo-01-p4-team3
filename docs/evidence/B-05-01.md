# B-05-01 Django 골격·로그·계측

- 커밋: e845622757472ea1e2fd8c4c04aeaf4c1395b843
- 작성자(흐름): B
- 환경: Windows, Python 3.14.6. Django 6.1.2와 격리한 MySQL Community Server 8.4.11에서 연결 시험, Django 6.1.2와 메모리 SQLite 3.50.4에서 회귀 시험. 앞선 로컬 연결 시험은 Django 6.0.10과 MySQL 8.0.46에서 실행했다.

## 명령

```powershell
& out/handoff/venv-django-6.1.2/Scripts/python.exe -B server/manage.py test server.tests --settings=server.paldo_web.test_settings --verbosity=2 --noinput
& out/handoff/venv-django-6.1.2/Scripts/python.exe -B -X utf8 out/handoff/check_mysql_8411.py
./ops/inventory_host.ps1
python -B -m tools.check_evidence B-05-01 --complete
python -B -m tools.precheck --pr-body out/handoff/pr-draft.md
```

MySQL 8.4.11은 [Oracle Windows ZIP](https://cdn.mysql.com/archives/mysql-8.4/mysql-8.4.11-winx64.zip)을 별도 디렉터리에 풀고 새 데이터 디렉터리에서 실행했다. 시험 전용 DB와 `caching_sha2_password` 계정을 사용했다. PyMySQL 1.2.3의 인증에 필요한 `cryptography` 50.0.2는 검증 가상환경에 설치했다. `server.paldo_web.settings`와 Django 테스트 클라이언트로 `SELECT VERSION(), 1`, 정상 경로 세 곳, 격리 DB 종료 후 503을 확인했다. 병합 커밋의 `server/` 소스는 시험한 구현 커밋 `417760f`와 일치한다.

앞선 MySQL 확인에서는 로컬 `PALDO_AUTH_DB_*` 설정을 사용해 `server.paldo_web.settings`로 초기화한 Django 테스트 클라이언트에서 `/healthz`와 `/readyz`의 `SELECT 1` 및 `/metrics` 응답을 확인했다. 이번에 `SELECT VERSION()`으로 로컬 MySQL이 8.0.46임을 확인했다.
