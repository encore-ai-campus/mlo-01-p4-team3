- PM 결정(11/6, 원본 E_pm.md 조건 2 문구 변경 대기)
  - 스레드 수는 `min(GEN_SETTINGS["n_threads"], CPU 수)`로 하고, 첫 설정 표에 "GEN_SETTINGS 8 → 실제 N"으로 표시한다. 무료 코랩은 vCPU가 2개다.
  - 생성 설정은 ③에서 zip을 푼 직후 표로 표시한다. `GEN_SETTINGS`가 zip 안에 있어 ① 입력 칸에서는 읽을 수 없다.
  - ⑥의 질문은 화면에 표시만 하고, 반응 의도는 직접 고른다. 기획서 7.2대로 LLM은 사실 문장과 반응 의도만 받는다.
- PM 결정(11/7, 원본 E_pm.md 조건 6 문구 "무료 CPU" 변경 대기): 무료 CPU 런타임은 요청 1건이 약 30초(예시 3건 29,632~34,201 ms, 모두 15초 초과)라 200건이 목표 40분을 넘는다. 코랩 실행은 T4 GPU 런타임으로 하고 15초 기준은 그대로 둔다. 노트북은 CPU 런타임에서도 돈다(CPU 휠로 대체).
- PM 결정(11/7, 원본 조건 7 문구 변경 대기): 모델 파일과 zip을 따로 공유하지 않고 드라이브 폴더 하나(노트북, 모델, zip, `KANANA_LICENSE.txt`, `NOTICE.txt`, `NOTICE_ko.txt`)를 "링크가 있는 모든 사용자(뷰어)"로 공유하고, 제출물에는 폴더 링크를 적는다. Kanana 라이선스 3.1절 재배포 고지 때문이다(`docs/reports/llm_bench.md` 1절).
- 참고: llama.cpp는 스레드 수가 달라도 같은 시드에서 출력이 대체로 같다. 다만 부동소수점 합산 순서 때문에 보장되지는 않는다. 코랩 결과에서 E-07-07(8스레드)과 판정이 다른 사례가 보이면 그 수를 적는다. → 코랩 T4는 GPU 연산이라 같은 시드에서도 출력이 달랐다. 성공 93건(E-07-07 Windows 86건), 일관성 판정 일치 85 %(E-07-07 95 %). E-07-07 결과 JSON에는 사례별 판정이 없어 다른 사례 수는 세지 않았다.
