- WSGI 오류 시각에 시험 컬렉션의 Mongo 느린 작업 17건을 확인했다. 최대 작업 18,284ms, majority 쓰기 확인 대기 최대 18,211ms로 API/클라이언트의 5초 제한을 넘겼다. 웹 로그에도 약 5초 후 500 응답이 있다. 클라이언트의 상태 `0`은 실제 HTTP 상태 코드가 아니라 전송/응답 처리 실패다. 쿼리·주소·접속값을 제외한 기록은 `out/handoff/b0705-mongo-slow-summary.json`이다. 디스크·회선 등 더 아래 원인을 확정하거나 제품 오류가 없다고 단정하지 않는다.
- 정상 혼합 대비 광고 지연 p95 증가 -8.304ms, 광고 실패 -7.663ms였다. 세 혼합 시나리오 모두 광고 HTTP 1,790건이 200이고 비콘 연결 오류는 0이었다. 지연의 중계 지표는 timeout 10·busy 2·circuit_open 1,778, 실패는 error 9·circuit_open 1,781이다. 5회·30초 회로 규칙 자체의 판정은 기존 단위 시험과 구분한다.
- 첫 측정 실패를 보존하고 소스·설정·시간 제한·합격 기준을 바꾸지 않은 반복 측정으로 재현 여부를 확인한다. 대상 VM 결과로 확대 해석하지 않는다.

### 범위 밖 노출 비율 회귀 확인 (`e38d357`)

- 4,096바이트 이하 비콘의 `visible_ratio`가 `10**400`이면 기존 검증에서 `OverflowError`가 발생했다. 숫자를 실수로 변환하지 않고 0~1 범위를 직접 비교하도록 수정했다.
- 인증 웹소켓에서 해당 입력이 `bad_message`를 반환하고 광고 중계를 호출하지 않는지, 같은 연결에서 다음 정상 비콘에 `ack.relayed=true`를 반환하는지 확인했다. 웹소켓·중계 시험 10개가 통과했다.
- Django 서버 시험 90개 중 87개가 통과했다. SQLite에서 MySQL 전용 3개는 건너뛰었다.
- 비밀정보 검사에 잡힌 고정 시험 토큰 두 곳을 실행 시 생성하는 가짜 UUID로 바꿨다. 웹소켓·중계 시험 10개와 로컬 Daphne 시험을 다시 통과했다.
- PR 본문을 포함한 `precheck`에서 시험 701개와 구조·비밀정보·문서·증빙 검사가 통과했다. 로그는 `out/handoff/B-07-05-ratio-precheck.log`에 있다.
