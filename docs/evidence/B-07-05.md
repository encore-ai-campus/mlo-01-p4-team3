## 출력

### 범위 밖 노출 비율 회귀 확인 (`e38d357`)

- 4,096바이트 이하 비콘의 `visible_ratio`가 `10**400`이면 기존 검증에서 `OverflowError`가 발생했다. 숫자를 실수로 변환하지 않고 0~1 범위를 직접 비교하도록 수정했다.
- 인증 웹소켓에서 해당 입력이 `bad_message`를 반환하고 광고 중계를 호출하지 않는지, 같은 연결에서 다음 정상 비콘에 `ack.relayed=true`를 반환하는지 확인했다. 웹소켓·중계 시험 10개가 통과했다.
- Django 서버 시험 90개 중 87개가 통과했다. SQLite에서 MySQL 전용 3개는 건너뛰었다.
- 비밀정보 검사에 잡힌 고정 시험 토큰 두 곳을 실행 시 생성하는 가짜 UUID로 바꿨다. 웹소켓·중계 시험 10개와 로컬 Daphne 시험을 다시 통과했다.
- PR 본문을 포함한 `precheck`에서 시험 701개와 구조·비밀정보·문서·증빙 검사가 통과했다. 로그는 `out/handoff/B-07-05-ratio-precheck.log`에 있다.

### 제출 전 계약 재확인

- Django의 `server.tests.test_ws` 9개를 다시 통과했다. 인증·출처·메시지 제한, 폐기 사유 집계, 노출·클릭·랜딩 중계와 대체 응답을 확인했다.
- Node 클라이언트 시험과 로컬 Daphne 시험을 다시 통과했다. Daphne에서 HTTP 200, WS 101, 중계 성공, 폐기 집계 2건·1건, 세션 폐기 후 4401을 확인했다. 실제 광고 HTTP 제공자 연결·전달 헤더 검증은 B-08-03에서 이어 간다.

Django 회귀 89개 중 86개 통과, MySQL 전용 3개 건너뜀(34.809초). Node 클라이언트 시험과 실제 Daphne 연결 시험을 다시 통과했다. 사유별 폐기는 queue_full 2건·page_exit 1건이며, 인증 폐기 후 4401을 확인했다. 로컬 SQLite·가짜 광고 제공자 기준으로, VM 성능·실제 Mongo 부하 결과는 아니다. PR은 Refs로 준비하며 조건 1·4의 미검증과 D 리뷰를 남긴다.
