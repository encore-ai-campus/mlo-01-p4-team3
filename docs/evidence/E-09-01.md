# E-09-01 정식 사용자 테스트 운영
- 커밋: fd02936
- 작성자(흐름): E
- 환경: 운영 게임 웹(오전 후보 `46eeb1a`, 16:02 병합 후보 `38abc0d` 배포 뒤), 집계는 로컬 Windows 11 miniconda Python에서 읽기 전용 내보내기 파일로 했다. 운영 DB에 직접 붙지 않았다
- 상태: 확인 대기. 지표 표는 채웠고, 입장 분산 실시 여부·목표 인원 미달 원인·장애 구간 여부는 사용자 확인 뒤 채운다

정식 테스트는 11/10 13:00~18:00에 열었다. 18:00 클로즈를 스냅숏으로 보고, 11/11에 운영 Mongo·계정 DB를 읽기 전용으로 내보냈다(`server/infra/ut_export.py`, `ut-export-2`). 내보낸 파일은 원본 데이터라 저장소에 넣지 않고 NAS `5. 테스트 데이터/user_test/export_1110/`에 둔다(`games.json` sha256 앞 16자 `24721290eb658e2f`). 버전 태그 `v-usertest-1`은 만들지 않았다.

## 명령
```
python -m server.infra.ut_export games --out games.json
python -m server.infra.ut_export accounts --out accounts.json
python -m tools.ut_metrics metrics --games games.json --out metrics.json
```
마감·시작 시각은 도구 기본값(11/10 18:00 KST, 13:00 KST)이고 부하 판(`load_test`)은 기본으로 뺀다. 결과 JSON은 `tools/evidence_result.py`로 `docs/evidence/perf/E-09-01/ut_1110.json`에 옮겼다.

판 수를 버전별로 나눈 값

| 규칙 버전 | 시작 | 완주 | 18:00 뒤 중단 처리 | 18:00에 진행 중 |
|---|---|---|---|---|
| `rule-0.6.decision-1` | 8 | 2 | 3 | 1 |
| `rule-0.7.decision-1` | 14 | 8 | 0 | 2 |

해석
- 한 판 시간 중앙값은 10분 이하를 지켰다. 완주 10판 중 1판이 31분으로 길어 p90이 30.8분이다.
- 완주율이 낮은 주된 이유는 두 가지다. 18:00 전 중단 6판은 모두 같은 참가자가 새 판을 시작한 시각에 이전 판이 중단으로 끝난 경우다. 나머지 미완주 6판은 18:00 클로즈 때 끝나지 않은 판이다.
- 설문은 대부분 건너뛰었다(14/16). 자유 입력은 12묶음 중 10묶음이 후보를 누르지 않고 끝났다.
