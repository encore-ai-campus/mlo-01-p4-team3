### 검증 범위와 C 인계 재확인

- `tests/ads/test_http.py`는 실제 MySQL 캠페인·admin과 Django 테스트 클라이언트를 사용하되 `AdService`의 메모리 `BudgetBook`을 주입한다. 경매 CTR·서버 시계만 시나리오에 맞춰 고정한다. 전체 픽스처를 외부 TCP HTTP로 재생했다는 뜻은 아니다.
- `test_mysql_ledger`는 실제 InnoDB 원장에 원본 Budget·AdsReviewRegressions 계약을 재사용한다. `test_persistent_http`는 실제 구성의 MySQLLedger/MySQLAdStore·아웃박스 원자성·재생·pending·한국 귀속일을 검사한다. 도메인 직접 호출을 HTTP 재생으로 세지 않는다.
- 조건 8은 광고 API 수신 요건을 검사한다. 게임 웹 실제 HTTP 어댑터·브라우저 중계·장애 판정은 B-08-03 범위이며 이번 시험으로 통과 처리하지 않았다.
- 최신 dev의 C-06-03 증빙은 named channel `pj4` 실복제, 광고 호스트 TLS 설정·migration·실제 serve/impression/click→MySQL→Kafka, B 계정 호스트 TLS·migration을 기록한다. 이전 “광고 접속 미실행·복제 미완료” 정보로 판정하지 않았다. PJ3 전체 복구·자동 승격 증빙은 아니다.
- C-07-01은 공식 200판 Kafka→Delta bronze·silver·truth 조인과 driver/executor Python 3.14.4, C-07-02는 브로커·발행기 중지/재개 무손실, C-07-04는 HTTPS·wss·브라우저 검증을 기록한다. 이는 해당 증빙 검토 결과이며 이번 D 작업이 VM을 직접 다시 실측한 것은 아니다.
- 기준 dev에는 `docs/evidence/C-08-02.md`가 없고 D-06-02 증빙의 조건 7(실제 silver 재판정·Delta 대사)·8(ad-01 작업자 배포)는 미검증이다. 별도 D-06-02 후속 worktree의 문서도 read-only로 확인했으며 세 작업자 운영 확인이 남았다고 기록되어 있다. 그 폴더를 수정하지 않았다.
- 조건 2는 PR #263에서 메모리 기준 원장에 대한 검증으로 정정됐다. 실제 silver 재판정·Kafka 환입·Delta 대사와 운영 작업자 배포는 D-06-02·C-08-02의 별도 조건이며 이번 D-05-03 통과로 완료 처리하지 않는다. 보호 운영 인계 파일의 위치·접속 경로는 이 작업에 확인되지 않아 운영 상태를 추측하지 않았다.

### 조건 2의 11/8 PM 결정 반영

PR #263, 결정 커밋 `3eaea6e`, dev 병합 `1bb7405`의 `docs/tasks/D_ml_ads.md` 조건 2를 따른다. 예약·확정·해제는 HTTP로 재생하며 해제는 주입 시계를 이동한 뒤 serve 요청으로 확인한다. 환입과 대사는 HTTP로 만든 원장에 `BudgetBook.refund`·`reconcile`을 적용한다. 실제 소비자·Delta 통합은 D-06-02 7번·C-08-02에서 판정하며 유지관리 HTTP 엔드포인트는 만들지 않는다.

기존 대사 테스트는 `reconcile(case["ledger"], case["delta"])`로 고정 사전끼리 비교했다. 새 문구의 “HTTP로 만든 원장”을 검증하도록 각 원과금을 HTTP serve·click으로 생성하고 환입만 도메인 함수로 적용했다. 실제 charge_id는 픽스처 라벨에 대응시키되 원장 금액·확정 상태·행 수를 검사하고 원장 값으로 대사를 실행한다. `ledger_only`, `delta_only`, `duplicate`, `amount_mismatch`, `orphan_refund`가 모두 픽스처 기대값과 일치했다. 픽스처·기대값과 애플리케이션은 바꾸지 않았다.

### 지연 측정 조건

2026-11-08, 단일 Django 개발 WSGI 프로세스·임시 loopback 포트, 준비 20회 뒤 200회 순차 호출·filled 200회다. 전용 스키마의 기본 캠페인 4개를 사용하고 요청마다 새 ID·세션으로 호출했다. 최신 dev의 영속 MySQL 원장·serve 저장·아웃박스와 캠페인 조회·HTTP 왕복·JSON·로그를 포함한다. 이번 지연 재측정은 서비스·계약 테스트 종료 뒤 수행했고 전체 precheck와 겹치지 않았다. 같은 전용 스키마의 선행 벤치마크 예약 행은 보존했다. VM 간 네트워크·게임 웹 전체 중계·동시 부하 합격을 뜻하지 않는다.
