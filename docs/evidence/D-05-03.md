### 검증 범위
- 광고 테스트는 실제 Compose MySQL의 캠페인·소재·admin 계정을 사용하고 Django 테스트 클라이언트를 통해 HTTP 뷰·미들웨어를 실행했다.
- 경매는 픽스처에 고정된 CTR로 소재 점수만 주입하고 캠페인 조회·필터·경매·예약·응답은 실제 구현을 사용했다. 시간 의존 판정은 서버 시계만 고정했다. 클라이언트 발생 시각은 판정에 사용하지 않는다.
- 예산 경합은 HTTP serve 동시 요청 후 예산 합계를 확인했다. 클릭 동시 재전송도 확정이 한 번인지 확인했다. 이 검증은 단일 프로세스 메모리 BudgetBook에 대한 것이며 MySQL 원장 경합 테스트가 아니다.
- 미확인 serve의 최초 서버 수신 시각을 유지하므로 유예 재판정이 no_serve에서 expired로 바뀌지 않는 회귀 시험을 포함했다. 재판정은 반복 수신으로 실행했고 별도 소비자·스케줄러는 D-06-02 범위다.
- source=synthetic 캠페인·소재 접두어 격리, 타기팅·빈도 제한·load_test 무효, request_id 재전송·충돌, 삭제 지면 거부를 검증했다.
- 조건 8의 게임 웹 **실제 중계 구현·장애 시험**은 B-07-05·B-08-03 범위다. 여기서는 광고 서버가 받을 내부 API의 CSRF·Content-Type·Location·추적 ID 요건을 검증했다.
- 조건 2는 B-05-03 완료만으로 해소되지 않는다. 환입 소비자는 D-06-02, 실제 집계와의 대사는 C-08-02와 연결된다. 이후 계약·검증 범위를 확인해야 한다.
