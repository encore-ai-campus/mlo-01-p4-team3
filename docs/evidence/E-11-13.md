```powershell
python -B -m unittest tests.llm.test_npc_polish tests.contract.test_layers
python -B server/manage.py test server.tests --settings=server.paldo_web.test_settings --noinput
python -B <저장소 밖 실측 스크립트> http://127.0.0.1:<터널 포트> <저장소 밖 결과 파일>
```

## 출력

```text
tests.llm.test_npc_polish: 17 tests OK
server.tests.test_npc_lines: 20 tests OK
server.tests: Ran 563 tests, OK (skipped=14)
```

- 도메인 시험(`tests/llm/test_npc_polish.py`): 요청에는 원문·말투·종류·허용 이름만 들어가고, 씐 자 화자와 마을 사람 화자에게 같은 공개 입력을 주면 요청 바이트가 같다. 조립 함수는 문자열만 받고 판 진실 객체를 import하지 않는다(정적 검사). 거부 사례: 문장 추가, 역할어(창귀·범인), 대상 바꿈, 판단 뒤집기(의심 → 믿음, 변호 → 의심), 새 인물·장소, 이름 없는 원문에 이름 추가, 길이 초과, 새 명사.
- 서버 시험(`server/tests/test_npc_lines.py`): 모드 off면 회의 HTML이 기존과 같고 등록·호출이 없다, 화면 요청 때 멱등 등록(빠진 줄을 다음 요청이 메움), 첫 확정 1회만 고정(경합), 단계가 넘어가면 이전 단계 미고정 줄은 템플릿 고정, 대기 상한을 넘으면 `skipped`(마감 지난 대기 줄은 세지 않음), 판 삭제 때 작업 문서 삭제·늦은 완료가 되살리지 않음, 실시간 판정(마감 안 완료는 마감 뒤 폴링이어도 인정, 마감 넘은 대기 줄은 `timeout`·꺼내지 않음, 마감 뒤 완료 저장 거부, 임대가 끝난 작업 프로세스는 다시 잡힌 작업을 닫지 못함, 다른 판의 같은 작업 번호는 다른 작업), 실시간 > 다듬기 우선순위, 운영 설정 캐시 10초·읽기 실패 60초 넘으면 off.
- Chrome 1528×730: off에서는 회의 화면에 선조회 속성·Kanana 표기가 없고 템플릿 문장이다. polish에서는 좌측 하단 "Powered by Kanana"가 보이고, 대사창에 다듬은 문장("거 참, …")이 나온 뒤 고정된다. 새로고침하면 고정된 문장이 바로 보이고 기록 패널은 템플릿 원문 그대로다. 콘솔 오류 없음.

## 판정

- 구현·시험·화면은 통과. 운영 켜기(표본 승인)는 남았다.
- 읽기 경로 다듬은 비율은 생성 서버 하나(CPU, 줄당 약 1.6초)와 작업 프로세스 1개의 처리량에 묶인다. 판 1개를 천천히 읽으면 절반 이상이 다듬은 문장이지만, 동시 판이 늘거나 빨리 넘기면 거의 템플릿이다. 게임 진행은 영향을 받지 않는다.
- 실시간 답은 기본 꺼짐이고, 켜면 마감 3000 ms 안에 끝난 답만 보인다. 복기 생성과 겹치면 템플릿이 자주 보인다.
