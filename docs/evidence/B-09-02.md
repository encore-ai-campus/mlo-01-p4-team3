# B-09-02 BERT 해석기 연결 사전 준비

- 커밋: 0f1e8e2a44aeffb2a38b44f9213bdeb9d5135b8d
- 작성자(흐름): B
- 환경: Windows, Python3.14.6·Django6.1.2, 실제 기준선·녹화 엔진, 임시 SQLite·격리 Mongo8.0.34 단일 노드 Replica Set·Caddy2.10.2·Daphne 2프로세스
- 상태: 실패

SHA는 최종 검증한 시험 코드·설명·관련 문서의 커밋이다. 최종 회귀검사 기준 dev는 fcf8752다. 초기 HTTP 측정과 표준 결과 JSON의 기준은 d106024이며 당시 미커밋 B-09-02 시험 코드에서 확인했다. 실제 BERT·실제 엔진 혼합·동급 VM 검증과 RunPod 준비는 미수행이다. 태스크 전체 완료나 BERT 운영 전환을 주장하지 않는다. 사용자 승인에 따라 PR은 Refs #37로 연결하며 이슈를 닫지 않는다. 디자인 작업 worktree·운영 조립·계약은 수정하지 않았다.

## 최신 dev 반영 후 최종 검증

11/9 원격 dev fcf8752를 확인하고 기존 작업을 백업한 뒤 fast-forward로 반영했다. 추가된 PR #321·#323은 모델 재현 검사 도구와 회의·밤 배경 에셋이며 B-09-02 태스크·API 계약 변경은 없다. 구조 계약에는 모델 재현 도구 경로가 추가됐다.

`measure_game`의 설명을 초당 한 게임 진행 주기와 선택적 해석·취소 추가 요청으로 바로잡았다. 실행 로직은 바꾸지 않았다. 서버 라우팅·설계 문서의 요청량 설명과 일치한다.

- Django 회귀: 95건 중 94건 통과·1건 건너뜀, 15.363초. 실제 엔진 Mongo 환경 변수 미설정에 따른 건너뜀은 유지된다. 로그: `out/handoff/b0902-final-regression.log`.
- 다중 프로세스/CLI 회귀: 22건 중 18건 통과·4건 건너뜀, 12.719초. Redis 패키지·접속 환경 미준비에 따른 건너뜀은 유지된다. 로그: `out/handoff/b0902-final-scaling.log`.
- 사전검사: `precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 382개(선택: tests/contract 2개·tests/engine 1개·tests/infra 전체·tests/llm 1개·tests/ops 2개·tests/tools 11개(tests/assets는 --with-assets로)), base fcf8752, 16초)`. 로그: `out/handoff/b0902-latest-precheck.log`. 전체 저장소·에셋 전수 검사가 아니라 이번 변경과 연결된 검사다.
- 아래 HTTP·Mongo 수치는 초기 측정을 보존한 것이다. 이번 설명 수정 후 성능 시험을 다시 실행한 수치로 표기하지 않는다.

## 출력

- 초기 관련 회귀56건·13.190초 통과, 건너뜀0, Django system check 문제0. 가짜→실제 기준선의 기존 설정 한 줄 교체에서 같은 녹화 판의 해석·취소·명령·종료를 확인했다. 각 해석·취소는 같은 상태 버전을 반환하고 저장된 게임 버전도 변하지 않았다. 오류·취소 누락·잘못된 간격을 정상 부하로 세지 않는 시험을 포함한다. 이후 팩토리 형식 차단 시험도 확대 회귀에 포함했다.
- 최종 확대 회귀는 Django95건·13.059초(실행94건 통과·실제 엔진 Mongo 환경 변수 미설정1건 건너뜀), 다중 프로세스/CLI 회귀22건·11.054초(실행18건 통과·Redis 패키지/접속 환경 미준비4건 건너뜀)다. 기준선 단계 필터·서버 조립·기존 성능 판정·시험 계측까지 포함한다. 실제 Mongo 사전 시험은 아래 별도 결과이며 건너뛴 실제 엔진/Redis 시험을 대신한 것으로 표기하지 않는다. 로그는 `out/handoff/b0902-regression.log`·`b0902-web-scaling.log`다.
- 최종 사전검사: `precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 382개(선택: tests/contract 2개·tests/engine 1개·tests/infra 전체·tests/llm 1개·tests/ops 2개·tests/tools 11개(tests/assets는 --with-assets로)), base d106024, 27초)`. 원자료는 `out/handoff/b0902-precheck-final.log`다. 위 Django 회귀와 별도로 실행했으며 전체 저장소·전체 에셋 검사로 확대하지 않는다.
- 아래 HTTP 표는 각 경우2명·18초인 기능 사전 시험이다. 한 게임 진행 주기/초에 해석·취소를 추가하므로 총 요청량이 다르며 성능 개선 비교로 해석하지 않는다. 순수 parse 표본은 요청에 연결된 숫자 계측 헤더에서 수집했다.

| 실제 기준선 혼합 | 84 | 24/24 | 2 | 0/0 | 203.290ms | 274.979ms | 2.414ms |

## 계약·예상 동작 대조

- API4절: 해석은 확인용 후보만 만들고 취소는 소비 없이 닫는다. 부하는 confirm/edit를 자동 선택하지 않는다. 시작·명령의 녹화 버전·멱등 경로는 유지한다.
- B-09-02: 기존 INTENT_PARSER_FACTORY 교체 지점을 시험에서도 사용하고 기본 운영 기준선은 유지한다. 시험용 해석기 경로는 CLI로만 선택하며 BERT 클래스·아티팩트 형식은 임의 결정하지 않았다.
- 전체 API p95에는 오류를 포함한 해석·취소 HTTP 표본도 넣는다. 순수 parse와 HTTP 지연을 구분한다. 이번 수치로 실제 BERT·30명·3분·사용자 테스트 서버 성능을 판정하지 않는다.
- 이번 실행 환경에는 sklearn이 있으나 torch·transformers는 없다. 실제 BERT 설치 실패로 판정한 것은 아니며 공유 가상환경을 변경하지 않았다.

## 인수 후 남은 절차

1. D-09-02 4번에서 IntentParser 공개 팩토리·모델/토크나이저 아티팩트·해시·의존 버전·최소 입력/기대 후보·모델 버전을 받는다. 비밀값은 저장소에 넣지 않는다. D-09-02 전체 종료가 아니라 이 인수 항목의 준비 여부를 확인한다.
2. D-08-01 6번 실제 엔진·적격 모델의 다중 프로세스 부하 옵션을 인수한다. 이번 공개 화면 기반 probe_intent를 같은 부하에 연결하고 실제 판의 합법 명령 생성은 D 쪽과 맞춘다. 녹화 부하를 실제 엔진으로 표기하지 않는다.
3. 별도 시험 환경에서 같은 프로세스 BERT 설치·로드·B-07-01 회귀를 실행한다. 사용자 테스트 서버 또는 동급 VM의 웹2프로세스·30명·3분 이상으로 전체 API p95 1초 이하와 실제 parse 지연을 측정한다. 미측정·기준 초과 시 기준선을 유지하며 설치 실패/기준 초과는 수치와 별도 프로세스안을 PM에 보고한다.
4. RunPod는 본인 계정 결제·자동 충전 끔·알림·B 한도$5를 확인하고 Restricted 키를 4th_private로만 E에게 전달한다. 채팅·저장소에 키를 쓰지 않는다. 완료 한 줄만 증빙에 남기며 실험 후 폐기·Storage0개·요금 전달도 확인한다. 이번에 결제·키 생성·외부 전달은 하지 않았다.
