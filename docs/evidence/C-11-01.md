# C-11-01 실제 스택 장애 복구 시험

- 커밋: 38abc0d42eea8897749b60fb084c341ed966193b
- 작성자(흐름): C
- 환경: 11/11 실제 Kafka 3노드·Mongo 3노드·광고 서버·Spark/Delta, 운영 소스와 동일 조립의 격리 HTTP 포트, 합성 계정 및 load_test 이벤트
- 상태: 부분 완료. MySQL 승격 및 광고 DB 지연·10배 광고 폭주·노트북 자원 압박 시험은 미실행이다.

## 명령

```sh
# 정지 대상 호스트에서 자동 복구를 먼저 준비한다.
sudo systemd-run --unit="$RECOVERY_UNIT" --on-active=90s /bin/systemctl start "$TARGET_UNIT"
sudo systemctl stop "$TARGET_UNIT"
# Spark 강제 종료 시험은 정상 배치 commit 확인 후 수행했다.
sudo systemctl kill --kill-whom=all --signal=SIGKILL paldo-bronze
# 실제 API로 합성 판을 진행한 뒤 명시적으로 재기동한다.
sudo systemctl start "$TARGET_UNIT"
sudo systemctl stop "$RECOVERY_TIMER"
python -m tools.reconcile_game_events --mongo "$PRIVATE_MONGO_METADATA" --published "$PRIVATE_KAFKA_METADATA" --bronze "$PRIVATE_BRONZE_METADATA" --out "$PRIVATE_RESULT"
```

## 출력

각 장애 전에 합성 판을 시작하고, 장애 동안 실제 HTTP 게임 명령으로 완주했다. 판당 15회씩 총 60회에서 HTTP 오류는 0건이었다. 입력·세션·DB는 실제 스택을 사용했고 수집 이벤트에는 load_test=true를 확인했다. 웹 전용 포트는 시험 뒤 종료했고 합성 계정 4개를 비활성화했다. 인증 세션 4개와 복사 인증 파일 2개를 제거했다.

| 장애 | 주입과 복구 | 정지 전 시각~active 확인 | API 요청/오류 | 결과 |
|---|---|---|---|---|
| Kafka 한 브로커 | 3브로커·18파티션 ISR 3 확인 후 한 노드 정지·복구 | 07:51:09~07:51:30 KST, 21초 | 15/0 | 완주 |
| Mongo Primary | Primary 식별 후 정지, 다른 노드에서 판 진행, 원래 노드 재합류 | 07:55:51~07:56:25 KST, 34초 | 15/0 | 완주 |
| 광고 서버 | PJ4 광고 unit 정지 후 게임 진행·광고 복구 | 07:59:50~08:00:09 KST, 19초 | 15/0 | 완주 |
| Spark | 공식 Bronze 강제 종료 후 자동 재시작, 같은 checkpoint 재개 | 08:07:40~08:08:01 KST, 21초 | 15/0 | 완주·재적재 대조 통과 |

위 시간은 운영자 기록의 정지 전 시각부터 active 확인까지 측정 구간이며, 별도 장애 감지 시간과 자동 재선출 소요만을 분리 측정한 값은 아니다. 복구 시간 합격선은 P-13 인계를 따른다.

Mongo에는 네 판이 각각 95개의 이벤트를 가졌고 미발행은 0건이었다. Kafka 380건을 전량 회수하고 공식 Delta와 대조해 고유 수·연속 seq·본문 hash가 일치했다. Delta 누락·원본 중복·hash 불일치는 모두 0이다.

사전 점검 중 공식 Bronze가 `human_identity_missing`으로 재시작을 반복함을 발견했다. 일반 판의 `session_id=null`을 거부한 오래된 조건을 [수정 PR #371](https://github.com/encore-ai-campus/mlo-01-p4-team3/pull/371)로 복구했다. 같은 checkpoint에서 batch 135·136의 commit이 새로 완료된 뒤 강제 종료 시험을 진행했다.

MySQL Replica의 `pj4` 채널은 IO/SQL Yes, 지연 0이지만 공유 PJ3 기본 채널은 IO No·오류 13114였다. 전체 인스턴스를 승격하기 전에 공유 채널 복구·fencing·되돌림 계획 검증이 필요해 시험하지 않았다. P-31로 운영 LLM 서버는 없으며 이 경로는 템플릿 응답이다. 실제 LLM 서버 정지 수치로 기입하지 않는다.
