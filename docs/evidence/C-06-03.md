# C-06-03 PJ4 복제 복구·웹/광고 TLS 실배포
- 커밋: 597e5974538748c1e111c83e427586fb848e35db
- 작성자(흐름): C
- 환경: MySQL 8.4.11, Django 6.1.2, Python 3.14.4, 기존 Ubuntu VM. 실측일 2026-11-08.

복구 범위는 `paldo_ads`·`paldo_auth`의 **named channel `pj4`**다. 기존 PJ3 기본 GTID 채널의 만료된 binlog 문제·기존 데이터는 보존했다. 전체 PJ3 복구나 자동 승격 완료를 뜻하지 않는다. 광고 원장·예산·판정 상태는 D-06-02의 MySQLLedger/MySQLAdStore를 사용한다. 광고 silver·재판정·환입 대사는 후속 C-08-02 범위다. B→D 실제 HTTP 광고 어댑터의 미구현은 별도 B 작업이다.

## 명령

```sh
python -m ops.mysql.pj4_channel snapshot --directory "$PRIVATE_SNAPSHOT"
python -m ops.mysql.pj4_channel configure --directory "$PRIVATE_SNAPSHOT"
python -m ops.mysql.service_runtime --profile "$PRIVATE_RUNTIME" migrate-web
python -m ops.mysql.service_runtime --profile "$PRIVATE_RUNTIME" migrate-ads
python -m ops.mysql.replication_check --role primary --marker c06_pj4_post_restart_20261108
python -m ops.mysql.replication_check --role replica --channel pj4 --marker c06_pj4_post_restart_20261108
```

실행 주소·보호 파일 경로는 저장소 밖 인계 기록에 있다. 아래 명령의 `$PRIVATE_*`는 그 경로이며 자격정보를 CLI로 전달하지 않는다.

## 출력

```json
{"io_running": 1, "sql_running": 1, "lag_seconds": 0, "last_io_errno": 0, "probe_replicated": 1, "marker": "c06_pj4_post_restart_20261108"}
```
