```sh

python -m ops.mysql.verify --secrets-dir "$PRIVATE_MYSQL_DIR"
python -m ops.mysql.replication_check --role primary --marker c06_20261107_handoff
python -m ops.mysql.replication_check --role replica --marker c06_20261107_handoff
```

## 로그

복제 IO 중단 원인은 Primary 연결 실패였다. 기존 GTID/TLS 설정을 유지한 채 `START REPLICA IO_THREAD`로 재개하자 연결은 됐지만, Primary가 필요한 binlog를 이미 purged해 수신이 중단됐다. 원문은 source fatal 1236을 포함했고 최종 상태의 Last_IO_Errno는 위 출력과 같다. 지연 NULL을 0으로 치환하지 않았다. 신규 probe도 Replica에 없어서 검사 종료 코드가 실패로 반환됐다.

초기 로컬 검증은 기존 LAN-only bind로 loopback 연결이 거절됐다. Primary의 정확한 자기 주소를 검증 출발지로 제한 허용하고 TLS VERIFY_IDENTITY를 사용한 뒤 양방향 거부가 확인됐다. 접속 정보·주소·계정·암호는 증빙에 싣지 않는다.

## 남은 일

Replica의 기존 데이터를 대체하기 전에 양쪽 백업·자체 거래 비교와 복원 범위 검토가 필요하다. 구체적인 재구성·롤백 순서는 ops/mysql/README.md에 적었다. GTID 건너뛰기·RESET·데이터 덮어쓰기는 실행하지 않았다. Replica 검증 성공과 B/D 호스트별 연결·마이그레이션 인계가 끝날 때까지 #51을 닫지 않는다. 현재 Primary 사용 시 복제 보호가 없는 상태임을 인계한다.
