# C-08-01 Prometheus·Grafana·경보

- 커밋: 32fbf56
- 작성자(흐름): C
- 환경: PJ4 테스트 VM의 Prometheus·Grafana, TLS 검증을 켠 Chrome
- 상태: VM 20대와 운영 웹 두 프로세스의 지표를 모두 수집한다.

대시보드 6종과 경보 6개를 구성했다. 합성 검증 실행 r6에서 활성 판 30개를 유지하는 동안 6개 화면을 모두 캡처했다. 전체 30판이 끝났고 HTTP 303건 중 오류 0건이었다. 부하 도구의 HTTP 동시 실행 상한은 12였다. 요청 대기 시간을 포함한 클라이언트 p95는 4048.847ms이고, 서버 미들웨어 실측 p95는 1152.402ms로 1초 기준을 초과했다.

이 캡처 뒤 광고 패널을 P-25 집계 정의에 맞췄다. 캠페인·귀속일 소진율과 전체·지면별 fill, 노출·클릭 무효율은 source 및 잠정·확정 라벨을 유지한다. 캡처의 광고 화면은 이 변경 전 버전이다. 11/9 변경 후 운영 Prometheus에서 fill, 소진율, 노출·클릭 무효율, 대사 지표의 잠정·확정 두 라벨을 확인했고, Grafana 프로비저닝 API에서 새 쿼리를 전부 대조했다. 운영 런타임 LLM은 P-31 결정에 따라 사용하지 않아 해당 패널에 실측값이 없다.

11/9 두 웹 프로세스용 수집 설정을 별도로 준비했다. 운영 8000의 기본 loopback Host는 400, 공개 출처와 일치하는 Host를 넣으면 200, 기존 relay의 `/web`도 200이었다. 두 경로의 고정 Host와 Prometheus `web-1`·`web-2` 설정을 검증했다(`promtool check config` 통과). 8002 기동 후 두 대상을 동시에 긁는 실제 검증은 C-08-04 전환 때 수행한다.

11/10 운영 Prometheus에서 `paldo-nodes` 20대가 모두 `up`이고 MySQL03은 PJ3 VM 점검 대상에서도 `up`이었다. 현재 PJ4 운영 서비스 지표와 경보 6개를 확인했다. 기존 운영 웹 대상은 `up`이며 두 번째 운영 웹 대상은 아직 등록되지 않았다. 별도 시험용 `paldo-web-validation`은 `down`으로 확인했다.

11/10 웹 후보 `46eeb1a`가 두 포트에서 기동한 뒤 relay에 `/web-2`를 추가했다. 두 포트에서 공개 출처의 고정 Host로 `/metrics`가 각각 200을 반환했다. `promtool check config` 통과 후 Prometheus를 reload했고 `up{job=~"paldo-web(-2)?"}`에서 `web-1=1`, `web-2=1`을 확인했다. 기존 시험용 scrape는 운영 웹의 두 대상과 별개다.

## 명령

```sh
promtool check rules ops/prometheus/alerts.yml

```
