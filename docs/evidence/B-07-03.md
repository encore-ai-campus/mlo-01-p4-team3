## 출력

지면 HTTP 시험 5개 통과(0.825초). 실제 `configure_ad_gateway`로 병합된 중계에 연결해 세 지면의 링크가 같은 출처 클릭·랜딩으로 이어짐을 확인했다. 로그: `out/handoff/ad-targeted-latest.log`.

같은 serve의 조각 재삽입 회귀는 수정 전 실패(2건), 수정 후 통과(1건)했다. 새 serve는 정상 전송된다. 50% 미만·연속 999ms·탭 숨김·이미지 미로드에서 전송 0건, 조건 충족 뒤 1건이며 클라이언트 지연 준비·htmx 재관찰을 확인했다. 로그: `out/handoff/ad-serve-before.log`, `out/handoff/adslots-js-latest.log`.

전체 MySQL 시험 첫 실행은 기존 계정 시험 1건이 무작위 ID·비밀번호 유사성 검증에 걸렸다. 같은 생성 방식의 검증 2,000회에서 2회를 재현해 원인을 확인했고, ID의 문자 집합을 비밀번호의 16진 문자와 분리했다. 운영 비밀번호 검증은 변경하지 않았다. 빈 지면 보완까지 반영한 최종 격리 MySQL 전체 서버 127개가 건너뜀 없이 통과했다(52.799초). Django 계정·세션은 실제 MySQL이며 게임·보조 저장소는 대역이다. 임시 DB·프로세스는 정리됐고 기존 DB·`.env`는 변경하지 않았다. 로그: `out/handoff/empty-mysql-run.log`, `out/handoff/adslots-mysql-8411-tests.log`.

저장소 최종 사전 검사도 통과했다. `precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 701개, base 1c17a2d, 82초)`. 로그: `out/handoff/empty-precheck-final.log`. 커밋 전 작업본 검사이며 PR 생성 전 실제 구현 SHA와 본문 완료 검사를 갱신한다.

### 최종 검수의 빈 지면 보완

광고가 없는 응답에 안내문을 남기던 템플릿·시험을 ports.md 5절의 빈 지면 요구에 맞췄다. 수정 전 빈 응답 회귀 2개가 실패했고 수정 후 지면 HTTP 5개가 통과했다(0.595초). 정상 소재는 광고 표시·링크·토큰을 유지하고, `empty`, `error`, `timeout`, `busy`, `circuit_open`은 200·공백을 제외한 본문 0바이트다. 각 요청의 결과 카운터가 정확히 1 증가하는지도 확인했다. 외부 이미지 거부·게이트웨이 미조립도 빈 응답이다. 로그: `out/handoff/empty-before.log`·`empty-after.log`. JavaScript 회귀도 통과했다.

Browser plugin not available. 기존 Playwright·Chrome에서 가짜 제공자에 정상 → 미제공 → 예외를 순서대로 주입했다. 실제 htmx GET·innerHTML 교체로 기존 광고·안내·링크·토큰이 제거됐고 빈 지면의 추가 비콘은 0건이었다. 정상 비콘 ack는 1건이었다. 1280×900·390×844에서 가로 넘침·페이지/콘솔 오류 0건. 스크립트·로그: `out/handoff/preview_empty.py`, `empty-browser.cjs`, `empty-browser.log`. 캡처는 별도 백업 폴더의 `B-07-03-empty-desktop.png`·`B-07-03-error-mobile.png`다.

스테이징된 전체 파일 검사에서 기존 JavaScript 시험의 고정 `adToken` 문자열을 비밀값 규칙이 탐지했다. 시험 토큰을 실행 시 UUID로 생성하도록 바꾸고 JavaScript 회귀·최종 사전 검사 701개를 통과했다. 검사 규칙과 운영 비콘 코드는 변경하지 않았다. 검증용 Daphne와 임시 MySQL은 종료·정리했다.

## 브라우저 검증

Browser plugin not available. 기존 Playwright·Chrome과 임시 SQLite·Daphne 미리보기에서 실제 이미지·IntersectionObserver·웹소켓을 사용했다. 흐름은 로그인 → 로비 광고 → 노출 ack → 클릭·가상 랜딩 → 녹화 판 종료 → 결과 광고이며 `review_side`는 시험 페이지에 조각을 삽입해 확인한다(복기 화면 구현이 아님). 실제 광고 서버·과금·Kafka 수신을 입증하지 않는다.

Chrome 1280×900·390×844에서 로비·결과·복기 조각별 `ack.relayed=true` 총 3건, 같은 serve 추가 전송 0건, 외부 출처 요청 0건, 페이지·콘솔 오류 0건을 확인했다. 모바일 가로 넘침이 없었다. 처음 로비의 아이콘 404는 manifest 아이콘을 연결한 뒤 사라졌다. 스크립트·출력: `out/handoff/adslots-browser-latest.cjs`·`out/handoff/adslots-browser-latest.log`. 별도 로컬 백업 폴더의 `B-07-03-lobby-desktop.png`·`B-07-03-lobby-mobile.png`·`B-07-03-result-mobile.png`를 직접 확인했다. 새 브라우저 의존성은 설치하지 않았다.
