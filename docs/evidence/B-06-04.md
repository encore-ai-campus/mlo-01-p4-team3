## 출력

### 최신 dev 재검증 (11/8)

- PR #247의 dev 병합 `09e26a7`에서 전용 worktree를 분리했다. 계정·동의·광고 식별자 계약 변경은 없고 운영 코드 수정이 필요한 유출은 발견하지 않았다.
- `test_credentials_absent_from_logs_outbox_and_metrics`를 확장했다. 초대 코드 오답·가입·로그아웃·대문자 ID 로그인·녹화 판 완주·중복 가입·오답·잠금·없는 ID·비밀번호 초기화 거부까지 실행한다. 세 광고 지면과 판 종료 지면의 총 4개 `AdRequest`에서 로그인 ID와 인증 입력을 검색해 0건임을 검사한다.
- 광고 DTO는 계약의 여섯 필드만 가지며 같은 로그인 세션의 별도 UUID 가명만 사용한다. 계정 가명·로그인 세션 키·판 ID·쿼리의 위조 식별자는 전달하지 않는다. 각 광고 호출의 `request_id`는 웹 응답 헤더와 일치한다. 로그아웃·잠금 뒤 비로그인 광고 요청은 401이며 광고 호출 수가 증가하지 않는다.
- 포트 경계 시험 1개 통과(2.794초). 파일 로그·아웃박스·`/metrics`·광고 DTO를 같은 계정 시나리오에서 검사한다. 광고 서버 수신 본문·HTTP 헤더 검증은 아니며 테스트 대역은 `server/tests` 안에서만 조립한다. 로그 `out/handoff/b0604-privacy-port.log`.
- 실제 Mongo 8개 통과(3.814초): 광고 가명의 재접속 보존·동시 발급 20건의 동일 UUID·참가자별 삭제, 실제 엔진 판의 소유권·동의·재접속·저장 응답 유실 복구를 확인했다. 계정 DB는 이 시험에서 임시 SQLite다. 로그 `out/handoff/b0604-mongo.log`.
- 격리 MySQL 8.4.11 전체 서버 회귀 156개 통과(50.569초, 건너뜀 없음). 동시 가입 6건·동시 로그인 실패 잠금·세션 폐기·CSRF·소유권과 확장한 광고 포트 비노출 검사를 포함한다. 로그 `out/handoff/adslots-mysql-8411-tests.log`·`pr-mysql-run.log`. `makemigrations --check --dry-run`은 `No changes detected`였다.
- 위 MySQL 시험의 Django `default`는 임시 스키마 `test_paldo_auth`였으며 `accounts_accountprofile`, `accounts_loginlock`, `auth_user`, `django_admin_log`, `django_session`을 그 스키마에서 확인했다. 이전 운영 설정용 `paldo_auth` 시험과 구분하며 VM 접속 시험은 아니다. 임시 MySQL 프로세스·datadir는 시험 뒤 정리했다.
- 결과 JSON은 `docs/evidence/perf/B-06-04/privacy_port.json`이다. JSON의 commit은 기준 dev를 뜻하며 위 미커밋 시험 보강을 포함해 실행했다. 광고 포트 요청 4건·인증 입력 검출 0건을 실제 HTTP 요청 건수와 혼동하지 않는다. 제출 전 구현 커밋이 생기면 해당 SHA로 증빙을 연결한다.
- 서버·웹 라우팅·디자인, 계정 시험 안내·웹 모듈·트러블 기록을 갱신했다. 이전 마이그레이션과 DB 권한 시험 기록은 보존한다. PR은 `Refs #26`으로 준비하며 조건 5의 실제 HTTP 수신 검증 전에는 이슈를 닫지 않는다.
- 최종 검사: `precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 778개, base 09e26a7, 173초)`. 로그 `out/handoff/b0604-final-precheck.log`. 실제 HTTP 미검증이 남으므로 증빙 `--complete` 통과를 주장하지 않는다.
