# E-07-05 원한 단서와 결말 초안
- 커밋: 71b7c1996c59be4e94c1aaf3ae00eca49ff8e3fb
- 작성자(흐름): E
- 환경: 로컬 Windows 11, Python 3.14.6(표준 라이브러리 + `engine` 패키지), 작업 트리 `paldo-E-07-05`(브랜치 `task/E-07-05`, `origin/dev` dd200cc에서 땀, 콘텐츠 커밋 64118ea 뒤 `origin/dev` 36a30cb 병합 71b7c19)
- 원한 단서: `clue_id`·`part`·`unlock`·`hypothesis_id`는 그대로 두고 `text_ko` 4개만 다듬었다. 신원 단서가 2개(`clue_famine`·`clue_valley`)라 둘 중 하나와 죽음·대상만 모아도 한풀이가 열리므로(domain.md 9절), 두 신원 단서가 각자 생전 신원(떠돌이 일꾼 삼돌)을 밝히게 했다. 대상 단서는 원한의 대상(김 훈장)을 이름으로 가리킨다.
- 대상 단서 ID 변경: `clue_tiger` → `clue_gate`(11/7 사용자 결정, 문장이 범 이야기가 아니라 사립문 내용이라서). 계약(content.md 1절, domain.md 9절)은 `clue_id`를 버전이 바뀌어도 유지하라고 한다. 운영 판이 아직 없어 `clue_id`로 쌓인 판 밖 진척이 없으므로 이번 한 번 바꾸고, `content_version`은 `content-1.0` 그대로 둔다. 비밀 `drinking`의 `grudge_clue_id`도 같이 바꿨다. 공용 픽스처 `fixtures/content_min/bundle.json`·`tools/build_fixtures.py`의 `clue_tiger`는 문장이 실제로 호랑이 내용이라 그대로 둔다. 실제 콘텐츠를 읽는 다른 코드에 `clue_tiger` 하드코딩 0건(`git grep`, 작업 트리와 `origin/dev` 36a30cb 모두).
- 결말 문안: 새 데이터 파일 `content/endings_v1.json`(PM 결정: 엔진 미사용, 게임 웹·복기가 읽음). 계약 content.md 1절에 `Ending` 행 추가.
- 결정(11/7 사용자, PM 세션 전달): 질문 1 진 판의 결말 연출은 A안. 결말마다 문안 하나를 두고 첫 줄을 "몇 번을 되풀이했든, 그 며칠이 마침내 끊기는 날 …"(되풀이 전체의 맺음말)로 둔다. 질문 2 원한의 대상이 그 판에 없을 때도 A안. 김 훈장을 고정 출연시키지 않고 한풀이 4번째 줄을 그대로 둔다. 결말은 되풀이가 끝난 뒤의 장면이라 그 판에서 누가 사라졌든 마을 사람이 모두 있다.
- 원본과 다른 점: 결과 JSON 지표는 `write_result`가 숫자 값만 받으므로 지시문의 `clues_by_part`·`lines_per_ending`을 `clues_identity`·`clues_death`·`clues_target`·`lines_exorcism`·`lines_haewon_h1`로 나눴다.
