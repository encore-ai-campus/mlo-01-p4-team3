# C-08-02 광고 집계·실제 환입 재대사
- 커밋: a0b677a6d3c3f77ded798894409411a73e46cbb8
- 작성자(흐름): C
- 환경: 2026-11-08 실제 PJ4 VM, Python 3.14.4.
- 상태: 부분 완료. 아래 미완료 조건을 유지하고 Refs PR로 제출한다.

C 자체 격리 합성 실행을 실제 광고 HTTP·MySQL·Kafka·Spark·Garage로 검증했다. 요청 40개에서 실제 HTTP 96건(200/204/302), 오류 0이다. 공식 원본 104개 ID/hash가 모두 일치했고 같은 원본 104개를 재발행해도 고유 104개다. missing serve는 별도 validation Delta 복사본의 합성 양수 과금 한 건에만 주입했고 공식 bronze는 유지했다. 재판정 1건이 실제 Kafka ACK를 받고 D 환입 소비자가 실제 MySQL에 -137284mw를 1회 기록했다. serve 복원·실제 ad.rejudge 포함 재집계 후 원장/Delta 1208456mw, 다섯 범주 모두 0이다.

원본 → 공식 bronze 104 → 재판정 포함 validation bronze 105 → silver(impression/click) 64 → gold 그룹 6·학습 그룹 3이다. 이 행 수는 서로 다른 단위라 동일 수를 요구하지 않는다. 비용 합계는 최초 1345740mw, 환입 후 1208456mw로 원장과 같았다. 최종 silver valid 38/invalid 26/pending 0, gold 유효 노출 23·클릭 15다.

잠정·확정은 별도 Delta 경로에 저장했다. 위 cutoff는 합성 검증의 **명시적 논리 미래 시각**이며 실제 다음 날 마감이 지났다는 뜻이 아니다. 실제 write/read는 11/8이다. 확정 후 정정 정책은 원 귀속일 수정·Delta 이력/학습 버전 보존을 제안하며 PM 승인 없는 final 변경을 거절한다. 최종 가드가 있는 동일 입력 재실행도 실제 Spark에서 성공했다.

11/9 P-25 후속 검증에서는 같은 격리 입력을 별도 Delta 경로에 잠정·확정 각각 저장했다. 두 마감에서 시간별 6행, 캠페인별 일간 3행, 학습 3행, 확정 순액 1,208,456mw 및 대사 불일치 0건이었다. 부하용 serve 8건을 분리한 전체 fill은 32/32였고, 검증에 쓰인 로비·결과 지면은 각각 16/16이었다. 확정 후 늦은 환입을 원 귀속일에 반영하도록 이전 가드를 교체했다. 같은 원장으로 관찰 종료 시각을 1초 올려 재계산하니 확정 Delta 세 테이블 버전이 각각 0에서 1로 증가하고 금액과 대사 결과가 일치했다. 이 실행의 환입은 앞서 원장에 반영한 1건이며, 확정 후 새 환입을 입력하는 경우는 계약 시험에서 검증했다.

**미완료: 조건 3의 입력은 PM #267에 따라 D-08-02 7번에서 D가 제공한 실행 ID여야 한다. 현재 이슈·PR에 그 ID가 없어 C 자체 실행을 대신 완료로 쓰지 않는다. D 실행 ID 수령 후 동일 대사를 반복하고 D와 재환입 확인을 인계해야 한다.** 운영 전체 광고 gold 상시 스케줄 완료도 주장하지 않는다. 현재 공개 코드는 실행 가능하며 실제 결과는 격리 C 검증 범위다.
