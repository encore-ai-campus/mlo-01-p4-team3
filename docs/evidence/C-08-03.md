# C-08-03 k3s 실행·Kafka sink·자원 재측정
- 커밋: 6960f28ab4dd639c998a521e1a1852f794abe6ad
- 작성자(흐름): C
- 환경: 2026-11-08 실제 PJ4 VM, Python 3.14.4.
- 상태: 부분 완료. 아래 미완료 조건을 유지하고 Refs PR로 제출한다.

k3s 두 노드 Ready를 확인했고 각 노드에서 실제 runner 기반 Job을 실행했다. 첫 base6 50판(content-1.0, baseline-0) 4637건, 최종 digest 이미지의 duo11 50판(content-min-0.1 fixture, rule-v0) 9536건이다. 둘 다 source=bot, 불법 명령 0, 공식 bronze 전체 seq·해시 대조 누락/중복/해시 차이 0이다. fixture는 시뮬레이션용이며 11인 사람 콘텐츠를 공개한 것이 아니다. 운영 6인 콘텐츠로 duo11을 실행하면 첫 판에서 실패하는 것을 확인하고 기존 11인 fixture를 명시했다.

이미지 코드 SHA는 592bff5617b372a4b27f25d09b754fd2c3fd8fb6, OCI digest는 manifest.json에 있다. 레지스트리에 push하지 않았으며 두 k3s 노드의 로컬 OCI다. D가 Job args의 정책·판 수·seed·preset을 정하면 된다. 기본 이미지도 digest로 고정했다. kubeconfig/token·Kafka private key는 저장소 밖 root 전용이며 Pod에는 전용 Write-only 토픽 생산자 Secret을 주입했다.

노드 로그 조회는 agent tunnel과 private kubelet bind 불일치로 EOF다. 보안 설정 완화는 적용하지 않았다. 완료 컨테이너의 해당 노드 CRI 로그를 읽어 metadata manifest를 회수했다. 실패 Job 2개도 완료로 세지 않고 보존했다. 최종 Job은 다른 노드에서 성공했고 일회성 BuildKit daemon은 종료했다.
