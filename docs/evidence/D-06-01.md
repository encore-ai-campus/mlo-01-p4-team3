### 실행 경계와 재현 조건
- `runner.py`는 `GameEngine.new_game`·`player_view`·`apply`만 호출한다. 실제 `PaldoEngine` 조립과 콘텐츠 로드는 CLI가 맡는다. runner가 `GameTruth`의 역할·행적·주장 진실 필드나 NPC 개인 상태를 읽지 않는 경계를 테스트했다. 진실 객체는 엔진에 되넘기기만 한다.
- 봇은 무당 자리에서 `PlayerView`와 시드 RNG만 받는다. 활동 인물·결선 후보·허용 명령·자신의 점괘·공개 기록으로 후보를 만든다. 자기 자신 투표·퇴장자 대상·없는 점괘 공개를 제외하고, 수정된 주장은 모순 근거에서 제외한다.
- 거부 명령을 만나면 재선택해 숨기지 않고 실행 전체를 실패시킨다. 판별 명령 상한 500도 초과 시 실패한다. 모든 판이 종료한 경우에만 집계 결과를 작성했다.
- 프리셋 base6, 콘텐츠 `fixtures/content_min`, source=bot. 판 i의 시드는 `7 * 1000000 + i`(정책 사이 같은 판 시드), 판 ID는 `sim_base6_<정책>_7_<i:05d>`다. 봇 인스턴스와 RNG는 판마다 새로 만든다. 시간·처리량은 재현성 비교 대상에서 제외했다.
- NPC는 dev의 `BaselinePolicy`(baseline-0), 의심 모델은 `FakeSuspicionModel`의 규칙 기준값이다. 새 NPC 정책·의심 ML 모델·LLM을 구현하거나 학습하지 않았다. 공통 버전·콘텐츠 버전·선택 정책 버전은 manifest에 기록했다.
- 미커밋 시뮬레이터+측정 CLI 소스 SHA-256: `b22cdd23037b0f6d6f46b548c0c6301c86862c10dd33b72ed87ebbef3937e983`. 결과 JSON의 commit은 기반 HEAD이며 새 코드가 그 커밋에 들어 있다는 뜻은 아니다.

### 최소 정책과 지표 정의
문서에는 4종 이름과 지표 목록만 있고 세부 규칙·계산식은 없다. 사용자가 별도 합의가 없다고 확인하여 아래 최소 규칙을 구현했다. 점수·선택 횟수 정의는 구현상 정의이며 기획서에 원래 있던 수치로 표현하지 않는다.

- 무작위: 구성한 합법 후보에서 균등 추출한다. 모든 슬롯 조합을 망라한 목록은 아니므로 모든 가능한 행동에 대한 완전 균등 분포를 의미하지 않는다.
- 논리 우선: 자신의 실제 점괘 공개를 먼저 하고, 공개 모순 대상 +2·공개 기색 화자 +1·자신의 탁한 점괘 +1로 대상 우선순위를 정한다. 맑은 점괘는 -100, 공개 고백자는 -100으로 낮춘다. 이는 씐 자 확률이나 확정 판정이 아니다. 이후 질문·의심·투표·점을 우선하며 동률은 시드로 정한다.
- 반복 의심형: 처음 고른 활동 대상에 대한 의심·질문·투표·점을 반복한다. 대상이 퇴장하면 새로 고른다. 반복 의심이 새 증거인 것처럼 점수를 누적하지 않는다.
- 거짓말 공략형: 공개 주장끼리 같은 인물·밤·시간대에 서로 다른 장소를 주장하는 모순을 먼저 질문·지적한다. 그다음 공개 기색이 나온 행적을 질문하고, 없으면 논리 우선 규칙을 쓴다. 진실의 거짓말 라벨은 사용하지 않는다.
- 진영 승률: 해당 진영 승리 판 수 / 완료 판 수. 판 길이는 `GameResult.day` 평균이다.
- 무감금률: `PublicRecord.locks`에서 locked=None인 수 / 확정된 투표일 기록 수. 고백률: 공개 고백자 수 / 판 시작 시 프리셋의 비밀 보유자 수 합계. 분모가 0이면 비율을 비워 표에 —로 표시한다.
- 의미 있는 선택: advance 외의 서로 다른 후보 명령이 2개 이상인 지점에서 실제로 advance 외 명령을 낸 횟수. 강제 advance·대상이 하나뿐인 투표는 제외한다. 판당 평균으로 보고하며 사람의 재미나 추론 품질을 증명하지 않는다.
- 현재 NPC baseline-0은 질문에 항상 해명으로 답하므로 고백률 0은 정상 실측값이다. A-07-01의 고백 반응 정책을 연결하면 다시 측정해야 한다. 논리 우선과 거짓말 공략형의 이번 승률이 같아도 모든 상태에서 같은 정책이라는 뜻은 아니다(공개 모순 우선순위는 별도 테스트).
- 이번은 각 200판의 기능 검증이다. 1,000판 이상·95% 구간·밸런스 목표 40~60% 판정은 A-08-03 등의 후속 기준이다. Kafka·bronze·k3s와 대규모 실행은 C-08-03·D-08-01 범위다.
