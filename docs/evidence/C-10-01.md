# C-10-01 재학습·카나리아·롤백 실행 기반

- 커밋: 32fc98b21a3c5d4785ad4bbd1738f5703b727264
- 작성자(흐름): C
- 환경: Windows Python 3.14, NiFi 격리 MLflow SQLite, 운영과 분리한 promtool, k3s 서버 dry-run
- 상태: 부분 완료. 실제 검수 입력·학습 이미지·PVC를 사용한 수동 재학습 Job과 운영 모델 로더 적용은 대기다.

## 명령

```sh
python -m unittest tests.ops.test_lifecycle tests.ops.test_ml_gate tests.contract.test_model_selector -q
python -m ops.mlflow.retrain --config "$PRIVATE_RETRAIN_CONFIG" --check
promtool test rules ops/prometheus/canary-test.yml
python -m ops.mlflow.lifecycle rollback --model "$MODEL" --expected-production "$CURRENT" --reason fallback_above_limit
```

## 출력

NiFi에서 D의 기존 엔진 실증을 사용해 카나리아 30판·대조 138판을 실제로 실행했다. 합성 폴백률 100% 주입 결과와 C 별칭 명령을 연결했다. B의 실제 `VersionPinning` 포트는 진행 중 판의 `fake-canary`를 유지하고 새 판에는 `fake-previous`를 고정했다. 사용한 모델과 레지스트리는 격리된 합성 자료다. git 메타데이터가 없는 배포 묶음에서는 실증 harness에 해당 묶음의 고정 SHA를 명시해 D 도구의 출처 기록을 제공했다.

세 모델의 D 지표 관문을 합성 보고서로 통과시킨 뒤 C 메타데이터 검사·후보 등록을 격리 MLflow에서 확인했다. 사람 평가가 빠진 씐 자 보고서는 등록되지 않았다. 학습 명령은 기존 D 진입점만 허용하고, source SHA·Delta 버전·특징 버전·삭제 목록을 확인한다.

실제 promtool에 폴백 10% 시계열을 주입한 경보 시험은 SUCCESS였다. k3s API의 server dry-run으로 CronJob 스키마를 검증했다. 이 검증은 기존 namespace에서 리소스를 저장하지 않고 수행했다. 야간 정의는 02:00 KST, suspend=true, Forbid이며 의도·씐 자·CTR를 차례로 처리한다.

## 로그

### 11/11 승격 경합 수정

수정 소스는 `8d3ad12b770e59282e6e8884565955663d6f9842`다.

관측 시점의 `--expected-canary`를 `transition`에 전달하고, 관문 조회 뒤 첫 별칭·감사 태그 쓰기 전에 canary와 production을 다시 대조한다. 전환 대상은 평가한 명시적 버전 번호로 고정한다. CLI 관측 직후 후보 교체, 관문 조회 중 후보 교체, 관문 중 운영 교체, 기대 후보 누락 및 정상 승격 회귀와 기존 시험을 합쳐 9개가 통과했다.

NiFi의 실제 MLflow를 고유 SQLite 레지스트리로 띄워 후보를 관측한 뒤 다른 버전으로 바꿨다. `canary_version_changed`로 거부했고 production과 감사 태그는 그대로였다. 원래 평가 후보를 다시 지정한 정상 승격도 확인했다. 모델 메타데이터는 합성이며 실제 학습·가중치 평가 증빙은 아니다. 중앙 운영 레지스트리는 변경하지 않았다. MLflow API의 원자적 비교·교환 보장을 주장하지 않는다. 결과는 [경합 JSON](perf/C-10-01/canary_race.json)에 보존한다.

```sh

```
