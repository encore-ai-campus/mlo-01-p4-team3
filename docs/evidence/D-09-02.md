## 11/10 후속 검증

검증 기준 dev는 `5cbb14e`다. 실물 가중치 로더를 사용한 B 수신 시험을 실행했다.

Django test client와 임시 SQLite·녹화 엔진에서 모델 로드와 HTTP 계약을 확인했다. 새 시험은 실제 후보 suspect/hunjang, 확인 필수, 기록된 모델·토크나이저 버전, 취소 후 상태 보존을 확인한다. 같은 VM·실제 엔진·Kafka·30명3분 성능 측정은 남아 있다.

아티팩트 5개와 인계 압축 내부의 SHA256을 대조했다. 묶음 위치·해시·환경 버전·재현 설정은 [인계 문서](../reports/D-09-02-handoff.md#1110-로컬-bert-http-수신-검증)에 있다. 측정 소스 테스트 파일 해시도 이 문서에 기록했다.

조건 2의 로컬 보조 시험 2개가 통과했다. 시험용 밴딧 귀속 값을 설정한 웹 종료·설문 이벤트는 배치가 결합했고, 기본 조립의 귀속 값 없는 이벤트는 배치가 거부했다. 실제 조립과 Kafka 연동은 E 담당 B-09-01과 함께 검증해야 한다.

11/10 사용자 확인: D 계정 RunPod 결제 설정·키 전달 완료. 선불 충전, 자동 충전 OFF, 잔액 부족 알림 ON, Restricted 설정 저장 및 E 수령을 확인했다. 첨부 편집 화면에서 GraphQL Read / Write는 전체 GraphQL 접근으로 표시되며, 화면에 Pod 전용 권한 항목은 없다. 실험 후 키 폐기, 실험용 Network Volume 0개 확인, Pod별 사용 시간과 요금의 E 전달은 대기다. 조건 5는 종료 증빙 대기 상태다.


## 11/11 최신 dev 반영과 후속 착수 확인

`task/D-09-02`와 로컬 `dev`를 `origin/dev`의 `5156dec`까지 fast-forward했고, 기존 미커밋 변경은 자동 임시 보관 후 충돌 없이 복원했다. E-11-12 PR #346의 병합 커밋 `33c9861`이 포함돼 있다. 해당 병합은 자유 대화 클라이언트·평가 세트·실행 도구 변경이며, 저장소에서 E-11-12 실험 종료 증빙은 확인하지 못했다.

최신 태스크의 B-09-01 1번은 E 담당이다. 운영 조립 `server/infra/game_factory.py`에는 여전히 `RuleV0Policy(content)`가 쓰이고 `VersionedMixSource` 주입 및 `model_versions["bandit"]` 고정 경로가 없다. 실제 웹 시작 → 종료/설문 Kafka → 배치 → 다음 판 반영 검증은 이 연결 이후 진행한다. E-11-12 병합으로 이 선행 조건이 충족되지는 않았다.

```text
PALDO_BERT_TESTS=1 python -X utf8 -B -m unittest tests.test_ml_gate tests.test_bandit tests.intent.test_bert -v
Ran 23 tests in 4.990s, OK, skipped 0
PALDO_BERT_RECEIVE_RUN_DIR=<D-07-03 checkpoint> python -X utf8 -B server/manage.py test server.tests.test_bert_receive --settings=server.paldo_web.test_settings --noinput --verbosity=1
Ran 31 tests in 22.992s, OK, real checkpoint class 11 tests, skipped 0
python -X utf8 -B out/d09_02/verify_mongo.py
Ran 5 tests in 2.253s, OK, MongoDB 8.3.7
```

첫 실행은 별도 D-07-02 가상환경에 torch가 없어 실물 클래스 준비에서 중단됐다. torch·transformers·Django·pymongo가 있는 프로젝트 `.venv`로 재실행한 위 결과를 판정에 사용했다. 결과는 [dev_recheck.json](perf/D-09-02/dev_recheck.json)과 [mongo.json](perf/D-09-02/mongo.json)에 기록했다. HTTP 시험은 Django test client·녹화 엔진·임시 SQLite를 사용하며 실제 Kafka 또는 운영 웹 부하 결과가 아니다.

RunPod 준비는 사용자 확인으로 완료다. 조건 5의 다음 행동은 E의 실제 실험 종료·키 폐기 요청 확인 → D가 전달 키 폐기 → 실험용 Network Volume 0개 확인 → Pod별 사용 시간·요금을 저장소 밖으로 E에게 전달하는 순서다. 이 종료 확인은 아직 받지 못했으므로 완료로 표시하지 않았다. 전체 상태는 실패를 유지한다.

문서 검사 `python -m tools.check_docs --task D-09-02`와 증빙 `--format`은 통과했다. `--complete`는 상태 실패 및 조건 2·5 미충족으로 3건 실패했다. 검증 중 추가 병합된 D-08-01 PR #377까지 반영한 뒤 위 59개 시험을 다시 실행했다. 현재 시험 파일 `server/tests/test_bert_receive.py`의 SHA256은 `61f65e7e5c5f227b8008674d97a953515d76805953fd051922d7f9bb47dfb739`다.
