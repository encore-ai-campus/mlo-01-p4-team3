# B-08-03 내부 광고 HTTP 연결·장애 사전 검증

- 커밋: 6fb8bf90aa7b9d95e7f9410f6ecfe885c76e5ea0
- 작성자(흐름): B
- 환경: Windows, Python 3.14.6, Django 6.1.2, 실제 Daphne·Mongo 8.0.34, 격리 MySQL 8.4.11·임시 SQLite 계정, 녹화 엔진, B loopback HTTP 광고 대역
- 상태: 실패

SHA는 시작 시 반영한 dev 기준이며 구현은 PR 승인 전 미커밋이다. B HTTP 구현·사전 검증만 완료한 부분 작업이다. D-08-02 인수 서버·장애별 5분 정식 측정·app-01/ad-01 배치 검증을 하지 않았으므로 전체 완료를 주장하지 않고 Refs #35로 준비한다. 루트 README·공통 계약·ads 실행 코드는 수정하지 않았다. 태스크가 명시한 tools/perf/ad_fault_test.py와 필수 증빙만 server/web 밖에 추가·갱신했다.

## 출력

### 실제 소켓·Django 회귀

serve·impression·click·landing의 경로·본문·응답, 요청 ID, 세 지면의 내부 HTTP 호출, 계정/세션 정보·금지 헤더 비전달, 클릭 리다이렉트 미추적, 외부 경로 차단, 빈 응답·오류·무응답·3초 지연·느린 본문과 300ms 마감, 재시도 없음·5회 실패 후 30초 생략/회복을 검사한다. 공개 DTO·게임 명령은 바꾸지 않는다. 최초 중단 시험에서 Windows 연결 실패가 timeout으로 분류돼 error만 기대하던 시험을 수정했다. 두 경우 모두 광고를 비우는 계약은 같다.

관련 HTTP·광고·웹소켓·성능 판정 회귀는 33건, 2.915초에 통과했다. 로그: out/handoff/b0803-http-tests.log. 잘못된 버전 필드 타입·설정 오류도 빈 광고로 처리하는 회귀를 포함한다.

격리 MySQL 8.4.11·Django 6.1.2의 최종 홈 조회 보완을 포함한 전체 서버 219건은 건너뜀 없이 56.370초에 통과했다. 실제 Mongo 운영 조립 회귀도 포함했다. 기존 DB·.env를 수정하지 않았고 임시 MySQL 프로세스·데이터 디렉토리를 정리했고 이번에 기동한 Mongo 컨테이너도 원래 중지 상태로 되돌렸다. 로그: out/handoff/b0803-final-mysql.log·b0803-final-mysql-run.log. 게임·광고 화면 시험의 녹화 엔진/HTTP 대역은 실제 D 광고 서버 검증과 구분한다.

### 성능 미달 분석·B 범위 보완

엄격한 전송 헤더·시험 토큰/HTML 파서 보완 뒤 같은 3명·30초 조건으로 측정했을 때 오류 응답 구간 p95는 정상 173.560ms 대비 255.673ms(+82.113ms)로 증가해 50ms 기준을 넘었다. 게임 오류는 0이었다. 이 실패는 [개선 전 결과](perf/B-08-03/local_http_before_home_reuse.json)와 out/handoff/b0803-ad-fault-before-home-reuse.json·b0803-http-bench-before-home-reuse.log에 보존한다. 앞선 로컬 통과를 최종 통과로 대체하지 않는다.

오류 구간의 실제 serve는 3회였고 비콘 88건·클릭 89건이 circuit_open으로 생략돼 재시도 폭증은 없었다. 게임 요청의 단계별 p95는 load 20.565→43.250ms, content 22.863→49.183ms, server_total 160.136→245.000ms로 증가했다. 단계 p95는 서로 다른 요청에서 나올 수 있으므로 더하지 않는다. 이 기록만으로 디스크·DB 또는 광고 코드 하나를 최종 원인으로 확정하지 않는다.

B에서는 클릭 실패 후 홈이 진척을 두 번 읽고 이어 하기/회차 목록에서 같은 판을 다시 조회하는 부분을 확인했다. 진척 1회·판별 최대 1회로 요청 내 재사용을 연결했다. 다음 요청은 다시 읽는다. 홈·결과·진척·일반/회차 시작을 포함한 관련 70건이 7.235초에 통과했다(out/handoff/b0803-final-targeted.log). 위 실패와 같은 조건의 개선 후 측정은 아래 최종 수치로 기록한다.

초기 사전 검사는 시험의 고정 토큰과 HTML 추출 정규식을 비밀 문자열로 판정했다. 고정 토큰은 실행 중 생성하고 정규식은 표준 HTML 파서로 바꿨다. 비밀 검사 예외 파일을 수정하지 않았다.

### 실제 Daphne·Mongo와 HTTP 대역 동시 측정

홈 조회 재사용 보완 후 정상 기준선과 장애 4종을 각각 3명·30초로 실행했다. 최대 p95 증가 16.106ms로 네 장애 구간 모두 50ms 이하였고 오류율 증가도 0이다. 게임 부하는 기존 api_bench의 실제 HTTP 시작/명령 함수를 그대로 사용했다. 동시에 지면 3종·인증 웹소켓 비콘·같은 출처 클릭/랜딩을 요청했다. 요청 450건·게임 오류 0·완주 30판, 비콘 ack 455건·클릭 455건이며 비콘 프로토콜 오류·광고 HTTP 조각 오류·클릭 화면 오류는 모두 0이다. 장애에서는 비콘 relayed=false와 홈 이동으로 격리됐다. 부하 광고 요청의 load_test=True도 검사했다. 중단 구간은 실제 수신 요청이 없으므로 해당 표시 검사는 공집합이며 정상·나머지 장애 구간에서 실제 수신을 확인했다.

| 구간 | 게임 요청 | 오류 | 완주 | p95(ms) | 정상 대비 증가(ms) | 비콘 ack/실패 | 클릭 요청/오류 |
|---|---|---|---|---|---|---|---|
| 정상 | 90 | 0 | 6 | 160.569 | 기준선 | 90/0 | 90/0 |
| 중단 | 90 | 0 | 6 | 176.675 | 16.106 | 91/91 | 91/0 |
| 무응답 | 90 | 0 | 6 | 116.995 | -43.574 | 92/92 | 92/0 |
| 3초 지연 | 90 | 0 | 6 | 141.718 | -18.851 | 92/92 | 92/0 |
| 오류 응답 | 90 | 0 | 6 | 169.918 | 9.349 | 90/90 | 90/0 |

측정 결과: [local_http_smoke.json](perf/B-08-03/local_http_smoke.json). 원자료: out/handoff/b0803-ad-fault.json·b0803-http-bench.log. 짧은 사전 측정에서 증가 50ms 이하·오류율 증가 0을 확인했지만 D 광고 서버 5분 시험이나 VM 성능으로 확대하지 않는다. CLI 결과도 mode=local-http-fixture, formal_duration=false, task_complete=false다.

개발 중 첫 CLI 실행은 측정 뒤 시간대 API를 잘못 참조해 결과 기록에서 AttributeError가 났다. 기록 처리를 수정하고 부하용 HTTP 제공자의 load_test 강제를 추가한 뒤 전체 5구간을 재실행한 위 결과만 최종값으로 삼았다. 첫 로그는 out/handoff/b0803-http-bench-initial.log에 보존했다.

최종 전체 사전 검사가 통과했다. 원자료는 out/handoff/b0803-precheck.log다. 최초 비밀 검사 실패 기록은 b0803-precheck-initial.log에 보존했다. 최종 확인 시 원격 dev도 기준 SHA와 동일하고 D-08-02는 열린 상태다.

~~~text
precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 902개, base 6fb8bf9, 178초)
~~~

### 11/9 PR 전 재확인

원격 dev를 다시 조회·fetch한 결과 6fb8bf90aa7b9d95e7f9410f6ecfe885c76e5ea0으로 현재 작업 기준과 같았다. 추가 계약·태스크·저장소 규칙 변경은 없었다. 초기 33건 시험 시간의 오기(3.043초)를 원본 로그의 2.915초로 정정했다. 구현 코드는 변경하지 않았다.

HTTP·광고·웹소켓·홈·결과·진척·일반/회차 시작 관련 70건을 다시 실행해 7.060초에 통과했다(out/handoff/b0803-review-final-targeted.log). 기존 격리 MySQL·실제 Mongo 219건과 부하 측정 결과는 동일 코드의 이전 시험 기록으로 보존하며 이번에 재실행한 결과로 표시하지 않는다.

전체 사전검사도 통과했다(out/handoff/b0803-review-final-precheck.log). 아래 결과는 현재 미커밋 작업본의 부분 작업 검증이며 D 인수 후 완료 조건 검증을 대신하지 않는다.


## D 인수 후 마무리

[서버 설계의 인수 목록](../../server/DESIGN.md#d-인수실제-배치-검증-대기)에 내부 출처·기준 SHA·지면 소재 준비·정상 토큰 및 serve_id/request_id 대응·장애 주입/복구·배치 검증 항목을 적었다. 서명 키·광고 DB 인증은 B 인수 항목이 아니다. 실제 설정을 환경에 주입하면 같은 운영 어댑터를 사용한다.

정상 측정은 --scenario normal --users 10 --minutes 5 --output out/handoff/ad-normal.json, 각 장애는 D가 외부에서 주입한 뒤 --scenario stopped|unresponsive|delay|error --baseline out/handoff/ad-normal.json과 구간별 --output 파일을 지정한다. CLI는 새로운 D 장애 제어 API를 가정하지 않는다. 실제 배치 브라우저 기록과 같은 serve_id 양측 로그, B-06-04의 실제 광고 수신 정보 분리도 별도로 남긴다.

## 로그

토큰·쿠키·내부 접속값·계정 ID·원본 본문을 증빙에 복사하지 않는다. HTTP 대역은 요청을 시험 메모리에서만 비교하고 접근 로그를 출력하지 않는다. 측정 결과에는 횟수·지연·경로 구분·허용된 지표만 기록한다.
