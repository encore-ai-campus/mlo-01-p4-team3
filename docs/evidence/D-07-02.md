### 학습 미사용 거짓말 전략 평가

`MixSource`로 학습 입력 300판은 `unrefuted`, 별도 평가 60판은 `routine` 선택을 고정했다.
정책·규칙·콘텐츠·특징 버전은 동일하다. 학습·dev·test 게임과 별도 평가 게임은 겹치지 않으며 판별 seed 집합도 겹치지 않는다.
학습 입력의 실제 `lie_unrefuted` 선택은 164건,
`lie_routine`은 0건이다.
별도 평가의 `lie_routine` 선택은 24건,
`lie_unrefuted`는 3건이다.
정책 버전이 다른 데이터를 학습에 합치지 않았다. 별도 평가 데이터는 fit·온도 선택에 사용하지 않았다.

| 모델 | 판 수 | 관측 수 | log loss | 상위1 적중률 | ECE |
|---|---|---|---|---|---|
| heldout_rule_v0 | 60 | 976 | 1.221583 | 0.376025 | 0.046546 |
| heldout_logistic | 60 | 976 | 1.126353 | 0.466189 | 0.049435 |
| heldout_lightgbm | 60 | 976 | 1.053070 | 0.497951 | 0.027695 |

| heldout_post_night_logistic | 20 | 161 | 0.540215 | 0.714286 | 0.049018 |
| heldout_post_night_lightgbm | 20 | 161 | 0.436657 | 0.763975 | 0.127590 |

이 holdout은 거짓 행적 유형의 **정책 선택 축**이다. 0일째 초기 배정은 두 프로필에서 공통이며,
routine을 골라도 실제 범행 장소와 알리바이 장소가 겹치면 기존 엔진이 unrefuted 방식으로 대신할 수 있다.
`heldout_post_night_*`는 실제 routine 선택이 기록된 밤 이후 관측만 평가한다. 해당 선택이 없는 판과 선택 전 관측은 제외한다.
나머지 누명·대사·밤 대상 축은 두 프로필 모두 기본 혼합이다. 실효 알리바이 전체의 상호 배타성을 주장하지 않는다.

## VM Python·패키지 확인 결과와 재시도

사용자가 VM에 비밀번호로 접속해 직접 실행한 출력을 11/8 채팅으로 전달했다. 아래는 해당 출력 발췌이며 에이전트의 원격 실행 결과와 구분한다.

```text
pj3-nifi
2026-11-08T11:46:12+09:00
Python 실행 경로: /usr/bin/python3.14
Python 버전: 3.14.4 (main, Aug 20 2026, 10:41:58) [GCC 15.2.0]
[FAIL] torch
ModuleNotFoundError: No module named 'torch'
[FAIL] transformers
ModuleNotFoundError: No module named 'transformers'

ModuleNotFoundError: No module named 'lightgbm'
[FAIL] pyspark
ModuleNotFoundError: No module named 'pyspark'
최종 결과: 실패 항목 있음
```

Python 부 버전 조건은 확인했다. 네 패키지는 이 실행 파일의 import 경로에서 발견되지 않았다. 다른 venv·컨테이너의 설치 여부는 이 출력으로 판단하지 않는다. 기존 ML 환경을 확인하거나 사용자 전용 Python 3.14 venv에 지정 버전을 설치한 뒤 다시 검증한다.

저장소 지정 버전은 torch `2.15.0+cpu`, transformers `5.22.1`, lightgbm `4.7.0`, pyspark `4.1.3`이다. 확인된 환경의 Python 경로와 네 import 성공·버전이 확보될 때까지 완료 조건 6과 기존 이슈 #79의 관련 항목은 미충족으로 유지한다.

기존 프로젝트용 Python 3.14 환경이 없다면 다음 사용자 전용 환경으로 재시도한다. 이 명령의 VM 실행 결과는 아직 받지 않았다.

```sh
python3.14 -m venv "$HOME/.venvs/paldo-d0702-py314"
source "$HOME/.venvs/paldo-d0702-py314/bin/activate"
python -m pip install "torch==2.15.0+cpu" --extra-index-url https://download.pytorch.org/whl/cpu
python -m pip install "transformers==5.22.1" "lightgbm==4.7.0" "pyspark==4.1.3"
```

설치 뒤 검증 명령은 위 환경의 `python`으로 실행하고 `sys.executable`도 함께 기록한다. venv 생성이나 설치에서 오류가 나면 해당 출력을 남기고 환경 구성을 확인한다.

## VM 환경 확인 목록

11/8 현재 SSH 22번 포트 접근과 사용자의 비밀번호 로그인을 확인했다. 에이전트의 기존 키 인증은 `Permission denied (publickey,password)`로 실패했다. IP와 인증 정보는 저장소 밖에서 관리한다.

1. `hostname`으로 대상이 학습·시뮬레이션 VM nifi-01인지 확인한다. `whoami` 출력으로 실제 SSH 계정명을 확인한다. VM 이름과 계정명은 구분한다.
2. SSH 포트와 기존 키 인증 방법을 확인한다. 키를 사용한다면 파일 경로와 해당 계정의 공개키 등록 여부를 확인한다. 비밀번호는 채팅·증빙·Git에 적지 않는다.
3. Python 3.14 환경의 실행 경로를 확인한다. 전용 venv나 기존 컨테이너를 쓴다면 그 실행 방법과 환경 이름을 받는다. VM의 시스템 Python이 3.14가 아닐 수 있으므로 실제 ML 실행 환경을 사용한다.
4. 같은 환경에서 아래 명령을 실행한다. Python 전체 버전, 네 패키지 버전, import 오류 원문, 실행 시각을 전달받는다. 담당자가 직접 실행했다면 실행 주체도 기록한다.
5. import 실패가 있으면 현재 환경의 패키지 설치 여부와 지원 조합을 담당자와 확인한다. 확인 결과와 기존 D-07-02 이슈의 미완료 상태를 갱신한다.

```sh
hostname
whoami
date -Is
python3.14 - <<'PY'
import datetime
import importlib
import sys

print(datetime.datetime.now(datetime.timezone.utc).isoformat())
print(sys.executable)
print(sys.version)
for name in ("torch", "transformers", "lightgbm", "pyspark"):
    try:
        package = importlib.import_module(name)
        print(name, package.__version__)
    except Exception as error:
        print(name, type(error).__name__, str(error))
PY
```

`python3.14` 부분은 3번에서 확인한 실제 Python 3.14 실행 파일로 바꾼다. C-07-01 담당자에게는 별도로 silver TrainingRow·종료 후 라벨 조인 완료 여부, Delta 테이블 버전, export 경로와 해시, 정책·규칙·특징 버전을 확인한다.
