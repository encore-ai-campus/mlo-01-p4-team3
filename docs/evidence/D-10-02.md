# D-10-02 광고 CTR LightGBM 비교·시나리오 6·페이싱 보정·자동 입찰
- 상태: 완료 조건 1~4 충족 (격리 합성 검증)
- 커밋: 68887b9bc04b1b59f38b185469e60b1f103425c2
- 작성자(흐름): D
- 환경: Windows Python 3.14.6, LightGBM 4.7.0, Spark 4.1.3/Delta 4.4.1, MLflow 3.18.0(SQLite), Django 6.1.2/MySQL 8.4.11.

11/10 격리 합성 데이터로 D-10-02 조건 1~4를 검증했다. 시나리오 6은 11/1~3 귀속일을 학습, 11/4~6을 평가에만 사용했다. 평가 시드 17·29·43과 학습 시드 1017·1029·1043은 서로 다르다. 날짜별 12,000회 요청의 정답 확률은 별도 파일에 보존했고, 학습기는 확정 Delta 집계에서 유효 노출·클릭만 읽었다. 사전분포는 광고 서버와 같은 픽스처를 썼다.

## 명령

```powershell
python -X utf8 -m tools.ad_ctr_scenario prepare --out out/d1002/scenario --requests 12000
docker run --rm --name paldo-d1002-spark --hostname localhost --network none --cpus 3 --memory 5g --user 0 -v "${rootPath}:/repo:ro" -v "${dataPath}:/data" --entrypoint /bin/sh apache/spark:4.1.3-scala2.13-java17-python3-ubuntu /repo/out/d1002-spark/run.sh
python -X utf8 -m ml.ad_ctr --input out/d1002/scenario/exports/ctr.json --source synthetic --eval-from 2026-11-04 --out out/d1002/ctr-report.json --register
python -X utf8 -m tools.ad_ctr_scenario score --out out/d1002/scenario --report out/d1002/ctr-report.json
python -X utf8 -m tools.ad_ctr_scenario pacing --out out/d1002 --requests 12000
pwsh -NoProfile -File out/d1002-mysql.ps1
pwsh -NoProfile -File out/d1002-mysql.ps1 -Probe
python -X utf8 -m tools.precheck --base origin/dev
python -X utf8 -m tools.check_evidence D-10-02 --complete
```

`rootPath`는 이 작업폴더, `dataPath`는 `out/d1002/scenario`의 절대 경로다. 격리 Spark에서는 생성한 JSONL을 `topic, envelope_json` Delta bronze로 재생한 뒤 실제 `pipeline/spark/ads_silver.py`와 `pipeline/spark/ads_gold.py --phase final --export-optimization /data/exports`를 실행했다. CPC 전용 입력 검사를 추가한 뒤 같은 Docker 명령에 `gold-only` 인수를 붙여 확정 Gold와 CTR 학습 Delta 버전 1을 만들었다. 별도 MLflow SQLite URI를 프로세스 환경에 지정하고 같은 버전의 순수 Python SQLAlchemy를 이 실행에만 사용했다. 광고 서비스는 루프백 랜덤 포트의 새 MySQL에 migration을 적용하고 별도 WSGI 포트에서 실제 `/ads/v1/serve`, `/ads/v1/click`과 아웃박스를 대조한다.

## 출력


CTR 결과는 동일한 보류 노출 35,898개의 이항 로그 손실과 10개 구간 ECE다. 베타 로그 손실 0.416478, ECE 0.003079이고 LightGBM은 로그 손실 0.389471, ECE 0.002809다. 로그 손실 증가 허용 0.01과 ECE 0.05를 모두 충족해 `candidate` v2로 등록했다. 평가 노출 35,898개 모두 LightGBM 점수를 적용했다. MLflow run `8d6bb4b7a33e43989bffdf6ab66d8a78`의 데이터 버전은 `delta:ads-ctr:b8dac4d61dcaefdf:1`, 특징 버전은 `ad-context-v1`이다. 등록 모델을 다시 불러와 범주 인코딩과 게시 예측 96개를 재현했다.

| 시드 | 패배 정답 CTR | 패배 예측 CTR | 승리 정답 CTR | 승리 예측 CTR |
|---|---:|---:|---:|---:|
| 17 | 6.760% | 6.641% | 22.879% | 22.157% |
| 29 | 6.760% | 6.641% | 22.880% | 22.158% |
| 43 | 6.760% | 6.640% | 22.880% | 22.158% |

시나리오 1은 기존 17·29·43에 검증 시드 59·71·83을 추가해 각 12,000회 실행했다. 5분 버킷의 목표 소진율과 예약+확정 소진율 간 평균 절대오차가 이득 5.0의 0.6674%p에서 8.0의 0.5899%p로 줄었다. 참여 확률 범위 0.05~1.0과 회당 조정 폭 ±0.2는 그대로다.

격리 MySQL 서비스 회귀는 70개 중 69개 통과, Kafka 브로커 설정이 필요한 1개 건너뜀이다. migration 상태 검사에서 모델과 migration 간 차이가 없었다. CPC 과금 방식 혼합 제외, 입찰 상·하한, 변경된 입력으로 동일 버전 재시도 거절, 변조 후보 보고서 거절, 카나리아 중 베타 갱신과 롤백 후 재개를 테스트했다.

실제 HTTP에서 갱신 직후에는 이전 CTR·입찰값을 사용했고, 60초 캐시 재적재 후 카나리아 30건은 후보 CTR, 대조 30건은 원래 베타 CTR을 사용했다. 맥락 누락 2건을 추가해 관측 폴백률 6.25%를 만들고 롤백했다. 다음 60초 재적재 뒤 원래 베타 버전으로 돌아왔고, 이전 카나리아 토큰의 클릭은 당시 CTR·입찰 버전으로 유효 과금됐다. CTR 조회 지연 p95는 0.0132ms다.

| 관측 범위 | 실현 CPC(밀리원) | 목표 CPC(밀리원) | 실현−목표(밀리원) | 사용 입찰가(밀리원) |
|---|---:|---:|---:|---:|
| 최신 확정일 11/6, 유효 클릭 1,716건 | 29,759.526 | 4,000 | 25,759.526 | 갱신 전 120,000 |
| 갱신 후 HTTP 유효 클릭 1건 | 2,798 | 4,000 | −1,202 | 16,129 |

입찰 갱신은 상·하한 1,000~120,000밀리원 안에서 120,000 → 16,129밀리원으로 바뀌었다. 갱신 뒤 CPC는 1건의 연결 검증 수치이며 평균 목표 CPC 수렴을 입증하는 표본은 아니다.

최종 사전 검사는 구조·비밀·테스트·문서·증빙 모두 통과했다. 원본 `out/d1002/precheck-final.log`에는 `precheck: 통과 (구조·비밀·테스트·문서·증빙, 테스트 1104개, base 2c4f341, 200초)`가 기록돼 있다.

실제 경매의 CTR 버전은 대조·시작·롤백 뒤 모두 `ctr-cd5c4d89d2aaf5219a253d4aa97a21f7b45a7c62ba06197577fcf81e844bad83`이고, 카나리아에서는 `ctrml-24842638c85a8d0759c0ab68f9439f17d9a8ccbf7ab83c541956e037bc38536b`였다. 갱신 입찰 버전은 `bid-43d747c508f66165a0f8b7fd12145716781cbcbf18a7710849e0a37c4011085d`다. 이전 토큰의 클릭은 카나리아와 입찰 버전을 그대로 기록했다. 최종 `check_evidence D-10-02 --complete`가 통과했고 시험 컨테이너가 남아 있지 않음을 확인했다.
