# user_test — 사용자 테스트 운영 절차

## 무엇을

11/8 사전 테스트와 11/10 정식 테스트(13:00~18:00, 11/8 일정 변경)를 어떻게 운영하는지 정한 절차 모듈이다. 산출물은 계획서 [`docs/user_test/plan.md`](../user_test/plan.md)와 집계 도구 3개다(지표 집계·실험 회차 등록용 가명 ID 추출 `tools/ut_metrics.py`, `test_human` 분할·교집합 검사·동결 `tools/ut_freeze.py`, 읽기 전용 내보내기 `server/infra/ut_export.py`). 계획서는 일정(리허설·진행 판단·SHA 유지 포함), 인원·판 수, 참가자당 진행 순서, 운영자 준비물, 동의 문구(원문 인용), 수집 항목, `test_human` 스냅숏·동결 규칙, 판 종료 설문 확정본, 실험 회차(선택), 뒤 태스크 연결을 담는다. 실제 기능은 게임 웹(E-08-14 일반 판 시작, B-06-03 실험 회차·고정 시드 판, B-06-04 가입·로그인, B-07-02 판 종료 설문)과 프록시(C-07-04)가 만든다. 이 모듈은 그 기능을 운영에서 어떤 순서·값으로 쓰는지 정한다.

계층: 문서(운영). 도구는 인프라 `server/infra/ut_export.py`(Mongo `games`·계정 DB를 `find`·ORM 조회로만 읽어 비밀 없는 JSON으로) → 도메인 순수 함수와 CLI `tools/ut_metrics.py`·`tools/ut_freeze.py`(표준 라이브러리만, 그 JSON만 읽음). `tools/`는 pymongo·Django를 import하지 않는다(`tests/contract/test_layers.py`). 참가자 이름·연락처·명단, 강의실 호수, 접속 주소, 계정·비밀번호는 저장소에 쓰지 않는다.

## 왜

- 근거: 기획서 7.4(사람 데이터 활용 범위·고정 시드 판), 7.5(모집과 개인정보), 8.4(학습 루프), 태스크 E-06-04, 결정 README 7절 P-12(11/6)와 11/6 PM 결정(판 수, 설문 형식, `test_human` 14:30 동결, 가입 속도 제한 삭제, PM 문서 PR #195).
- 일반 판(11/8 사용자 결정, E-08-14): 실제 서비스처럼 로그인·동의한 사용자가 바로 시작하고 시드는 판마다 랜덤이다. 사람 간 비교는 같은 프리셋(`base6`) 판끼리 하고 시드 차이를 리포트에 적는다(E-10-08). 고정 시드 회차는 실험용 선택 경로로만 남긴다(계획서 8절).
- 18:00 클로즈 = 스냅숏(11/8 사용자 결정): 참가자는 18:00 뒤 모이지 못하므로, 지표와 `test_human` 분할을 같은 시각에서 한 번 자른다. 진행 중이던 판은 "미종료"로 따로 센다.
- `test_human`은 시각이 아니라 사용자(가명 ID) 단위로 나눈다. 한 사람의 문장이 평가와 학습에 나뉘어 들어가면 평가 수치가 부풀기 때문이다.
- 설문은 짧게(점수 3문항 + 자유 의견 선택, 전체 건너뛰기 허용) 해서 판 사이 부담을 줄이고 응답률을 지킨다. 필드 이름은 계약 `SubmitSurveyInput`(`server/app/dto.py`)을 그대로 쓴다.
- 동의 문구와 수집 항목의 원본은 계약 [`docs/contracts/privacy.md`](../contracts/privacy.md)다. 계획서는 원문을 인용만 하고 바꾸지 않는다.

계획서 절별로 쓰는 곳이 다르다.

| 실험 회차 만들기·고정 시드 판 지정(선택, B-06-03 세션 관리 화면 `/admin/sessions`) | 계획서 8절(순서, 프리셋 ID, 시드) |

운영자 명령(계획서 4절):

```
python manage.py changepassword <로그인 ID>     # 비밀번호 초기화. 본인을 현장에서 확인한 뒤에만
```

잠금 해제 관리 명령은 B-06-04가 만들고 사용법은 모듈 문서 [`web`](web.md)에 둔다.

집계 도구(지표 정의는 계획서 10절). 내보내기는 운영 DB 읽기 권한이 있는 실행 환경에서 돌리고, 계산은 받은 JSON으로 어디서나 한다. 시간대 없는 명령줄 시각은 KST로 본다. 마감 시각 `--cutoff`의 기본값은 11/10 18:00 KST(스냅숏)이고 지표·동결 도구가 같은 값을 쓴다(`none`이면 자르지 않음).

```
# 1) 내보내기(접속 정보는 환경 변수로만. 저장소·대화에 쓰지 않는다)
PALDO_MONGO_URI=<읽기 전용 URI> python -m server.infra.ut_export games --out games.json [--session-id <실험 회차 ID>]
DJANGO_SETTINGS_MODULE=<운영 설정> python -m server.infra.ut_export accounts --out accounts.json
# 2) (실험 회차를 열 때만) 회차 등록용 가명 ID: 가입 시각 [시작, 끝] 경계 포함, 동의·활성·비운영자만
python -m tools.ut_metrics participants --accounts accounts.json --from <시작> --to <끝>
# 3) 지표(18:00 스냅숏): 13:00 오픈 전에 시작한 판(리허설 등)과 마감 뒤 시작한 판·종료·입력·명령·설문은 세지 않고, 그때 진행 중이던 판은 games_unfinished. PM 가명은 빼서 한 번, 넣어서 한 번
python -m tools.ut_metrics metrics --games games.json [--preset base6] --exclude-pseudonym <PM 가명> --out metrics.json
# 4) test_human 동결(18:00~19:30): 같은 스냅숏(13:00~18:00)으로 자른 뒤 분할. 검수 결과·학습·개발 세트는 필수(없으면 {"exclude": []}·빈 파일). 실패면 종료 코드 1, 묶음은 쓰지 않고 report_failed.json만
python -m tools.ut_freeze --games games.json --pretest-games pretest.json --pm-pseudonym <PM 가명> --seed <분할 시드> \
    --exclude-set <학습 세트.jsonl> --exclude-set <개발 세트.jsonl> --privacy-review review.json --out-dir <동결 폴더>
```

동결 폴더: `test_human.jsonl`(시도 ID·가명·`pm` 표시·마스킹 문장), `train_candidates.jsonl`(학습 쪽 사용자 문장), `assignment.json`(시드·정렬된 참가자·평가/학습 사용자), `report.json`(수·제외 사유·충돌), `manifest.json`(앞 네 파일의 바이트 수·sha256, Delta 버전 대신 쓰는 동결 기록, 11/8 사용자 결정). 개인정보 검수 제외는 학습 쪽 문장에도 적용한다. 검수 결과 형식은 `{"exclude": [{"attempt_id": ..., "reason": ...}]}`.

## 한계

- 30명 동시 진행의 서버 여력은 이 계획에서 확인하지 않았다. 게임 API는 B-06-02·INT-09, LLM 추궁은 E-07-07·INT-09 측정을 따른다.
- 1인 판 수와 1인 총시간은 11/8 사전 테스트에서 실측해 확정한다. 사전 테스트는 PM 혼자 하므로 그 문장은 사용자 1명으로 보고, PM 문장을 넣은 값과 뺀 값을 함께 보고한다(E-09-02).
- 정식 테스트는 11/10 한 번이고 순연하지 않는다(18:00 뒤 참가자가 모이지 못함, 11/11은 검증 전용). 판 수가 모자라면 실제 수와 원인을 기록한다(E-09-01).
- 참가자 접속 안내(지원 브라우저, 인증서 경고 넘기기)는 C-07-04가 만들고, 사전 테스트 전에 받는다.
- 집계 도구 검증은 **로컬만** 했다(11/8, 로컬 Mongo 레플리카셋 + SQLite 계정 DB + `tools/perf/int07_web_run.py` 판과 자유 입력·설문 요청). 운영 DB 접속·실데이터 검증은 하지 않았다(읽기 전용 계정 미확보).
- 원하는 행동 완료율·추가 선택 횟수·취소·버튼 전환 비율·분당 추궁 수·설문 응답률 분모는 문서에 정의가 없어 도구가 낸 안을 11/8 사용자가 확정했다(취소·전환에 `none_of_these`를 합친 `give_up_rate` 추가). 설문 분모는 처음에 "끝난 판 전부(마감 전후 무관)"였다가 같은 날 18:00 스냅숏 결정으로 "마감 시각까지 끝난 판"이 됐다(`ut-metrics-1.1`). 분당 추궁 수의 체류 시간은 명령 사이 간격으로 잡아, 마지막 명령 뒤 화면을 보는 시간은 판 종료·마감까지로 본다.
- Delta 경로로 집계 수치를 대조하지 않는다(11/8 사용자 결정). 원본은 게임 웹 Mongo·계정 DB이고, 동결 기록은 `manifest.json`이다.
- 문장 교집합은 정규화 후 완전 일치만 본다. 비슷한 문장(띄어쓰기 외 차이)은 잡지 않는다.
