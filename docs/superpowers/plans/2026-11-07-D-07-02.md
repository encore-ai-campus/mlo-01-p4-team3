# D-07-02 로컬 사전 개발 계획

요청의 명시적 즉시 개발·필수 입력만 질문 지시에 따라 추가 설계 승인을 생략한다.
기준: docs/tasks/D_ml_ads.md D-07-02, events/ports/ml_lifecycle/parallel_dev/structure/tech_stack 계약.

## 설계

엔진 JSONL → 완료 판의 마을 NPC 관측 → 허용 목록 특징 → 종료 진실 라벨 조인 → TrainingRow.
TrainingRow JSONL과 별도 provenance manifest를 경계로 두어 C의 Delta export도 같은 입력을 사용한다.
정책 혼합, 형식용 synthetic/scripted 데이터, 다중 창귀, 잘못된 후보·행·분할은 거부한다.
로지스틱 회귀와 LightGBM 점수를 관측별 softmax로 바꾸고 같은 test에서 규칙 v0와 비교한다.
게임별 고정 분할, 모델과 분할·원본 해시·특징 버전·코드/정책/seed를 로컬 MLflow에 보관한다.
학습 모델의 행동 연결은 D-08-01 범위라 행동 위반은 원본 관측/결정 감사와 구별한다.

## 실행 계획

- [ ] `tests/test_suspicion.py`: 실제 소량 엔진 출력에서 누수·미완료 판·관찰자·정책 혼합 검사 RED.
- [ ] `ml/suspicion/features.py`: 관측 특징, TrainingRow 변환/검증/JSONL와 manifest 경계 구현, GREEN.
- [ ] 테스트: 게임 분할, softmax, 올바른 지표·입력 검증 RED.
- [ ] `ml/suspicion/evaluate.py`, `train.py`: 최소 학습/평가 CLI와 MLflow, GREEN.
- [ ] 실제 rule-v0 판 재생성·인수 검사·300판 이상 로컬 학습, 성능 표·구조화 로그·결과 JSON.
- [ ] 전체 unittest·문서/구조/비밀 검사, 독립 코드 검토와 누락 수정.
- [ ] 증빙·트러블·라우팅·ML 문서에 로컬 사전 개발 및 Delta/VM/전략 평가 제한 기록.

## 검토 초점

동일 snapshot의 후보 완전성, truth 변경이 특징을 바꾸지 않는지, 미래/중단 진실 거부,
게임 중복 및 정책 변경 거부, 실패·잘못된 provenance로 성공한 예전 모델을 덮어쓰지 않는지.
공유 D 문서는 새 worktree의 dev 기준에 이 태스크 부분만 추가한다. 다른 worktree 변경은 보존한다.
