B의 구현·트러블·검증 결과를 발표 트랙 S-11-03에서 인용할 수 있도록 정리한 자료다. 기준 문서는 [B-10-04](../tasks/B_web.md#b-10-04-트러블검증-기록-발표용)와 [A-10-03의 네 구간](../tasks/A_engine.md#a-10-03-트러블검증-기록-발표용)이다.

11/11 화면·광고 배치 갱신 기준은 dev `f648a2d`(PR #435)다. 부하·DB 수치는 각 증빙에 기록된 SHA와 환경을 따른다. UI 후속 수정은 #429, 8인 판·한풀이 로컬 증빙은 #435에서 인용한다. B-10-04 자료는 S-11-03 인계용이며 전달·수신은 실제 인계 후 기록한다. [태스크](../tasks/B_web.md#b-10-04-트러블검증-기록-발표용)

## 담당

B는 게임 웹의 인증, 표현·응용 계층, 플레이 입력·재전송, 게임 쪽 광고 포트와 HTTP·웹소켓 중계를 담당한다. 게임 규칙은 A, 게임 저장소·전송 인프라는 C, 해석기·광고 서비스는 D와 연결한다. 현재 E로 이관된 화면·콘텐츠 작업은 B의 새 구현으로 소개하지 않는다. ([영역 안내](../routing/B.md), [최신 담당 기준](../tasks/B_web.md))

## 산출물·검증 수치

### API p95와 광고 장애 시험

아래 표는 B-07-05의 **기준 SHA `a86722f`에서 측정한 과거 결과**다. Windows·Python 3.14.6·Django 6.1.2·실제 Compose MongoDB 8.0.34, 임시 SQLite 계정, 녹화 엔진, FakeAdProvider 조건이다. 실제 루프백 WSGI/Daphne HTTP로 사용자 10명·구간별 3분을 측정했다. 실제 운영 엔진·계정 MySQL·VM·배포 HTTPS의 성능은 포함하지 않는다. ([실행 조건·이력](../evidence/B-07-05.md), [원본 JSON](../evidence/perf/B-07-05/compose_10x3_start.json))

|---|---:|---:|---:|---:|---|
| WSGI·광고 없음 | 1,800 | 0 | 304.553 | — | [JSON](../evidence/perf/B-07-05/compose_10x3_start.json) |
| Daphne·광고 없음 | 1,800 | 0 | 305.550 | — | [JSON](../evidence/perf/B-07-05/compose_10x3_start.json) |

([판정·단계 분석](../evidence/B-07-05.md), [단계 원본](../evidence/perf/B-07-05/compose_10x3_start_stages.json))

별도 B-06-02 시험은 `8c4018d`의 Django test client·녹화 엔진·실제 Compose Mongo 조건에서 1,800요청·오류 0건·p95 244.861ms였다. 전송 방식과 SHA가 달라 위 표와 한 변경의 전후 성능으로 비교하지 않는다. ([증빙](../evidence/B-06-02.md), [원본 JSON](../evidence/perf/B-06-02/compose_10x3.json))
