# RunPod GPU 지연 실험 인계 (C-06-04, P-31 반영)

11/7 확정 결정 P-31 (나)가 이전 운영 후보안보다 우선한다. 게임 런타임에는 LLM 서비스를 두지 않는다. 추궁 답변은 오프라인에서 미리 생성·검수한 템플릿 변형으로 제공한다. E-08-09와 런타임 LLM을 요구하는 확장 서비스는 취소됐다. 근거: docs/tasks/README.md의 P-31·런타임 LLM 제거 결정, docs/contracts/integration.md G7·G8, docs/contracts/tech_stack.md.

## RunPod 범위

RunPod는 상시 게임 운영 서버로 배정하지 않는다. 현재 계획의 E-11-12(11/11)는 GPU LLM NPC 대화 서비스 시연이다(11/8 사용자 결정으로 목적 변경. 처음 계획은 E-10-12, 11/10 RTX 4090 한 장 지연 측정). 실행 절차와 사용량 제한은 E-08-13이 만드는 `ops/runbook/gpu_demo.md`를 따른다. 결과는 참고 증빙이며 런타임 LLM 재도입의 승인이나 서비스 배포가 아니다. E-10-13 템플릿 사전 생성은 11/8 사용자 결정으로 Claude Code로 작성한다(로컬 Kanana 배치 계획은 바뀜). 이 문서를 근거로 GPU Pod를 상시 생성하거나 PALDO_LLM_URL을 설정하지 않는다.

| 항목 | 현재 적용 | 확인할 내용 |
|---|---|---|
| 게임 상시 LLM 자원 | 배정 없음 | 게임은 검수된 템플릿·변형 경로 사용 |
| CPU 기존 벤치 | Windows 직접·8스레드·6GB는 과거 잠정 측정안 | 오프라인 로컬 배치에 적용할 값은 E가 확인 |

| 실배정 CPU/RAM/VRAM | GPU 실험 미계측 | 실험 때 실배정·메모리 최고점·동시성별 지연 기록 |
| 신규 llm-01 | 현재 상시 서비스용 생성 불필요 | 과거 VM 생성·기동 여부와 반환 RAM은 미확인 |

## 측정·보존·정지

실험 계정과 시간·비용 범위를 확인하고 모델 revision·hash·라이선스와 고정 런타임을 준비한다. 모델 적재·예열 후 E 평가 세트로 단일·동시 2·4 요청의 전체 지연 p95·큐 대기·실패·메모리 최고점을 측정한다. 결과·모델 경로를 영속 저장소에 보존하고 실험 종료 후 Pod 정지 상태와 남은 저장소 과금을 확인한다. terminate는 컨테이너 디스크를 지우므로 보존 범위를 확인한 뒤 실행한다. 이번 문서 수정에서는 Pod 생성·실험·결제·정지를 실행하지 않았다.

실험 연결은 보호 설정·인증과 HTTPS 또는 접근 제한된 SSH 경로를 사용한다. RunPod 관리 API 키는 공개 추론 서비스 인증으로 자동 적용되지 않는다. 모델 서비스의 외부 노출 제한은 프로젝트 라이선스·계약 결정을 따른다. 공개 런타임 endpoint를 만들거나 키·URL·Pod ID를 저장소에 기록하지 않는다. 과거 renders/poll/cancel HTTP 경로는 취소된 서비스 계약 기록이며 현재 운영 인계 조건이 아니다.

신규 llm-01 생성·기동의 확인 자료가 없어 정지 완료나 RAM 반환을 주장하지 않는다. 실제 실행 인벤토리를 확인한 뒤 C-06-04 잔여 정리 여부를 PM과 맞춘다. Garage는 두 스토리지 노드가 쓰기에 필요하므로 LLM 자원 확보 목적으로 media-storage-01을 끄지 않는다.

공식 자료 확인일 2026-11-07: [포트 노출](https://docs.runpod.io/pods/configuration/expose-ports), [Pod 관리](https://docs.runpod.io/pods/manage-pods). 구체 단가·가용성은 실험 시점에 확인한다.
