# VM 점검표 (C-05-01)

3차 프로젝트 VM 20대를 4차에서 다시 쓰기 전에 상태를 확인하는 양식이다. 각 노트북 담당이 자기 노트북 VM 4대를 점검해 아래 표의 자기 행을 채우고, C가 20대 표로 모은다(`docs/tasks/C_infra.md` C-05-01). 논리 서버명만 쓰고 IP·계정·비밀번호는 쓰지 않는다(`ops/runbook/vm_roles.md`). 접속 정보는 저장소 밖 비공개 문서에 있다.

## 점검 방법

1. **호스트(노트북, Windows)**: VMware VM 폴더를 읽어 기동 여부·vCPU·RAM·디스크(디스크별 OS·데이터)·스냅샷 수와 호스트 디스크 여유를 한 번에 출력한다. VM이 꺼져 있어도 된다.
   ```
   powershell -ExecutionPolicy Bypass -File ops\inventory_host.ps1
   ```
   VM 폴더가 기본 위치(`문서\Virtual Machines`)가 아니면 `-VmRoot "<폴더>"`를 붙인다. 폴더 이름이 스크립트의 대응표(`pj3-…` → 논리 서버명)에 없으면 "(프로젝트 밖)"으로 나오니 논리 서버명을 직접 고쳐 적는다.
2. **게스트(VM 안, Linux)**: VM을 켜고 SSH로 들어가 OS·Python·vCPU·RAM 사용·디스크별 크기와 마운트별 사용량(`disks`·`mounts`)·서비스 상태를 JSON 한 줄로 받는다. 스크립트를 VM에 복사할 필요 없이 표준 입력으로 넘긴다.
   ```
   ssh <접속 별칭> 'bash -s <논리 서버명>' < tools/perf/vm_probe.sh
   ```
   출력에는 IP·hostname이 없다. JSON의 값을 아래 표에 옮긴다.
3. 기동이 안 되거나 SSH가 안 되면 "기동 안 되는 VM" 표에 증상·원인·조치 계획을 적는다.

## VM 20대

칸 설명: "(설치 기준)"은 3차 VM 설치 패키지의 기준값이고 실측이 아니다. "(설치 기준 + PM 확인)"은 설치 기준 OS 디스크 40GB와 PM이 확인한(11/5) 데이터 디스크(별도 가상 디스크)다. "OS 40 + 데이터 n"은 OS 디스크 40GB + 데이터 디스크 nGB(별도 가상 디스크)라는 뜻이다. "(가정)"은 설치 패키지에 없는 VM이라 같은 사양으로 가정한 값이다(근거 없음). 노트북 3 외 행의 RAM 4·디스크 40·OS도 같은 출처다. 기동은 점검 시점의 상태(켜짐/꺼짐/기동 실패). RAM·디스크의 "사용"은 게스트 안에서 잰 값(`vm_probe.sh`), "호스트 점유"는 호스트의 가상 디스크 파일 크기다. 서비스는 `vm_probe.sh`의 `services`·`versions`에서 옮긴다.

- 노트북 3 외 16대의 vCPU·RAM·디스크 할당은 **3차 VM 설치 패키지(공유 드라이브) 기준값**이다: 모든 VM 2 vCPU(1소켓 × 2코어), RAM 4096MB, 40GB 확장형 디스크, Ubuntu 26.04.1 live server. 실측이 아니다. bastion-01·app-01은 설치 패키지에 없어(app-01은 나중에 추가) 같은 사양이라고 가정했다.
- 디스크는 OS 디스크 40GB(설치 기준)와 **별도 가상 디스크로 붙인 데이터 디스크**로 나뉜다(PM 확인 11/5): Object Storage(media-storage-01, lake-storage-01) 100GB, MySQL 3대·MongoDB 3대 50GB. 나머지 VM은 OS 디스크만 있다. 노트북 3 실측(.vmx의 `scsi0:0`=OS, `scsi0:1`=데이터, `ops/inventory_host.ps1` 디스크별 출력)과 일치한다. 다른 노트북은 실측 아님.
- 노트북 3의 데이터 디스크 파일은 스냅샷 델타가 아니라 기준 파일을 직접 가리킨다(스냅샷 뒤에 붙인 디스크로 보인다). 게스트 안 마운트 위치와 사용량은 `vm_probe.sh`의 `disks`·`mounts`로 채운다.
- 노트북별 VM 배치는 `ops/runbook/vm_roles.md` "노트북별 VM과 4차 역할" 표다. 노트북 담당은 `docs/tasks/README.md` 1절.
- 노트북 3: 11/5 밤 점검 때 VM 4대가 모두 꺼져 있어(LLM 벤치 전 RAM 확보) 호스트 값만 적었다. 같은 날 낮 E-05-01 점검에서는 4대 모두 켜져 있었다(`docs/evidence/E-05-01.md`). 게스트 값은 VM을 켜고 `vm_probe.sh`로 채운다.
