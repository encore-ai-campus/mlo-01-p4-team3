## B-10-08 로그인·홈 시안 적용

11/9 PR #314의 확정 기준으로 시안의 먹빛 배경·금빛 선·로그인 두 열·밤 그림 영역·창귀 제목과 로컬 글꼴을 적용한다. 기존 API·폼·동의·로그인 잠금·UUID·재전송·게임 규칙은 바꾸지 않는다. 구현 브랜치는 `task/B-10-08`(dev `51e17f6`), 11/10 후속 검수는 `task/B-10-08-visual-final`(촬영 dev `2c4f341`, 제출 dev `7a09a79`)이다. 제출 직전 추가된 광고 HTTP 변경을 인수한 뒤에도 계정 CSS·템플릿은 촬영 때와 같다.

- `accounts/scene_intro.html`은 PR #323(A-10-05)의 정식 `background:night`를 로그인·가입·홈에 표시한다. 1280×720 공식 그림이며 65% 중심 크롭을 쓴다. 보존 HTML의 로그인 그림과는 동일 정규화 후에도 픽셀이 달라 PM의 기준 원본 확인이 남는다. 임시 대체 그림·표기·옵션은 제거했다.
- 비로그인 홈은 게임 소개·가입/로그인·시작 방법 순서다. 로그인 뒤 일반 게임/배정된 테스트 참여는 하나씩 펼친다. 미완료 배정이 있으면 테스트, 없으면 일반 게임이 먼저 열린다. 표시만 바꾸며 두 시작 양식의 값과 API 정책은 유지한다.
- 공통 헤더는 계정 기본 템플릿에서만 `branding:tiger_emblem`을 로고로 사용한다. 게임 헤더에는 로고 URL을 넣지 않는다. PNG는 시안의 엠블럼 v3를 비율 유지·투명 여백으로 512×512 정규화한 공식 에셋이다. 출처·가공·SHA는 `content/images/SOURCES.md`에 있다.

- PC는 최대 1040px의 두 열, 900px 미만 계정 화면은 밤 그림·폼 한 열이다. 게임의 900px 기준·16:9 무대·대사/선택지 배치는 바꾸지 않는다. 실제 계정 필드·오류·동의 문구는 그대로 유지하며 시안 전용 경고·가짜 로그인은 옮기지 않는다.

## B-08-02 시작 선택과 심문 입력

새 게임과 배정 회차의 시작 폼은 무당 초상 두 개와 여성·남성 라디오 버튼을 함께 보여준다. 초기 선택은 여성이다. 선택은 외형만 바꾼다는 안내를 표시한다. 초상은 manifest의 `portrait:mudang_f`·`portrait:mudang_m`를 사용한다. 회의는 공개 인물 목록과 별도로 본인 초상을 표시해 과거 녹화에서도 선택한 모습이 보인다.

공개 프리셋은 서버 설정을 따른다. 하나면 숨은 값, 둘 이상이면 선택 목록이다. 초기 `base6` 이외의 프리셋은 공개 승인 전까지 노출하지 않는다. 8인 화면은 기존 인물 목록의 줄바꿈을 사용하며 게임 흐름과 공개 정보 범위를 유지한다.

심문에서 밤은 지난 밤만 선택할 수 있다. 모순 질문은 선택 가능한 관련 진술이 두 개 미만이면 비활성화하고, 두 개 이상이어도 두 진술을 체크하기 전에는 제출 버튼을 비활성화한다. 이유·모순 질문에는 밤·시간 값을 보내지 않는다. 안내 문구와 기존 엔진의 최종 검증을 함께 사용한다. 정상 질문·상태 버전·명령 재전송 흐름은 유지한다.

Chrome 1280×900·390×844에서 외형 선택, 심문 제한·정상 제출과 8인 녹화 15화면을 확인했다. 콘솔 오류·리소스 실패·가로 넘침은 없었다. 기존 임시 에셋을 사용하며 이번 작업에서 에셋 품질이나 VN 연출을 변경하지 않았다. [증빙](../docs/evidence/B-08-02.md)

PR #272의 일정 변경에 따라 B-08-02는 현재 dev 빌드로 6인 1판을 공동 완주하고 화면·API 이슈 수정 결과를 E가 재확인한다. 이 공동 확인은 자동 시험과 구분한다. 태그 기반 테스트 서버 리허설은 11/10 B-09-03 범위다.

판 시작의 저장 후 재조회는 유지하고 같은 요청의 같은 버전 콘텐츠만 재사용한다. 시험 경로는 `asgi_bench.py` → `asgi_bench_app.py` → 시험 전용 `asgi_bench_metrics.py`·`asgi_bench_settings.py`이며 숫자 헤더로 요청별 시간만 연결한다. 운영 URL·DTO·화면 흐름·계약 조건은 유지한다.

일반 명령은 소유권을 확인한 요청 내 상태·콘텐츠를 재사용하고, 광고 가명은 기존 값을 조회한 뒤 최초 생성만 upsert한다. 소유권·멱등·CAS·세션 폐기·majority 조건을 유지한다. 시험 전용 단계별 계측과 상세 결과는 `server/tests/asgi_bench_app.py`·`asgi_bench.py`, 동작 회귀는 `test_api.py`·`test_ad_identity_reads.py`·`mongo_game_sessions.py`에 있다.

## B-07-05 광고 장애 성능 검증 범위

게임 API의 WSGI·Daphne 비교와 광고 지면·웹소켓 비콘 동시 부하를 실제 루프백 소켓으로 측정한다. 정상·지연·실패 광고에서 게임 API 지연·오류와 비콘 ack를 별도로 기록한다. 광고 실패의 `ack.relayed=false`와 빈 지면은 기존 계약대로 처리한다. 이번 작업은 화면 구성·표시 흐름을 바꾸지 않으며 브라우저 시각 검수를 새로 수행한 결과가 아니다. 대상 VM 검증은 보류한다.

## B-06-02 저장 계약 검증

저장소 Compose Mongo에서도 같은 HTTP 재생·충돌·거부·20개 경합 시나리오를 통과했다. 화면 URL·표시 규칙은 기존 계약을 유지하며 측정 수치는 [B-06-02 증빙](../docs/evidence/B-06-02.md)에 둔다.

화면 동작은 유지한다. 같은 명령 재전송은 저장 응답 200을 사용하고, 오래된 버전은 409의 최신 화면, 엔진 거부는 422의 기존 상태를 사용한다. 실제 Mongo API 시험은 이 상태·명령·이벤트 보존을 확인한다. 부하 CLI는 JSON 요청을 측정하므로 HTML 렌더·브라우저·ASGI 네트워크 성능을 측정했다고 해석하지 않는다.

dev `f24f6a8` 반영 후 같은 저장 계약과 시험 경계를 다시 확인했다. 녹화 엔진 측정과 실제 엔진·VM 통합 검증을 구분하며 결과는 B-06-02 증빙에서 관리한다.

운영자 회차 등록은 엔진이 출력한 규칙 버전(`rule-0.7.decision-1`)을 입력받는다. 다른 버전으로 바꾸지 않고 등록·판 시작까지 유지한다. 폼과 참가자 게임 흐름은 기존과 같다.

## 자유 입력과 발언 카드

행동 버튼 아래 입력창에 지원·미지원 예시를 함께 표시한다. 해석만으로 행동하지 않으며 여러 후보 중 하나를 확인한다. 누락 슬롯이 있는 카드는 확인 버튼을 비활성화하고 대상·시간·근거를 고쳐 실행하게 한다. 카드 편집의 작은 상태는 로컬 Alpine.js 3.14.9를 사용한다. 원본·MIT 라이선스는 `static/js/vendor/`에 함께 둔다.

빈 입력은 화면을 바꾸지 않는다. 미지원은 버튼 전환 안내, 대상 누락은 대상 선택, 근거 모호함은 근거 선택, 해석 실패는 재입력 안내를 표시한다. 모호한 근거는 해석기의 공개 주장 후보만 표시하며, 모순 지적에 필요한 주장 두 개를 체크박스로 고르게 한다. 재입력은 새 시도, 취소·버튼 전환·해당 없음은 시도 닫기다. 버튼 전환은 단순 이동 링크 없이 `switch_to_buttons` 반응을 보내는 버튼 하나로 제공한다. 실행 결과와 409·422는 서버가 지정한 현재 회의로 바꾼다. 새 행동에는 새 명령 ID를 쓰고 응답 유실 뒤 같은 폼 재전송은 ID를 유지한다.

추궁 발언은 폴백부터 보여 주고 해당 문장만 1초마다 조회한다. 완료 조각은 폴링 속성을 제거한다. 단계 전환으로 제거된 문장의 늦은 응답은 새 회의를 덮어쓰지 않는다. 렌더 작업·발언 ID가 일치하는 결과를 발언 영역에 연결하고, 진술표는 공개된 구조화 진술로 표시한다. 로컬 HTTP 시험에서 최종 문장으로 교체한 뒤에도 진술표의 문구가 그대로인지 확인했다.

폴링은 `hx-sync="#meeting:abort"`로 실행해 사용자 행동이 진행 중인 조회를 중단하고 즉시 처리되게 한다. 빈 재입력은 기존 시도를 닫지 않으므로 같은 카드에서 정상 문장으로 다시 시도할 수 있다.
## 광고 지면

로비·판 종료에만 광고를 지연 로드한다. 회의·투표·밤에는 광고 칸이 없다. 지면 크기는 공통 `SLOT_SIZES`에서 읽고 소재가 있는 광고 조각에 “광고”를 표시한다. 광고 미제공·실패 시 200 빈 조각으로 자리의 내용을 비운다. 광고 표시·안내문·이미지·클릭 링크·비콘 토큰은 남기지 않으며 자리의 예약 크기는 유지한다. 204는 htmx가 기존 내용을 유지하므로 사용하지 않는다. `review_side` 조각은 판 종료 화면의 복기 탭 조각(`review_panel.html`)에만 두어 탭을 열 때 요청한다(B-10-01).

## 정보 범위

진행 화면은 `PlayerView`로 만든 화면 모델을 쓴다. 진술표는 공개된 주장마다 화자와 내용을 보여 주고, 목격·비목격 진술에는 대상의 이름을 표시한다.

본투표와 결선이 진행 중일 때는 해당 회차가 비공개임을 안내한다. 공개 기록에 들어온 표만 일괄 표시하며, 결선 중에도 이전에 공개된 본투표는 보인다. 결선 투표 대상은 동점 후보 중 활동 중인 주민으로 제한한다.

투표가 끝나면 공개 감금 기록에서 감금 대상과 금줄 반응을 표시한다. 결선 재동점은 무감금으로 표시한다.

투표와 밤의 점 대상은 주민별 버튼으로 고른다. 대상마다 명령 폼이 독립돼 같은 대상을 재전송할 때만 기존 명령 ID를 사용한다. 처리된 점괘는 플레이어 자신의 기록에서 읽어 표시한다.

낮의 점괘 공개는 이미 점친 밤과 대상에 대해 맑음·탁함 중 하나를 고른다. 선택한 값은 공개 진술에 표시하고, ‘내 점괘’에는 실제 결과를 보존한다.

## 광고 연결

로그인된 계정·게임 전체 페이지는 [paldo_ws.js](static/js/paldo_ws.js)를 한 번 로드한다. `paldoWS.impression`은 비콘에 UUID를 붙이고 연결을 통해 보낸다. 끊김은 1·2·4·8·16·30초 간격으로 재연결하고 이후 30초 간격을 유지한다. 대기열 상한은 20이며 오래된 항목부터 버린다. 250ms마다 하나씩 보내고 응답 전 끊긴 비콘은 같은 UUID로 다시 보낸다. 실패 ack를 받은 비콘은 재시도하지 않는다.

대기열을 넘겨 버린 비콘은 `queue_full`, 페이지 이동 때 대기열·응답 대기 중에 남은 비콘은 `page_exit`로 센다. 두 수를 `sessionStorage`에 보관하고 다음 연결의 `hello.dropped_by_reason`에 담는다. `hello.dropped`는 두 수의 합이다. 전송 호출이 끝나면 저장한 수를 0으로 되돌린다. 전송 호출이 실패하면 다음 연결까지 보관한다. 서버의 빈도 제한 응답은 해당 비콘을 재전송 목록에서 제거한다. 4401은 재연결을 중지한다. 탭 종료 시 보고할 수 없는 손실이 있어 이 지표는 손실의 하한이다. ## 수첩·확신도·설문

응답 유실 뒤 재조회·같은 입력 재전송은 서버의 마지막 저장 계획을 복구한다. 수첩 값·확신도를 되살리고, 먼저 제출한 설문은 응답·건너뜀 모두 유지한다. 다른 설문으로 바꾸려는 요청은 기존 409 규칙을 적용한다. 복구할 저장소에 연결할 수 없으면 503이며 완료된 것으로 표시하지 않는다. 확신도는 확정된 5단계 버튼으로 입력한다.

같은 날짜·단계의 같은 값 저장은 중복 기록하지 않는다. 다음 날 투표나 결선에서 같은 확신도로 저장하면 각각 해당 시점의 이벤트를 남긴다. 수첩 슬라이더와 확신도의 최근 값은 그대로 복원하고 저장 자체로 게임 상태 버전을 올리지 않는다.

진행 중 판에는 무당을 제외한 공개 주민별 의심도(0~100) 슬라이더와 저장 버튼을 둔다. 처음 표시하는 50은 아직 저장하지 않은 중간 위치이며 저장 버튼을 눌러야 기록한다. 본투표·결선 단계에는 투표 직전 확신도 5단계 버튼(0·25·50·75·100)이 함께 나타난다. 네이티브 라디오 입력을 버튼 형태로 표시해 한 값만 선택하고 키보드로 이동할 수 있다. 기존 API로 저장된 88 같은 값은 최근 값으로 표시하며 임의로 반올림하지 않는다. 확신도를 선택한 뒤 저장 버튼으로 기록하고, 투표 버튼은 기존 게임 명령 경로를 사용한다. 저장 성공·실패를 안내하며 입력을 바꾸면 이전 저장 안내를 지운다.

종료 화면의 설문은 [확정 문항](../docs/user_test/plan.md#7-판-종료-설문-확정본)의 세 점수(1~5)를 모두 선택하고 자유 의견만 비워 둘 수 있다. **건너뛰기**는 별도 폼으로 전송해 미선택 점수 검사를 거치지 않고, 작성 중인 답변이나 의견도 전송하지 않는다. 최초 기록 뒤 완료 안내로 교체한다. 응답을 받지 못해 같은 요청을 다시 보내면 화면을 새로 읽어 완료 상태를 표시한다. 이미 응답하거나 건너뛴 판에서는 다시 선택할 수 없다. [서버 검증과 인수 범위](../server/DESIGN.md#b-07-02-인수계약-확인)

슬라이더 표시값과 저장 안내에는 로컬 정적 파일 Alpine.js 3.14.9를 사용한다. `web/static/js/vendor/alpine.min.js`는 고정 버전 배포본이며 라이선스는 같은 폴더의 `alpine.LICENSE.md`다. 브라우저는 외부 CDN에 접속하지 않는다.

## B-06-03 실제 저장소의 이어 하기

명령 저장 후 응답만 유실돼도 서버의 한 번 재시도가 저장 응답을 복구하면 정상 200 화면을 표시한다. 같은 명령의 사용자 재전송도 저장 응답을 재생하며 상태·명령·이벤트를 중복 추가하지 않는다. 실제 Mongo 쓰기 경계에 `AutoReconnect`·`NetworkTimeout`을 주입해 확인했다.

같은 회차·고정 시드 배정에 C Mongo 저장소를 연결했다. 서버 재시작 후 로그인하면 진행 중인 같은 판의 이어 하기 링크를 표시하며 저장된 상태 버전·공개 기록을 복원한다. 계정·동의·관리자 권한·CSRF 흐름은 유지한다. 로컬 Chrome의 데스크톱 시작·행동과 모바일 재로그인·이어 하기를 실제 엔진·Daphne·Replica Set으로 검증했다. 이 시험은 자유 입력·수첩·설문 보조 저장 또는 VM 성능 검증을 포함하지 않는다.

## B-06-03 완료 조건 재확인

가명·동의·고정 회차·광고 가명 대응표는 기존 계정/회차/Mongo 조립으로 처리한다. 최신 dev에서 실제 Mongo 8개와 격리 MySQL 서버 156개 회귀를 통과했다. 운영 조립과 PM의 브라우저 재시작 판정은 병합됐으며 전체 통합 미완료를 이 기능의 미구현으로 표시하지 않는다. [완료 근거](../docs/evidence/B-06-03.md). 실제 광고 요청 검증과 VM 성능은 해당 후속 태스크 범위다.

## B-06-04 계정과 광고의 분리

계정 화면의 가명 ID를 광고 요청에 사용하지 않는다. 세 광고 지면과 판 종료 지면은 별도 광고 UUID만 사용하고, 비로그인·동의 없는 요청은 광고 호출 전에 차단한다. B-06-04의 같은 인증 시나리오를 로컬 D Django 광고 API에 실제 HTTP로 보내 본문·헤더·로그 비노출을 확인했다. 화면·디자인 변경은 없으며 VM 운영 배치나 새 브라우저 검수를 뜻하지 않는다. [증빙](../docs/evidence/B-06-04.md).

## B-08-01 결과·원한 단서·결말 선택

종료 화면은 승패·종료 사유·날짜를 명확히 표시하고 공개 감금 기록을 유지한다. 마을 승리의 정상 종료에만 선택 결말의 제목·문안을 보여 준다. 중단은 중단 안내, 패배는 패배 결과를 표시한다. 단서 확인과 홈 복귀 링크를 제공하고 기존 설문·결과 광고를 유지한다. 일반 판·고정 회차 모두 결말과 무당 초상을 고를 수 있고, 동일 판 재전송은 처음 선택을 유지한다.

진척 화면은 본인이 수집한 단서의 문장·최초 획득 날짜만 표시한다. 미수집 단서·해금 조건·결말 원문은 숨기고 빈 진척을 안내한다. 콘텐츠 갱신 후에도 서버가 진척에 기록된 버전의 수집 단서 원문을 제공하며, 기존 판의 선택 결말 문안도 고정 버전으로 유지한다. 시작 폼의 퇴마는 기본 선택이며 한풀이는 `endings_unlocked`에 있을 때만 활성화한다. 잠긴 선택은 서버도 거부한다. 도전 3종은 공개된 옵션 계약 인수 전까지 준비 중·비활성이다. 이 상태를 도전 선택 완료로 기록하지 않는다.

## B-08-03 HTTP 연결과 실패 화면

광고 제공자만 B HTTP 어댑터로 연결한다. 기존 페이지의 별도 지면 요청·가시성 비콘·같은 출처 클릭 흐름은 유지한다. 정상은 기존 광고 조각, 미제공·실패·시간 초과·회로 열림은 200 빈 조각이다. 클릭 실패는 홈으로 이동하고 랜딩 실패는 돌아가기 링크를 표시한다. 브라우저가 내부 광고 출처에 접속하거나 내부 beacon_path/click_path를 사용하지 않는다. 실제 D 광고 서버·배치 환경 네트워크 검증은 인수 대기이며 로컬 HTTP 대역 시험으로 대체하지 않는다.

클릭 실패의 홈 복귀 화면은 그대로 유지한다. 서버가 같은 홈 응답의 진척·판 조회만 재사용하며 새 홈 요청에는 최신 상태를 다시 읽는다.
